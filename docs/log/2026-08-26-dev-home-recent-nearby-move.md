# 내 위치 추천을 추천 탭으로 · 홈에 「최근 둘러본 관광지」 신설

> 개발 Claude · 2026-08-26 · 사용자 요청

## 1. 내 위치 추천 블록 이동 (홈 → 추천 탭 맨 위)

'지금 내 옆에 뭐가 있나'는 추천의 한 갈래라 자리가 맞는다.

| 항목 | 처리 |
|---|---|
| 마크업 | `index.html` 의 블록을 통째로 추천 탭 맨 위(퀴즈 카드 앞)로 |
| id | `home-nearby-section` → **`nearby-section`** (더는 홈이 아니다). 참조 5곳 갱신 |
| 함수 | `requestNearbyRec`·`renderNearbyResult` 는 `js/home.js` 에 **그대로 뒀다** |

**함수를 옮기지 않은 이유** — 파일 이동은 diff 가 커지는 데 비해 얻는 게 없다.
지금은 라벨·자리가 계속 바뀌는 단계라, 확정된 뒤 한 번에 정리하는 편이 낫다.

### 놓치기 쉬운 것 — 리셋 책임도 함께 옮겨야 한다

탭 재클릭 초기화(§24)가 이 블록을 원본 CTA 로 되돌린다. 블록만 옮기고 리셋을 두면
**홈을 다시 눌렀을 때 추천 탭 블록을 건드리게 된다.**

- `resetHomePage()` 에서 복원 로직 **제거** → 대신 `renderRecentSection()` 호출
- `resetTourismPage()` 에 복원 로직 **추가** (`_nearbyGen++` 포함)
- `js/boot.js` 의 스냅샷 주석도 "홈 탭 재클릭" → "resetTourismPage()" 로 정정

## 2. 최근 둘러본 관광지 (홈, 빈자리)

### '둘러봤다' 를 어디서 잡는가 — 한 곳이면 된다

`js/map.js` 의 **`showPlaceSlide(place)` 진입부** 한 곳에만 걸었다.
지도 핀 클릭 · 관광 목록 클릭 · 홈 검색 결과 · 즐겨찾기 진입이 **전부 이 함수를 거친다.**
호출부마다 걸면 새 경로가 생길 때 빠뜨린다.

### 설계

| 항목 | 값 | 이유 |
|---|---|---|
| 저장소 | `localStorage['hsida_recent']` | 즐겨찾기와 같은 방식 |
| 저장 개수 | 12 | |
| 표시 개수 | 6 | |
| 대상 | **관광지(`tourist`)만** | 요청이 '관광지'였다. 축제는 성격이 달라 뺐다 — 필터 한 줄만 풀면 포함된다 |
| 중복 | 다시 보면 맨 앞으로 | `filter` 후 `unshift` |
| 빈 상태 | **섹션 통째로 숨김** | 빈 상자가 떠 있으면 고장으로 읽힌다 |

**저장은 id 만 하고, 그릴 때 `PLACES` 에서 다시 찾는다.** 이름·좌표가 바뀌어도 최신값을 쓰고,
삭제된 관광지는 자동으로 빠진다. 이름을 통째로 저장했으면 낡은 값이 화면에 남는다.

`localStorage` 가 막힌 환경(사파리 프라이빗)에서도 죽지 않도록 전부 `try` 로 감쌌다 —
저장이 안 되면 기능만 조용히 꺼진다.

### 가로 스크롤로 둔 이유

이 섹션은 '지나가는 정보'라 세로 공간을 많이 차지하면 안 된다. 아래 본문이 밀린다.
축제 가로 스크롤과 같은 리듬을 쓰되 카드가 더 작다(76px).

| 항목 | 결과 |
