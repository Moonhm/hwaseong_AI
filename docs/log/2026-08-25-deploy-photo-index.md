## 사진 라벨링 · 데이터 분류 반입 (배포 Claude 담당 · 2026-08-25)

> 사용자 지시 2건을 구현했습니다. **기존 데이터·사진은 한 건도 바꾸지 않았습니다** (28,142건 그대로, 사진 159장 그대로).

### 23-1. 사진 파일명 — 지역 이름으로 라벨링

**새 규칙**  `assets/images/places/{읍면동}_{id}[_{메모}].{jpg|jpeg|png|webp}`

```
서신면_1_제부도.jpg      동탄6동_162_CGV동탄역.jpg      우정읍_199_매향항 낙조.jpg
```

**매칭에 쓰이는 토큰은 `{id}` 하나뿐입니다.** 앞의 지역명과 뒤의 메모는 사람이 읽고 정렬하기 위한 장식이며 코드가 대조하지 않습니다. **지역명을 틀리게 적어도 사진은 정상적으로 뜹니다.** 지역 설계와 사진 설계가 서로의 실패를 전파하지 않도록 일부러 느슨하게 묶었습니다.

**기존 `{name}.jpg` 도 계속 인식합니다.** 159장을 한꺼번에 개명할 필요가 없습니다 (기존 파일을 새 정규식에 넣었을 때 오탐 0건 실측).

왜 바꾸는가 — 현행은 `data.js` 의 `name` 과 글자 단위로 일치해야 합니다. tourist 159건 중 **50건(31.4%)** 이 공백·괄호·쉼표·마침표·언더스코어를 갖고 있어, 이름을 한 글자만 고치면 그 사진이 조용히 404 가 됩니다. 실제로 커밋 `c941986` 에서 이름을 바꾸며 사진도 손으로 같이 고쳐야 했습니다.

| 구성 | 파일 |
|------|------|
| 인덱스 생성기 | `tools/build_photo_index.py` — 배포 서버에서 실행 |
| 산출물 | `js/photos.js` — `PHOTO_INDEX.byId` / `.byName` |
| 조회 함수 | `js/ui.js` `placePhotoSrc()` — byId 우선, 없으면 byName, 없으면 `{name}.jpg` |
| 호출부 4곳 | `js/map.js:401` · `js/tourism.js:237` · `js/home.js:90` · `js/quiz.js:195` |

```bash
python3 tools/build_photo_index.py --list    # 사진 넣을 때 참고할 CSV (id·읍면동·권장 파일명)
python3 tools/build_photo_index.py           # 사진 추가 후 인덱스 재생성
```

> 사진을 추가하면 **`index.html` 의 `js/photos.js?v=` 날짜를 함께 올리십시오.**
> `placePhotoSrc()` 는 `PHOTO_INDEX` 의 하위 객체까지 가드합니다 — 인덱스 생성이 실패한 `photos.js` 가 배포돼도 슬라이드 카드가 백지가 되지 않게 하기 위해서입니다.

`tools/check_data.py` 의 `check_photos()` 도 신규 규칙을 인식하도록 고쳤습니다. 안 고치면 신규 형식 사진을 1장만 넣어도 즉시 `FAIL`(고아)이 됩니다. 같은 `id` 에 사진이 둘 이상이면 `FAIL` 합니다.

### 23-2. 유입 데이터 분류 — `tools/ingest.py`

```bash
python3 tools/ingest.py                    # /home/jovyan/work/ 스캔 후 보고
python3 tools/ingest.py --geocode          # 좌표까지 조회
```

**기본은 보고만 하고 아무것도 쓰지 않습니다.**

| 단계 | 내용 |
|------|------|
| 형식 | CSV·TSV·JSON·XLSX. 인코딩 `utf-8-sig`→`utf-8`→`cp949`→`euc-kr` 순 자동 판별 |
| 분류 | ① 값 집합(결정적) ② 주소 값 ③ 컬럼명 토큰 ④ 최소요건 순 |
| 이름 컬럼 | 후보 목록 + `~명`·`~이름` 일반 패턴 (`화장실명`·`도서관명` 등 기관별 변형 흡수) |
| 지오코딩 | **이름 키워드 우선.** 주소 검색은 실측 유효 정보율 10%(22건 중 19건이 행정구역 중심점 반환), 이름 검색은 70% |
| 화성시 검증 | 좌표 상자 + `address_name` 에 `'화성시'` **indexOf**. `=== '화성시'` 는 `"화성시 만세구"` 형태라 전건 실패 |
| 중복 | 이름 정규화(공백·괄호·특수문자 제거) 후 기존 데이터와 대조 → **건별 보고** |

분류 결과별 처리 — `parking`·`localcurrency` 는 **API 수집분이 정확하므로 덮어쓰지 않고 보고만** 합니다(§18). 기존 분류에 안 걸리면 `_review`(신규 유형 후보)로 보류하고 컬럼 목록과 함께 보고합니다. **자동으로 카테고리를 신설하지 않습니다** — 새 category 하나를 추가하려면 리팩터링 후 기준으로 PLACES형 13곳 / 편의정보형 16곳을 고쳐야 하기 때문입니다.

### 검증

가짜 CSV 4종을 주입해 확인했습니다.

| 입력 | 판정 |
|------|------|
| `관광지명`+`소재지도로명주소` | 관광지 · 이름/주소 컬럼 인식 · 지오코딩 exact 2/2 · **기존 중복 2건 검출**(용주사→id:25, 제부도→id:1) |
| `주차장명`+`주차구획수` | 공영주차장 → **보호 대상, 덮어쓰지 않음** |
| `야영장구분` 값이 `일반야영장`/`글램핑` | 캠핑장 (값 집합으로 판정) |
| `화장실명`+`개방시간` | 신규 유형 후보 → 보류·보고 |

사진은 신규 형식 1장을 실제로 주입해 `byId` 매칭과 `FAIL 0` 을 확인하고 원복했습니다.
`bash tools/check.sh` → **FAIL 0 / WARN 0**.
