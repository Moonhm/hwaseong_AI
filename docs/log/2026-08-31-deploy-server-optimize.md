## 2. 구현한 것 다섯

### ① gzip 압축 + 압축 결과 메모리 캐시

`after_request` 훅 하나다. 텍스트 계열 7종만 압축하고 이미지·폰트는 건너뛴다
(이미 압축돼 있어 다시 하면 커지기만 한다 — 실측으로 `logo-icon.png` 는 21,506B
그대로 나간다).

**압축 결과를 캐시하는 이유**는 CPU다. `js/data.js`(101KB)를 요청마다 다시 압축하면
waitress 스레드가 거기 묶인다. 한 번 압축해 두면 그 뒤로는 메모리에서 나간다.

**캐시 키는 ETag 다.** Flask 가 파일 mtime+크기로 만드는 값이라 파일이 바뀌면 키가
저절로 갈린다. `?v=` 를 키로 쓰면 안 된다 — `?v=` 를 안 올린 채 내용만 바뀌는 사고가
이 저장소에서 세 번 났다(§12).

#### ⚠ ETag 를 바꾸지 않기로 한 것이 이 건의 핵심 판단이다

압축본에 `-gz` 를 붙이는 구현이 흔하다(`flask-compress` 기본값이 그렇다).
그러면 브라우저가 보낸 `If-None-Match` 와 어긋나 **304 가 영영 안 난다.**

그게 왜 비싼가 — `index.html` 은 `?v=` 가 없어 `no-cache` 로 나가므로 **재방문마다
재검증한다.** `02aebda` 가 줄여 놓은 것이 정확히 그 왕복(터널 실측 1.4~1.7초)인데,
ETag 를 갈면 그 이득을 gzip 으로 되사는 꼴이 된다.

그래서 ETag 는 그대로 두고 `Vary: Accept-Encoding` 을 붙였다. 실측으로 확인했다 —

```
ETag "1788102457.4111228-59984-909119279"
같은 ETag 로 조건부 재요청 (Accept-Encoding: gzip)  → 304
```

대가는 있다. `Vary` 를 무시하는 중간 캐시가 있으면 비-gzip 클라이언트에 압축본을
줄 수 있다. Cloudflare 는 `Vary` 를 지킨다. **304 를 지키는 쪽을 택했다.**

### ② 상류 API 캐시 + 실패 시 stale 반환

`list` 1시간, `realtime` 45초. 앱의 갱신 주기가 60초(`js/parking.js`
`REFRESH_INTERVAL`)라 45초면 화면이 낡아 보이지 않으면서 방문자가 여럿일 때
상류 호출이 합쳐진다.

**stale 반환이 이 항목의 핵심이다.** 화성시 API 가 잠깐 죽었다고 지도에서 주차장이
통째로 사라지는 것보다, 몇 분 낡은 여유 면수를 보여 주는 편이 낫다. 무엇을 줬는지는
`X-Cache: fresh|cache|stale` 과 `X-Cache-Age` 로 밝힌다.

세 갈래를 전부 재현해 확인했다.

```
① 정상      src=fresh
② 상류 죽음  src=stale   ← 낡은 값이라도 준다
③ 캐시도 없음 → 예외 전파 (기동 직후 상류 장애일 때만)
```

### ③ `requests.Session` 재사용

종전에는 `requests.get` 이 요청마다 새 연결을 열어 TLS 핸드셰이크를 다시 했다.
앱이 60초마다 부르는 경로다. 모듈 수준 `Session` 하나로 keep-alive 를 쓴다.

### ④ waitress WSGI (스레드 8)

Flask 개발 서버는 한 번에 한 요청씩 처리한다. `index.html` 이 js·css 30개를
한꺼번에 요청하므로 그 줄서기가 그대로 첫 화면 지연이 된다.

**재서 확인했다** — 31개를 동시 6개로 받기, 중앙값 5회:

| | 시간 |
|---|---:|
| Flask 개발 서버 (`--dev`) | 208.7 ms |
| **waitress (스레드 8)** | **110.3 ms** |

loopback 값이라 터널 너머의 체감과는 다르다. 다만 '줄서기가 실재한다'는 것은
이 숫자로 충분하다.

waitress 를 고른 이유는 **순수 파이썬**이라 빌드 도구 없이 pip 만으로 들어오기
때문이다. gunicorn 은 이 컨테이너에서 과하다.

`--dev` 플래그로 예전 동작을 남겼고, **waitress 가 없으면 경고를 찍고 Flask 개발
서버로 떨어진다** — 재부팅으로 pip 설치분이 사라져도 서버가 아예 안 뜨는 일은 없다.

### ⑤ 기동 시 상류 프리워밍

데몬 스레드로 두 API 를 미리 받아 캐시에 채운다. 첫 방문자가 상류 응답을
기다리지 않는다. **상류가 죽어 있어도 기동을 막지 않는다** — 실패하면 찍고 넘어가고
첫 요청이 다시 받는다.

```
프리워밍 list: 131건
프리워밍 realtime: 145건
```

### 곁들여 — `/healthz`

터널 점검용이자 최적화 확인용이다. 허용목록(`_PUBLIC_DIRS`)이 거부 목록이 아니라
**허용 목록**이라 `_PUBLIC_ROUTES` 에 넣지 않으면 404 가 난다. 그 자리를 따로 뒀다.

## 3. 기존 제약을 하나도 안 깼다

`02aebda`·`9fae4be` 가 못박은 것들이다. 전부 실측으로 확인했다.

| 지켜야 할 것 | 확인 |
|---|---|
| `assets/`·`img/` 에 캐시 헤더 금지 | `img/logo-icon.png?v=1` → `no-cache` ✅ |
| `.json` 에 `immutable` 금지 | `js/parking-static.json?v=1` → `max-age=3600` ✅ |
| 로컬 직접 접근은 예외 | `127.0.0.1` → `no-cache` ✅ |
| `?v=` 없으면 캐시 안 함 | `js/data.js`(무버전) → `no-cache` ✅ |
| `_PUBLIC_DIRS` 허용목록 | `WORKFLOW.md`·`README.md`·`tools/server.py`·`.git/config` → **전부 404** ✅ |

마지막 줄은 터널 너머에서도 확인했다. 공개 주소로 `/​.git/config` 를 쳐도 404 다.

## 5. 서비스 재기동과 새 주소

```
python3 tools/server.py --port 8080          # waitress (스레드 8), 프리워밍 131·145건
cloudflared tunnel --url http://localhost:8080 --no-autoupdate
```

**새 주소로 세 곳을 갱신했다**(§12 「`cloudflared` 를 끄지 마십시오」의 그 세 곳):

| 자리 | 값 |
|---|---|
| `README.md` 배지 · 본문 링크 | 2곳 |
| `WORKFLOW.md` §1 배포 URL | 1곳 |
| `tools/check.sh` `LIVE_URL` | 1곳 |

`bash tools/check.sh --live` **exit 0** — 배포본과 저장소를 대조하는 `live-drift`
검사가 새 주소로 정상 동작한다(`index.html` 243B 차이는 Cloudflare 가 `mailto` 를
난독화하는 알려진 차이, 상한 300B 이내).

§13 의 「배포 URL 죽음」과 「`tools/server.py` 최적화 중단 diff」 두 행은 §14 규칙대로
**지웠다.** 둘 다 이 작업으로 해소됐다.

> ⚠ **앞으로 서버만 고칠 때는 `cloudflared` 를 끄지 마십시오.** Flask 만 재시작하면
> 이 주소가 유지됩니다. 터널을 끄면 또 새 주소가 나오고 위 세 곳을 다시 고쳐야 합니다.

## 6. 안 한 것

| 항목 | 왜 |
|---|---|
| **Brotli** | gzip 보다 15~20% 더 줄지만 `brotli` 패키지가 추가로 필요하고, 재부팅마다 pip 설치분이 사라지는 환경이라 의존성 하나가 그만큼 비싸다. gzip 은 표준 라이브러리다 |
| **정적 파일 자체를 미리 압축해 디스크에 두기** | `?v=` 가 바뀔 때마다 다시 구워야 하고, 그걸 잊으면 낡은 압축본이 나간다. 메모리 캐시는 ETag 로 저절로 갈린다 |
| **`assets/` 이미지 최적화** | 08-26 에 이미 했다(57.5MB → 20.7MB). 이번 범위 밖 |
| **`index.html` 에 캐시 헤더** | 그게 캐시되면 `?v=` 갱신이 영영 전달되지 않는다 — 유일한 탈출구를 막는 셈이다(`02aebda` 판단 그대로) |
| **`ratings.json` 등 미사용 파일 정리** | 데이터 소관이고 `live_drift` 가 sha256 으로 지키는 파일이 섞여 있다 |
