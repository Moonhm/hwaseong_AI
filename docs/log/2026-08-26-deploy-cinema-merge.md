# 영화관을 관광지에서 편의정보로 이관 — PLACES 8곳 → CONVENIENCE.cinemas 13곳

- 날짜: 2026-08-26
- 담당: 배포 Claude
- 발단: 사용자 지시 — *"관광지중에 영화관이 있는데 너가 가지고 있는 영화관 정보랑
  합쳐서 데이터 합쳐서 영화관 쪽으로 넣어 사진같은것도 이거 중복되있는거야
  영화관은 관광지에 있으면안돼"*

---

## 1. 중복이 아니라 '반쪽씩 갈라져 있었다'

지도에서 같은 영화관이 두 번 찍히고 있었다. `PLACES` 의 `category:"tourist"` 핀과
`CONVENIENCE.cinemas` 의 🎬 칩 핀이다. 그런데 대조해 보니 단순 중복이 아니었다.

공식 CSV(`data/raw/20260825_경기도 화성시_영화상영관 현황_20260201.csv`, cp949)는
**13곳**인데 `CONVENIENCE.cinemas` 에는 10곳뿐이었다. **빠진 3곳이 정확히 PLACES 에만
있던 것들이다.**

| PLACES id | 이름 | CONVENIENCE | CSV |
|---:|---|:---:|:---:|
| 159 | 롯데시네마향남 | ✔ 중복 | ✔ |
| 160 | 롯데시네마병점 | ✔ 중복 | ✔ |
| 161 | CGV동탄 | ✔ 중복 | ✔ |
| 163 | 메가박스동탄 | ✔ 중복 | ✔ |
| 165 | 롯데시네마동탄 | ✔ 중복 | ✔ |
| 162 | CGV동탄역 | **✕ 없음** | ✔ |

그래서 "PLACES 쪽을 지운다"가 아니라 **"3곳을 건져 올린 뒤 지운다"** 가 됐다.
그냥 지웠으면 공식 목록의 3곳이 앱에서 통째로 사라질 뻔했다.

## 2. 주소 오류 하나를 함께 잡았다

`화성시 작은영화관` 의 PLACES 주소가 `경기도 화성시 향남읍` 이었는데
CSV 는 `만세구 마도면 마도북로 387, 마도문화센터 3층` 이다.

좌표(`126.7700856`)는 마도면 쪽이라 **좌표가 옳고 주소 표기가 틀렸던 것**이다.
CSV 를 따라 주소를 고치고 좌표는 그대로 옮겼다.

## 3. 사진이 고아가 되지 않게 파일명을 공식 표기에 맞췄다

`tools/check_data.py` 의 고아 판정은 이렇게 돌아간다(:478):

```python
want_all |= {N(m) for m in re.findall(r'name:\s*"([^"]+)"', open(conv).read())}
```

**`js/convenience.js` 의 `name:` 도 기준에 포함된다.** 그래서 영화관을 옮겨도 사진이
고아가 되지 않는다 — **단, 이름이 글자 단위로 같아야 한다.** `N()` 은
`unicodedata.normalize("NFC", s)` 일 뿐이라 **공백을 지우지 않는다**(:448).

PLACES 이름은 공백이 없고(`CGV동탄`) CSV/CONVENIENCE 는 있다(`CGV 동탄`).
그대로 두면 사진 6장이 즉시 고아가 되어 상한 3을 넘겨 FAIL 이다. 파일명을 고쳤다:

```
CGV동탄.jpg        → CGV 동탄.jpg
롯데시네마병점.jpg  → 롯데시네마 병점관.jpg
롯데시네마향남.jpg  → 롯데시네마 향남.jpg
메가박스동탄.jpg    → 메가박스 동탄.jpg
```

`CGV동탄역` · `CGV화성봉담` 은 CSV 표기 자체에 공백이 없어 그대로 뒀다.
`화성시 작은영화관_*.jpg` 4장은 멀티사진 규칙(`{장소명}_{설명}`)이라 기준 이름이
`화성시 작은영화관` 으로 잡혀 그대로 매치된다.

결과: 고아 사진 **3개 그대로**(상한 3 이내). 13곳 중 7곳에 사진이 연결됐다.

> assets/ 는 git 추적 제외라 이 개명은 **이 서버에만** 반영된다. 다른 환경에서
> 사진을 다시 받을 때는 공식 표기(공백 포함)로 넣어야 한다.

## 4. ⚠ 아직 해결되지 않은 것 — 사진이 화면에 안 뜬다

`tools/build_photo_index.py` 는 **`js/data.js` 만 읽는다**(:38 `DATA_JS`).
`js/convenience.js` 는 보지 않는다. 그래서 재생성한 `js/photos.js` 에 영화관 사진
항목이 **하나도 없다.**

이건 영화관만의 문제가 아니라 **CONVENIENCE 전체가 원래 그런 구조**다. 캠핑장 사진
(`엘리캠핑장.jpg` 등)도 `assets/` 에 파일만 있고 인덱스에 없다. `js/conv_map.js` 의
`_showConvSlide()`(:394)도 사진을 그리지 않는다.

**그래서 이관 전에는 보이던 영화관 사진 10장이 이제 안 보인다.** 검사는 통과하지만
(고아가 아니므로) 화면에서는 사라졌다 — 데이터 무결성과 화면 표시는 다른 문제다.

살리려면 둘 중 하나가 필요하다:
1. `build_photo_index.py` 가 `convenience.js` 도 읽어 `byName` 에 넣고,
   `_showConvSlide()` 에 썸네일을 붙인다 → 캠핑장·호텔 사진도 함께 살아난다
2. 영화관만 예외로 처리한다 → 같은 문제가 다음에 또 난다

**1번이 옳다고 보지만 `conv_map.js` 수정이 필요해 이 커밋에는 넣지 않았다.**
사용자에게 보고하고 판단을 받는다.

## 5. 숫자가 바뀌면서 함께 고친 것

`PLACES.tourist` 가 159 → 151 이 되어 검사 4건이 FAIL 로 떴다. 전부 이 작업의
정당한 파급이라 기준선을 내렸다.

| 위치 | 전 | 후 |
|---|---:|---:|
| `check_data.py` FLOOR `PLACES.tourist` | 159 | 151 |
| `check_data.py` FLOOR `CONVENIENCE.cinemas` | 10 | 13 |
| `check_data.py` TOOL_RE `regeocode.py:_PLACE_RE` | 209 | 201 |
| `check_data.py` TOOL_RE `fix_all_coords.py:BLOCK_RE` | 251 | 243 |
| `index.html:148` About 칩 「관광지 159곳」 | 159 | 151 |

뒤 두 개는 `tools/regeocode.py` · `tools/fix_all_coords.py` 의 정규식이 몇 건을
잡는지 미리 재두는 값이다. 안 고치면 그 도구를 돌릴 때 "✅ N개 수정 완료"라고
성공을 보고하면서 나머지를 조용히 빠뜨린다.

**하한을 내린 것이 데이터 손실을 덮는 게 아님을 밝혀 둔다** — 8곳은 사라진 게
아니라 자리를 옮겼고, 옮긴 쪽은 `CONVENIENCE.cinemas` 13 이 지킨다.
FAIL 은 기준선 7건으로 복귀했다(남은 7건은 이 작업과 무관한 기존 건).
