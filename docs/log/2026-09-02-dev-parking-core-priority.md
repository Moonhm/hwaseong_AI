# 이 문서에 기능 우선순위가 한 줄도 없었다 — 주차장 실시간을 핵심으로 못박는다

- 날짜: 2026-09-02
- 담당: 개발 Claude
- 커밋: `258cb29`
- 발단: 사용자 지시 — *"플로우에 주차장 정보 그니까 이 실시간 정보가 가장 중요하고 핵심인거
  기록해놔. 이미기록되어있나? 이 서비스에서 핵심 기능이야."*

---

## 1. 「이미 기록되어 있나」부터 답했다 — 없었다

지시가 두 개였다. 「기록해놔」와 「이미 기록되어있나」. 두 번째를 먼저 처리했다.

```
grep '핵심' WORKFLOW.md                    → 8곳. 전부 협업 구조·문서 규칙. 기능 우선순위 0건
주차장 + (핵심|중요|우선|최우선|1순위|대표)   → 0건
§1 프로젝트 개요                            → "통합 관광 정보 모바일 웹앱" 이라고만
```

**없었다.** 그래서 이 문서를 읽고 일하는 사람에게 주차장은 관광지·축제·지역화폐·문화재와
**같은 무게**였다. 실제로 §4 데이터 파이프라인에서도 다섯 항목 중 하나로 나란히 적혀 있다.

## 2. 선언만 적으면 안 지켜진다

「핵심입니다」한 줄로 끝내면 다음 사람이 **판단이 갈릴 때** 쓸 수 없다. 그래서 규칙 네 개를
같이 넣었다. 각각 실제로 일어날 수 있는 상황에 대응한다.

| 규칙 | 막으려는 것 |
|---|---|
| **주차장 실시간이 죽으면 P0.** 화면이 안 비어 있어도 죽은 것은 죽은 것이다 | stale 폴백이 화면을 채워 주므로 **장애가 눈에 안 띈다.** 실제로 오늘 5.8시간짜리 값이 나가는 것을 healthz 로만 알았다 |
| **낡은 값을 새 값인 척 보여주지 않는다** | 「빈자리 12면」과 「5시간 전 기준 12면」은 사용자에게 다른 정보다 |
| **성능 때문에 60초 갱신 주기를 늘리지 않는다** | 이 저장소는 최적화를 여러 차례 했다(gzip·brotli·캐시·waitress). **선의로 줄일 수 있는 자리**다 — 비용이 아니라 기능이라고 못박았다 |
| **주차장 회귀는 다른 어떤 기능보다 먼저 고친다** | 오늘 감사에서 주차장 관련 결함이 3건 나왔는데(`b10`·`b13`·`b16`) 다른 것과 같은 순서로 처리했다 |

### 왜 핵심인가 — 이유도 적었다

**다른 데이터는 틀려도 다음에 고치면 되지만, 실시간 여유는 틀리면 사용자가 헛걸음한다.**
「빈자리 있다」를 보고 갔는데 만차인 것이 이 서비스가 낼 수 있는 가장 나쁜 결과다.
관광지 주소가 하루 틀린 것과 성격이 다르다.

## 3. 두 곳에 넣었다

- **§1 프로젝트 개요** — 새 세션이 §0 다음으로 읽는 자리다. 사용자 지시를 원문 그대로 인용했다.
- **§4 → 주차장 절** — 파이프라인만 보고 고치는 사람이 §1 을 안 읽을 수 있다. 포인터를 걸고,
  「갱신 주기를 늘리거나 실시간을 정적 캐시로 대체하는 최적화는 **비용 절감이 아니라 기능 삭제**」
  라고 그 자리에 적었다.

## 4. 곁들여 — 지금 상류가 죽어 있다

이 지시를 받기 직전에 데이터 출처를 정리하다 발견했다.

```
배포 URL /healthz   (2026-09-02 10:16 UTC, 개발 컨테이너에서 읽음)
  realtime  age = 20,722초 (5.8시간)   n=145      ← TTL 은 45초다
  list      age = 34,975초 (9.7시간)   n=131
```

**2분 간격으로 두 번 읽으니 `age` 가 줄지 않고 경과만큼 늘었다(+135초).** 순간적인 실패가
아니라 갱신이 계속 안 되고 있다는 뜻이다.

상류 직접 호출은 개발 컨테이너에서 `HTTP 000`(0.1초 만에 끊김)이라 **원인을 여기서 단정할 수
없다** — 망 차단인지 상류 장애인지 구분이 안 된다. §0 의 「어디서 쟀는지 적어라」를 지켜
범위를 밝히고 배포 Claude 에게 인계했다.

> stale 폴백이 도는 것 자체는 §17 ② 설계대로다. 나는 2026-09-01 에 그 설계에 찬성으로
> 답신하면서 **"낡은 값임이 화면에 드러나야 한다. 화면 표시는 개발 Claude 몫으로 받겠다"**
> 고 적었다. 지금이 정확히 그 상황이다. 다만 서버가 응답에 캐시 나이를 실어 주는 형태가
> 필요해서, 그 요청을 인계에 함께 넣었다.

  갱신 시각을 실어 주면 붙인다. 지금은 `/healthz` 에만 있어 화면에서 못 읽는다.
