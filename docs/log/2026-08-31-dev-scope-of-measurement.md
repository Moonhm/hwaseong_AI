# 「없다」를 재고 틀렸다 — 잰 것보다 **어디서 쟀는지**가 빠져 있었다

- 날짜: 2026-08-31
- 담당: 개발 Claude (hm8824@naver.com)
- 커밋: `(push 뒤에 읽어 뒤따르는 커밋에서 채운다 — §0)`
- 발단: 배포 Claude 의 `2501996` 「그 diff 는 있다 — 요청받은 출력을 올리고 §13 을
  보류로 되돌린다」. 내가 `c2c546d` 로 종결한 것을 실물 출력으로 뒤집었다.

## 0. 결론 — 배포 Claude 가 맞다

`tools/server.py` 미완 diff 는 **있다.** 배포 컨테이너에.
내가 `c2c546d` 에서 「그런 diff 는 없습니다」로 단정한 것은 **틀렸다.**

## 1. 내가 무엇을 잘못했나

여섯 가지를 쟀다. 여섯 가지 다 「없다」였다. 그 값들은 **지금도 전부 맞다.**

```
git status -s                          → clean
git diff -- tools/server.py            → 비어 있음
git stash list                         → 없음
ls -la tools/server.py                 → mtime 08-26 13:30
git log 889bcaf..HEAD -- tools/server.py → 비어 있음
find /home/jovyan -name .git -maxdepth 3 → 사본 하나
```

틀린 것은 값이 아니라 **결론을 쓴 문장**이다.

```
잰 것    개발 컨테이너에 그 diff 가 없다        ← 참
쓴 것    그런 diff 는 없다                      ← 거짓
```

**범위가 빠졌다.** 특히 마지막 줄이 결정적이다. `find /home/jovyan …` 은
**내 컨테이너의 `/home/jovyan`** 만 훑는다. 상대 컨테이너는 그 명령의 사정거리
밖인데, 출력이 1건이라는 이유로 「저장소 사본은 하나뿐」이라고 적었다.
**볼 수 없는 곳을 「없다」의 근거로 삼았다.**

## 2. 왜 안 보였나 — 두 가지가 겹쳤다

배포 Claude 의 설명이 정확하다.

1. **커밋된 적이 없다.** `git` 이 나르는 것은 커밋된 객체뿐이다. 미커밋 변경은
   `git log`·`git stash list`·`git status` 어느 것으로도 **원리상** 상대에게 안 보인다.
2. **두 Claude 는 같은 작업트리를 쓰지 않는다.** 경로 문자열만 같은 별개 사본이다.

②는 내가 반대로 알고 있었다. §13 에 *"두 Claude 가 같은 작업트리를 쓰는 구조"* 라고
써 두기까지 했다. 그런데 **바로 그 오해를 깨는 증거를 내가 손에 쥐고 있었다.**

| | 개발 | 배포 |
|---|---|---|
| `tools/server.py` mtime | 08-26 13:30 | 08-30 08:01:45 |
| md5 | `e5adec20` | `8112583d` |

**같은 파일이면 나올 수 없는 값이다.** 나는 mtime 을 자로 삼는 판단까지 옳게 하고서,
「내 쪽 값이 곧 사실」이라고 읽어 정반대 결론을 냈다. 자를 고르는 것과 자가 닿는
범위를 아는 것은 다른 일이다.

## 3. 이게 왜 특히 위험했나

내 문장이 **검사·규칙의 모양**을 하고 있었다. §13 에 「없는 diff 를 찾지 마십시오」라는
제목으로 표까지 붙여 놓았다. 읽는 사람은 그 절을 보고 **다시 재지 않는다.**

그리고 실제 비용이 났다 — 배포 Claude 는 자기 컨테이너에 **실물이 있는데도**
「없다고 하니 내가 잘못 본 건가」를 확인하는 데 시간을 썼다. 없는 것을 찾으라고
시킨 게 아니라, **있는 것을 없다고 우긴 것**이다. 이쪽이 더 나쁘다.

## 4. 그래서 §0 에 한 줄을 더 넣었다

08-31 하루에 같은 형태가 **세 번** 났다.

| | 잰 것 | 결과 |
|---|---|---|
| ① `~/.claude/projects` 영속 | `findmnt` | 맞았다 |
| ② `tools/server.py` diff | 여섯 가지 | **내 컨테이너만 봤다** |
| ③ rebase 를 막던 파일 | 재현 | 원인을 한 파일로 좁혔다 |

어제 세운 규칙은 「증상에서 원인을 추측했으면 **재라**」까지였다.
②는 **쟀는데도** 틀렸다. 그래서 배포 Claude 의 제안대로 한 칸 넓혔다 —
**「그리고 어디서 쟀는지를 적으십시오.」**

```
✗  그런 diff 는 없습니다 (git status·stash·mtime 전부 확인)
✓  개발 컨테이너에는 없습니다. 배포 쪽은 그쪽에서 재 주십시오
```

두 번째 문장은 **틀릴 수가 없다.** 범위를 좁히면 단정이 아니라 사실 보고가 된다.
그리고 다음 행동(상대에게 묻기)까지 자연스럽게 나온다.

§0 본문은 개발 Claude 파일이라 배포 Claude 가 손대지 않고 제안만 남겼다.
**그 판단이 옳다** — 담당 경계를 지키면서 내용은 전달됐다. 내가 받아 적었다.

### 무엇이 '공통 사실' 인가

이 사건이 준 실용적인 선이다.

| 공통 (저장소가 나른다) | 각자 (안 나른다) |
|---|---|
| 커밋된 파일·이력·태그 | 워킹트리의 미커밋 변경 |
| `WORKFLOW.md`·`docs/log/` | `.git/config`(= `rebase.autoStash`) |
| `.gitignore` 규칙 | pip 설치분 · 실행 중 프로세스 · 마운트 |

**push 된 것만이 둘 다 보는 것이다.** 나머지를 상대에게 말할 때는
「내 쪽에서는」을 붙여야 한다.

## 5. 그리고 판단에 답했다 — 되돌림

§17 상 `tools/server.py` 는 개발 Claude 파일이라 내 몫이다. **되돌리기로 했다.**

- **구현 0줄** — docstring 계획 5건 + import 4건뿐이라 잃는 코드가 없다
- **없는 파일을 가리킨다** — `tools/requirements.txt` 와
  `docs/log/2026-08-30-deploy-server-optimize-deploy.md` 가 둘 다 없다.
  이대로 커밋하면 §0 이 막으려는 **죽은 참조를 새로 만드는 것**이다
- **미커밋 유일본** — 그 컨테이너가 갈리면 그냥 사라진다. 오늘 이미 두 번 사고를 냈다
- **재개 비용이 낮다** — 코드가 아니라 의도라서 **로그가 더 나은 보관처**다

다만 순서를 달았다. **지우기 전에 내용을 `docs/log/` 로 옮길 것.**
되돌림은 「그 최적화를 하지 말자」가 아니라 「미완 상태로 작업트리에 두지 말자」다.
계획은 살리고 유령만 치운다.

## 5-b. 그런데 그 판단도 지나갔다 — 배포 Claude 가 구현했다

이 로그를 쓰는 사이 `4803176` 「서버 최적화 5건 구현 — 첫 화면 876KB → 279KB」가
올라왔다. **내 「되돌림」 답이 도착하기 전에 사용자가 재개를 지시했고**,
§17 이 「사용자 지시가 이 표보다 항상 우선한다」로 못박고 있어 그대로 진행됐다.

**결과가 내 판단보다 낫다.** 내가 「구현 0줄이라 잃을 게 없다」를 근거로 버리라고 한
그 계획이 실제로 구현돼 **-68.1%** 를 냈다. 되돌렸으면 그 이득이 없었다.

내가 틀렸다기보다 **전제가 달랐다.** 나는 그것을 「방치된 미완 diff」로 봤고,
사용자는 「재부팅이 끊은 작업」으로 봤다. 같은 diff 인데 무엇으로 부르느냐가
처분을 정한다. 그리고 그 이름을 정하는 것은 **판단을 요청받은 나도, 인계한 배포도
아니고 사용자**다.

내가 든 근거 넷 중 둘도 배포 Claude 가 실제로 해소했다 —
`tools/requirements.txt` 를 만들었고, docstring 의 「6.46MB → 1.28MB」가
재지 않은 값이라는 것까지 잡아 다시 쟀다(4.2MB 지연 로드분을 첫 화면으로 세고
있었다). **§0 의 08-31 규칙이 배포 쪽에서 먼저 적용된 사례다.**

그래서 §13 의 내 「되돌림」 절은 지우지 않고 **경과 표로 바꿔** 남겼다.
셋이 서로를 덮어쓴 순서 자체가 기록할 값이 있다.

## 6. 안 건드린 것

- **`tools/server.py`** — 내 컨테이너에서는 HEAD 와 동일(`e5adec20`)하다.
  되돌릴 것이 애초에 없고, 실물은 배포 쪽에 있으므로 **실행도 그쪽 몫**이다.
- **배포 Claude 의 §13 서술·로그** — 그대로 뒀다. 맞는 내용이다.
- **`c2c546d` 의 로그** — §0 대로 고치지 않는다. 정정은 §13 과 이 로그가 갖는다.
  다만 §13 절의 **제목과 단정문**은 지금 사실을 말하는 자리라 고쳤다
  (「없는 diff 를 찾지 마십시오」 → 「내 컨테이너에 없다는 없다가 아닙니다」).
  실측 표는 **지우지 않고 남겼다** — 무엇을 어디서 쟀는지가 이 사건의 교훈이다.
