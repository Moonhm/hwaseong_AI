## 1. 넣은 것 — `_favParkBadge()`

`js/favorites.js:164-186`. 호출부는 `renderFavSection()` 안 한 줄(`js/favorites.js:214`)이다.

사용자 말대로 오른쪽이 비어 있었다. `.fav-item` 은 `display:flex` 인데
(`css/20-map.css:144`) 아이콘 32px 다음의 이름 블록이 `flex:1` 이라, 이름이 짧은
주차장 카드는 오른쪽이 그냥 여백이었다. 거기에 `flex-shrink:0;margin-left:8px` 로
두 줄짜리 배지를 끼웠다 — 큰 글자(14px/800)에 남은 대수, 작은 글자(10px)에 `/ N면`.

| 조건 (`js/favorites.js:170-180`) | 글자 | 색 |
|---|---|---|
| `!p.open \|\| p.total <= 0` | 미운영 | `#6B7280` |
| `p.avail <= 0` | 만차 | `#DC2626` |
| `avail/total >= 0.5` | `N대` | `#15803D` |
| `avail/total >= 0.2` | `N대` | `#B45309` |
| 그 아래 | `N대` | `#DC2626` |

주차장이 아니면 첫 줄에서 `''` 를 돌려준다(`f.type !== 'parking'`). 관광지·문화재·
가맹점 카드는 손대지 않는다.

즐겨찾기와 주차장 데이터를 잇는 열쇠는 `placeId` 다. 저장 버튼이 `data-pid="p.id"`
로 심고(`js/parking.js:452`) `toggleFavBtn` 이 `+btn.dataset.pid` 로 숫자화해
넣으므로(`js/favorites.js:32`), `x.id === f.placeId` 엄격 비교가 성립한다.

## 2. 색 — 지도 핀 색을 그대로 쓸 수 없었다

처음에는 핀과 같은 색을 쓰려 했다. 상태를 색으로 알리는 규칙이 이미 지도에 있으니
그대로 가져오는 게 맞다고 봤다. **틀렸다. 배경이 다르다.**

핀은 색 원판 **위에** 글자를 얹지만, 즐겨찾기 배지는 흰 카드(`.fav-item` 의
`background: var(--white)` = `#FFFFFF`) **위의 글자**다. 흰 배경 대비를 재 봤다.

| 색 | 원래 쓰임 | 흰 배경 대비 | 채택 |
|---|---|---:|---|
| `#16A34A` | 지도 핀 팔레트 초록(`js/map.js:30,34`) | **3.3:1** | ✗ AA 미달 |
| `#EF4444` | 주차 핀 만차(`js/parking.js:111`) | **3.76:1** | ✗ AA 미달 |
| `#15803D` | — | 5.02:1 | ✓ 여유 |
| `#B45309` | — | 5.02:1 | ✓ 보통 |
| `#DC2626` | — | 4.83:1 | ✓ 혼잡·만차 |
| `#6B7280` | `--text-muted` | 4.83:1 | ✓ 미운영 |

WCAG AA 본문 기준은 4.5:1 이다. 핀 색 둘은 **못 넘는다.** 한 단계씩 어두운 값으로
바꿨다. 이 수치는 `js/favorites.js:156-159` 주석에 그대로 남겨 뒀다 — 다음 사람이
"핀이랑 색이 왜 다르지" 하고 되돌리는 것을 막으려는 것이다.

(정확히 하자면 주차 핀의 여유 색은 `#16A34A` 가 아니라 아래의 hsl 그라데이션이다.
`#16A34A` 는 지도 핀 팔레트의 초록으로 지역화폐·캠핑장이 쓴다. 배지 초록의 후보로
가장 먼저 집은 값이 그거였고, 그래서 그 값으로 대비를 쟀다.)

**미운영 색은 핀의 `#9CA3AF` 를 안 썼다.** 그 색은 흰 배경에서 2.54:1 이다.
같은 결론이 이미 나와 있었다 — `2026-08-26-dev-audit-a11y-optimization.md:104` 의
`#9CA3AF` → `#6B7280` 교체. 그걸 그대로 따랐다.

### 버린 것: 연속 그라데이션

핀은 `hsl(ratio*118, 72%, 42%)` 로 여유 비율을 **연속으로** 칠한다
(`js/parking.js:112`). 배지도 그렇게 하려다 접었다. 색 원판은 면적이 넓어 미세한
색 차이가 읽히지만, 14px 글자에서 초록-연두 사이 한 칸 차이는 아무 뜻도 전달하지
못한다. **세 단계로 끊었다.** 임계는 절반(0.5)과 5분의 1(0.2)이다.

### 실시간이 아닐 때가 있다 — 숨기지 않았다

`parkingData` 는 지도 탭을 보고 있을 때만 60초마다 갱신된다(`refreshParking`,
`js/parking.js:70-81`). 게다가 `mergeParkingData` 는 실시간 응답이 없으면
`avail = p.total` 로 채운다(`js/parking.js:97`). 즉 **앱을 켜고 지도에 한 번도 안
들어갔으면 홈 배지는 거의 항상 초록**이고 숫자는 총 주차면수다.

숨기거나 '—' 로 대체할 수도 있었지만 안 했다. 이 사정은 홈 하단 데이터 고지
(`index.html:179-182`, `#page-home` 안이다)에 이미 문장으로 적혀 있고,
'가까운 주차장' 카드(`renderNearbyResult`)도 `avail` 이 없으면 `total` 을 쓰는
같은 값이다(`js/home.js:105`). 한 곳만 다르게 굴면 오히려 앱이 앞뒤가 안 맞는다.

(되짚어 적는다 — `a2e84e9` 커밋 메시지에 "**홈**의 '가까운 주차장' 카드" 라고
썼는데 틀렸다. 그 블록 `#nearby-section` 은 하루 전 `97aa4aa`(08-25 16:59 UTC)에서
추천 탭으로 옮겨 갔고 지금 위치는 `index.html:244`, 즉 `#page-tourism` 안이다.
같은 화면이 아니라 다른 탭이다. 근거 자체는 그대로 서지만 '같은 화면' 은 아니다.)

## 3. ⚠ 사고 ① — `?v=` 를 리베이스가 삼켰다

배지를 커밋한 직후 `check.sh` 의 version-guard 가 exit 1 을 냈다. `?v=` 를 126 으로
올렸는데 배포 Claude 의 `4f5bb71` 이 **같은 126** 을 이미 올려 둔 상태라, 리베이스가
내 `index.html` 변경을 '이미 적용됨' 으로 보고 흡수했다. 2분 뒤 `8b2b12b` 에서
128 로 끊었다.

> 전체 경위·서버 캐시 헤더·version-guard 구현·`bump_version.py` 의 `DL_VER` 동기화는
> **[`docs/log/2026-08-26-dev-cachebust-guard.md`](2026-08-26-dev-cachebust-guard.md)** 에 있다.
> 여기서는 배지 작업이 그 사고에 걸렸다는 사실만 남긴다 — 같은 이야기를 두 문서에
> 나눠 적으면 한쪽만 고쳐질 때 서로 어긋난다.

## 4. ⚠⚠ 사고 ② — 확인 방법이 틀려서 '된다'고 보고했다

여기가 이 문서의 본론이다.

나는 배지가 뜨는 것을 브라우저에서 봤다고 보고했다. 실제로 봤다. 그런데 **어떻게
봤느냐**가 문제였다. 정적 JSON(76KB) 로드가 끝날 시간을 넉넉히 잡아 3.2초를 기다린
뒤, 콘솔에서 `renderFavSection()` 을 **손으로 다시 불렀다.** 그러니 당연히 보였다.

사용자는 그런 짓을 하지 않는다. 진짜 새로고침에서는 이 순서다.

```js
/* js/boot.js */
fetch('js/parking-static.json?v=…')  // 비동기 — 나중에 끝난다
  .then(… mergeParkingData(d, []) …)

renderHomePage();                    // 동기 — 지금 당장 돈다  (:163)
```

`renderHomePage()` → `renderFavSection()` → `_favParkBadge()` 인데 그 시점
`parkingData` 는 빈 배열이다. `find` 가 빈손으로 오고 `if (!p) return '';` 에서
조용히 끝난다. 로드가 끝나도 아무도 다시 그리지 않으니 **홈에서는 배지가 영영 안
보였다.** 예외도 안 나고 콘솔도 깨끗하다 — 그래서 더 안 잡힌다.

메뉴(`renderMenuFavs`)는 `openMenu()` 가 부른다. 사용자가 햄버거를 누를 때쯤이면
fetch 는 끝나 있다. **같은 코드인데 홈에는 없고 메뉴에는 있는** 증상이 이래서
나왔고, 이건 "홈에 코드를 안 넣었나 보다" 로 오해하기 딱 좋은 모양이다.

### 안전망이 있었는데 왜 안 걸렸나

`js/nav.js:132-135` 에 홈 진입 시 `renderFavSection()`·`renderRecentSection()` 을
다시 부르는 안전망이 이미 있다(`bc5b158`, 배지보다 20시간쯤 먼저 내가 넣었다). 그런데 이건
`go('home')` 안에 있고, `index.html:42` 의 `#page-home` 은 마크업에서 이미
`class="page active"` 다. **첫 로드는 `go('home')` 을 거치지 않는다.**
안전망이 정확히 못 덮는 한 지점이 첫 화면이었다.

### 잡아낸 것은 배포 Claude 였다

`04f2402` 에서 `boot.js` 의 fetch 콜백에 `renderFavSection()` 한 줄이 들어갔다
(`js/boot.js:151`). 조사 과정은 `docs/log/2026-08-26-deploy-fav-parking-badge.md`
에 있다. 배포 Claude 는 색 3단계를 경계값 7종으로 전수 확인해 코드 자체는 멀쩡함을
먼저 못 박은 뒤 로드 순서로 갔다. 그 §5 에 나를 향한 당부까지 적혀 있다 —
"앞으로 `parkingData` 를 읽는 렌더러를 새로 만들면 그것도 이 콜백에 등록해야 한다."

> **교훈: 손으로 다시 그려서 확인하지 마라. 새로고침으로 확인하라.**
> 렌더 함수를 직접 호출하는 검증은 '그 함수가 맞게 그리는가' 만 본다.
> 사용자가 겪는 것은 '그 함수가 **언제** 불리는가' 다. 비동기로 채워지는 전역을
> 읽는 렌더러라면, 확인은 반드시 F5 에서 시작해야 한다.

## 6. 메뉴 배지는 도로 뺐다

나는 홈과 메뉴 양쪽에 붙였다. 사용자 지시는 *"메뉴에있는건 그냥 빼"* 였고,
배포 Claude 가 `04f2402` 에서 제거했다. 판단 근거는 **메뉴는 '어디로 갈지 고르는
곳'이라 실시간 수치가 들어가면 초점이 흐려진다** 는 것이다(`js/favorites.js:247-249`
주석). 나도 동의한다 — 메뉴 항목은 5개까지만 보여 주는 압축된 이동 목록이라
숫자가 붙으면 목록의 성격이 바뀐다.

`_favParkBadge` 함수 자체는 남겼다. 홈이 계속 쓴다.

한 가지 기록해 둘 것 — 이 제거로 **"홈에는 없고 메뉴에는 있다"는 진단 단서가
사라졌다.** 다행히 원인(로드 순서) 수정과 **같은 커밋**이었다 — `04f2402` 하나가
`js/boot.js`(재렌더 추가)와 `js/favorites.js`(메뉴 배지 제거)를 함께 고쳤다.
원인을 못 찾은 채 이것만 지웠다면 단서만 없어지고 홈은 그대로 비어 있었을 것이다.

## 8. 남은 것

- 미운영 색 `#6B7280` 은 `--text-muted` 와 같은 값인데 **하드코딩**이다. 상태 색
  셋이 리터럴이라 거기 맞춘 것인데, 정작 같은 배지의 `/ N면` 줄은

- 배지 스타일이 전부 인라인 `style=` 이다. `.fav-item` 계열은 `css/20-map.css` 에
  있으므로 클래스로 뺄 수 있다. 지금은 조건에 따라 색만 바뀌는 구조라 미뤘다.
- 이 기록은 **작업과 같은 커밋에 들어가지 못했다.** `a2e84e9` 가 건드린 파일은
  `js/favorites.js` 와 `js/datalab.js` 둘뿐이다. WORKFLOW.md §0 이 경고한 바로 그
  형태이고, 실제로 되짚어 쓰느라 §4 의 '3.2초' 같은 대목은 커밋에 안 남아 있다.
