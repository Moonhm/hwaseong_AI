# API 전수 점검 — 주차장 실시간이 '진짜' 살아 있는지까지 재봤다

- 날짜: 2026-08-31
- 담당: 배포 Claude
- 커밋: (push 뒤 뒤따르는 커밋에서 채운다 — §0)
- 발단: 사용자 지시 — *"이거 다른 api는 잘오는거 맞아? 특히 가장 중요한 주차장 정보들
  실시간으로 재대로되는지 확인해."*

**결론: 전부 정상.** 상류 원본 데이터에 불가능한 값이 2건 있는데, 앱이 이미 막고 있다.

---

## 1. 「200 이 온다」로는 확인이 안 된다

주차장 실시간은 **조용히 죽는 구조**를 갖고 있다. `js/parking.js` 의
`mergeParkingData` 는 실시간 응답이 없으면 **`avail = p.total` 로 채운다.**
그러면 화면은 「모든 주차장이 텅 비었다」로 보이고, HTTP 는 200 이며, 어떤 검사도
FAIL 을 내지 않는다. 그래서 이번에는 네 가지를 따로 쟀다.

| 물음 | 방법 |
|---|---|
| 상류가 살아 있나 | 우리 서버를 거치지 않고 `smartparking.hscity.go.kr` 직접 호출 |
| 우리 변환이 충실한가 | 우리 응답 ↔ 상류 원본 **전건 대조** |
| 값이 **변하나** | 캐시 TTL(45초)을 넘겨 두 번 받아 **차분** |
| 폴백이 아닌 진짜 값인가 | `avail == total` 인 것들이 정말 `used == 0` 인지 확인 |

## 2. 실측

### 상류 (직접 호출)

```
list      HTTP 200   146건   187ms
realtime  HTTP 200   145건   102ms
```

### 우리 서버

```
list 131건 · realtime 145건
id 교집합 131 · list 에만 0 · realtime 에만 14
```

`list` 가 146 → 131 로 주는 것은 정상이다 — `PARKING_ID == 9999` 와 좌표 없는 것을
거른다(원래 코드). 지도에 찍을 수 없는 것들이다. `realtime` 에만 있는 14곳이 그것이다.

### 값이 진짜인가

| | 값 |
|---|---:|
| `used > 0` 인 주차장 | **94 / 145곳 (64%)** |
| `avail < total` (실제 사용 중) | **90 / 131곳** |
| `avail == total` | 42곳 — **그중 `used == 0` 인 곳 42곳 (전부)** |

마지막 줄이 핵심이다. `avail == total` 이 폴백이면 `used` 는 아무 값이나 나올 수
있는데, **42곳 전부 `used == 0`** 이다. 즉 폴백이 아니라 **진짜 빈 주차장**이다.

가장 붐비는 곳 표본:

```
id541  여유 288 / 총 566   사용 278
id63   여유   0 / 총 204   사용 204   ← 만차
id28   여유  37 / 총 225   사용 188
```

### 값이 변하는가 — 결정적 확인

캐시 TTL 을 넘겨 75초 간격으로 두 번 받아 차분했다.

```
1회차  X-Cache=cache age=22.6
2회차  X-Cache=cache age=22.6      ← 45초 안이라 캐시가 맞다
(50초 대기)
3회차  X-Cache=fresh age=0.0       ← TTL 넘겨 새로 받았다

사용 대수가 바뀐 주차장 3곳
  id41  14 → 13
  id89   6 →  5
  id42   1 →  0
```

**차가 있다 = 살아 있는 값이다.** 그리고 같은 시점 상류 원본과 전건 대조해
**불일치 0건**이었다 — 우리 캐시가 낡은 값을 주고 있지도 않다.

공개 URL(터널 너머)로도 같은 값이 나온다(`realtime` 145건, 최다 사용 278).

## 3. 상류가 보내는 불가능한 값 2건 — 앱은 이미 막고 있다

| id | 이름 | 상류 원본 | 무엇이 이상한가 |
|---|---|---|---|
| 36 | 노작마을 | `CELL_CNT=141 CURRENT_CNT=-10 USE_CNT=151` | 141면에 151대 — **여유가 음수** |
| 501 | 봉담읍 와우리 | `CELL_CNT=128 CURRENT_CNT=130 USE_CNT=-2` | 여유가 총면수보다 많다 |

**우리 변환 잘못이 아니다.** 화성시 API 가 그대로 그렇게 준다(원본 대조로 확인).
초과 주차이거나 센서 오차로 보인다.

화면에서 어떻게 되는지 계산했다.

| 곳 | ratio | 렌더 | 인상 |
|---|---:|---|---|
| 노작마을 | −0.071 | `pinColor` 의 `if (ratio <= 0) return '#EF4444'` | **빨강 = 만차** ✅ 맞다 |
| 봉담 와우리 | +1.016 | `hsl(120,72%,42%)` | **초록 = 여유** ✅ 맞다 |

합계·게이지도 `Math.max(0, …)` 로 막혀 있다(`js/parking.js` 의 `availCp` · 게이지 `ratio`).
**우연이 아니라 이미 방어돼 있던 자리다** — 고칠 것이 없다.

## 5. 서버 상태

```
uptime 54분   upstream list 131건 · realtime 145건
gzip hit=193 miss=61 skip=6   캐시 54개 1.4MB
```

**`X-Cache` 가 한 번도 `stale` 을 낸 적이 없다** = 이 세션 동안 상류 장애 0회.
stale 폴백은 만들어 두었지만 아직 쓰인 적이 없다.

## 6. 남은 것

- **`js/parking.js` 는 손대지 않았다.** 방어가 이미 있고, §17 상 개발 Claude 파일이다.
- 상류의 음수 2건은 **화성시 쪽 데이터 문제**라 우리가 고칠 수 없다. 화면 인상이
  맞게 나오므로 보정도 하지 않았다 — 억지로 0 으로 깎으면 「만차」와 「초과 주차」가
  구분되지 않는다.
- `check.sh` 에 「realtime 이 폴백인지」를 보는 축은 없다. 넣는다면
  *"`avail == total` 인 곳이 전부인데 `used` 가 전부 0 이 아니면 FAIL"* 같은 모양이
  될 텐데, 네트워크가 필요하니 `--live` 축이다. 지시받지 않아 만들지 않았다.
