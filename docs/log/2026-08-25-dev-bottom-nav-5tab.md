# 하단 내비 4칸 → 5칸, 햄버거 메뉴를 상단에서 하단으로

> 개발 Claude · 2026-08-25 · 커밋 `690e6f8`

사용자 요청으로 하단 내비에 메뉴 버튼을 추가했다. 부수적으로 **실제 결함 하나가 해소됐다.**

## 해소된 결함

햄버거가 **홈 헤더에만 있어서 관광·생활·지도 탭에서는 메뉴를 열 방법이 아예 없었다.**
`css/30-panel.css` 주석도 스스로 "메뉴 유일 진입점"이라고 적고 있었다.
하단으로 옮기면서 4개 탭 전부에서 열리게 됐다.

## 변경

| 파일 | 내용 |
|---|---|
| `index.html` | 하단 내비 5번째 버튼 추가 (햄버거 SVG + "메뉴", `onclick="openMenu()"`) |
| `index.html` | 홈 헤더에서 `<button class="hamburger-btn">` 제거 — 로고 + 안내문구만 남음 |
| `css/00-base.css` | `.nav-item` 에 `min-width:0` · `white-space:nowrap` 방어 추가 |
| `css/30-panel.css` | 죽은 `.hamburger-btn` 규칙 2개 제거 (참조 0건이 됨) |

## 핵심 판단 — `data-page` 를 일부러 안 붙였다

메뉴는 **화면(page)이 아니라 드로어를 여는 동작**이다.
`js/nav.js` 의 `go()` 가 `.nav-item[data-page]` 만 골라 `active` 를 옮기므로,
`data-page` 가 없으면 어떤 탭에 있든 **메뉴 버튼이 활성색으로 잘못 칠해지지 않는다.**
4개 탭 전부에서 실측 확인했다.

## 간격은 손댈 것이 없었다

`.nav-item { flex: 1 }` 이 칸 수와 무관하게 균등 분배한다. 4칸이든 5칸이든 CSS 를 고칠 필요가 없다.
추가한 `min-width:0` 과 `nowrap` 은 칸이 더 늘거나 라벨이 길어졌을 때
글자가 두 줄로 접히거나 칸이 삐져나가는 것을 막는 **방어**일 뿐이다.

폭 실측: `480px→96px · 390px→78px · 360px→72px · 320px→64px`.
가장 좁은 320px 에서도 터치 타겟 최소 36px 의 1.8배라 여유가 있다.

## 아이콘은 SVG 로 통일했다

원래 햄버거는 `<span>` 3개로 그린 세 줄이었다. 그대로 하단에 옮기면 나머지 4개(SVG)와
아이콘 크기·색상이 따로 논다. 같은 `viewBox="0 0 24 24" fill="currentColor"` SVG 로 다시 그려
`.nav-item.active` 색 상속까지 동일하게 맞췄다.

- 활성 표시는 탭만 따라가고 메뉴는 한 번도 활성화되지 않음
