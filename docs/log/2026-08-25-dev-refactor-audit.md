## 오늘 변경 전체에 대한 반증 감사 (개발 Claude 담당 · 2026-08-25)

> **결론 한 줄** — **파손 0건.** 실제 Chromium 픽셀 비교까지 통과했다.
> 다만 개발 Claude가 §20·§21 에서 말한 **"동작 변경 0"은 리팩터링 2건에만 참**이고, 같은 묶음에 **진짜 동작 변경 2건**이 들어 있다. 아래에 전부 적는다.

### 왜 했는가

사용자가 배포 Claude 재가동 여부를 결정하기 전에 "정말 아무 문제 없나"를 확인해 달라고 요청했다. 개발 Claude 자신의 "괜찮다"는 주장을 검증 근거로 쓸 수 없으므로, **주장을 반증하는 방향**으로 독립 감사를 돌렸다. 4개 관점(JS 실행 의미론 / CSS 렌더링 / 실서비스 영향 / 데이터 무결성)이 각각 파손을 찾아 나섰고, 마지막에 판정자가 그 결과를 다시 검증했다.

### 감사 대상

기준점 `dc8cb70`(배포 Claude 마지막 커밋) → `1ffdf15`. 개발 Claude 커밋 7개.

### ⚠ 정정 — "동작 변경 0"은 사실이 아니었다

§20·§21 에 "동작 변경 0"이라고 적었는데, 그건 **JS/CSS 분리 두 커밋에만** 해당한다. 같은 날 묶음에 아래 2건이 있다.

| # | 무엇 | 안전한가 |
|---|------|---------|
| 1 | **`?v=` 캐시 버스팅** — 데이터 fetch 4곳(`js/parking.js:50`, `js/home.js:68`, `js/ui.js:83`, `js/boot.js:109`)의 URL 이 바뀌었다. 코드 이동이 아니다 | 안전. 서빙 본문 해시가 원본과 동일함을 확인 |
| 2 | **`tools/server.py` 접근 제한** — 허용목록 밖 404 | 안전하나 **Flask 재시작이 있어야 적용**된다 |

### ⚠ 또 하나 — "최적화"라는 표현도 정확하지 않다

**페이지 1회 로드당 요청이 7건 → 23건으로 늘었고, 전송량은 186,826B → 201,109B 로 늘었다.**

이전에는 `index.html` 하나가 CSS·JS 를 자기 안에 갖고 있어 첫 페인트에 추가 왕복이 **0회**였다. 지금은 **렌더 차단 CSS 6개를 더 받아야** 첫 화면이 나온다. Cloudflare Quick Tunnel 은 왕복 지연이 크므로 **시연 첫 화면 백지 시간이 늘어날 수 있다.**

즉 이번 분리는 **유지보수성·충돌 감소를 얻고 초기 로딩 속도를 조금 내준 거래**다. "최적화"가 아니라 "구조 개선"이 정확한 표현이다.

### ⚠ 실패 원자성이 사라졌다

전에는 `index.html` 이 오면 CSS·JS 가 반드시 함께 왔다. 지금은 **16개 독립 요청**이라 부분 실패가 가능하다.

- `js/tourism.js` 하나만 실패 → 나머지 9개는 정상 동작하고 **관광 탭 버튼만 조용히 죽는다**
- `css/20-map.css` 하나만 유실 → **지도 화면만 무너진다**

배포 후 브라우저 개발자도구 Network 탭에서 **404 가 0건인지** 한 번 확인하는 습관이 필요하다.

### 감사가 찾아낸 결함 2건 — 즉시 수정함

| 결함 | 조치 |
|------|------|
| **`css/20-map.css` 머리 주석이 거짓말이었다.** "선택자 규칙이 다른 화면과 완전히 분리돼 있다"고 적었으나, 실제로 271~284줄이 `.nav-item`·`.festival-card-big`·`.place-card-sm`·`.place-item`(전부 `00-base.css`)과 `.chip`·`.fd-cta-btn`(`10-content.css`) **6개를 덮어쓴다.** 특이성이 같아 승자가 오직 `<link>` 순서로 결정된다. 이 주석만 믿고 파일 순서를 바꾸면 눌림 애니메이션이 즉시 사라진다 | 주석을 사실대로 정정하고 **경고를 명시** |
| **`?v=` 검사가 css 를 아예 안 보고 있었다.** `tools/check.sh:165`·`tools/check_data.py:443` 의 정규식이 `src="js/[a-zA-Z_]*"` 라, 숫자·하이픈이 든 `00-base.css` 류는 **0개 매치**였다. css 6개는 `?v=` 갱신 누락을 잡을 수단이 없었다 | 정규식을 `(src\|href)="(js\|css)/..."` 로 확장 → **22개(js 16 + css 6) 전부 검사.** 실패 메시지도 `<link href=`/`<script src=` 를 구분하도록 정정. 양쪽 음성 테스트 통과 |

### 아무도 확인하지 못한 것 — 배포 Claude가 재개 후 확인할 것

1. **카카오 지도 내부** — SDK 도메인 화이트리스트 때문에 localhost 에서 로드 불가. 두 버전 모두 폴백 화면을 **동일하게** 표시하는 것까지만 확인했다. 마커·클러스터는 미검증. (완화 근거: `js/map.js`·`conv_map.js` 는 이번 커밋들에서 **블롭 해시가 안 바뀌었다**)
2. **`assets/images/places` 사진 163장** — 이 워킹트리엔 없어 사진↔이름 대조가 **SKIP** 됐다. **배포 서버에서 `bash tools/check.sh` 를 반드시 다시 돌려야 한다.** 「통과」가 아니라 「안 본 것」이다
3. **Cloudflare 엣지 캐시** 동작 — 실제 터널 URL 로 확인 못 했다
4. **모바일 실기기(iOS Safari)** — 터치 드래그·`safe-area-inset`·`env()`

### 배포 Claude 재개 체크리스트

1. `git pull`
2. **배포 서버에서 `bash tools/check.sh` 실행** — 사진 검사가 거기서만 돈다
3. 터널 URL 을 열어 **개발자도구 Network 탭에서 404 가 0건인지** 확인 (새 파일 16개)
4. **지도 탭을 실제로 눌러 볼 것** — 감사가 커버 못 한 유일한 기능 영역
5. Flask 재시작은 **선택** (§19-1 결론대로 보안 우려 없음). 재시작한다면 `cloudflared` 는 절대 끄지 말 것

- **`<link>` 6개의 순서는 고정이다.** `20-map.css` 가 앞 파일들을 덮어쓰는 구조이므로 순서를 바꾸면 스타일이 조용히 뒤집힌다
