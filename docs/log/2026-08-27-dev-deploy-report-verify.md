## 5. 배포 Claude 에게 넘긴 판단

배포 Claude 가 *"좌표 교체와 날짜 범위 채우기는 되돌리기 어려운 변경이라
확인받고 진행하겠다"* 고 물었다. 답은 이렇게 정리해 보냈다.

### ① 날짜 — 진행. 근거는 이미 데이터 안에 있다

`desc` 필드가 `"2026년 9월 | 9. 5.(토) ~ 9. 6.(일)"` 형태로 **실제 기간을 이미
담고 있다.** `date` 만 시작일로 잘려 있다. 확정 ISO 시작일 + `desc` 에 범위가
있는 조합이 정확히 10건(id 98·99·100·102·114·115·116·118·128·277).

교차 검증 둘이 통과했다.
- `desc` 의 요일 표기 16개를 2026년 실제 요일과 대조 → **16/16 일치**
- `data/raw/20260825_url_pagecopy_fulltext.txt` 에 화성시 공식 축제 일정표
  원문이 있고 4건이 완전 일치

형식은 `js/calendar.js` `_parseFestDateMeta` 기준으로 정확히 지정했다:

```
date: "2026-09-05 ~ 2026-09-06"
```

- 구분자는 **ASCII 물결 `~`(U+007E)**. 전각 `∼`·`-`·`—` 는 파싱되지 않는다
- **양쪽 모두 완전한 `YYYY-MM-DD`**. 끝값을 `"09-06"`·`"9. 6."` 로 적으면
  파서가 `null` 을 돌려주고 **end 가 조용히 start 로 되돌아간다** —
  화면에 오류가 안 뜨고 하루짜리로 회귀하는 무증상 실패다. 가장 위험한 실수
- 시작일이 근사(`"2026년 10월 중"`)면 `approx` 분기가 먼저 걸려 범위를 붙여도 무시된다

되돌리기 우려는 타당하지 않다. 원본(`desc`)이 같은 파일에 남고 값이 파생 가능하다.

### ② 좌표 — id118·id115 **두 건만** 진행

정정값이 저장소에 있다(위 2-1). 다만 성격 규정이 틀렸다 —
`37.2285,126.8266` 은 플레이스홀더가 아니다. **진짜 플레이스홀더는
`37.199,126.831` 이고 `js/map.js` 의 `HWASEONG` 상수와 소수점까지 같으며
21건이 공유한다.** 그중 15건은 주소가 `"경기도 화성시 미정"` 이라
좌표를 박으면 **없는 사실을 만드는 것**이다. 손대면 안 된다.

`id128 보육주간행사` 는 주소가 "화성시청 로비 및 대강당" 이라 **지금 좌표가 맞다.**
