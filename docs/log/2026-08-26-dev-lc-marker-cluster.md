## 1. ⚠ 같은 파일의 '격자 인덱스' 와 헷갈리지 말 것

`js/localcurrency.js` 에는 좌표를 키로 쓰는 자료구조가 **둘** 있다. 이름이 비슷해
다음 사람이 반드시 헷갈릴 자리라 먼저 갈라 둔다.

| | 격자 인덱스 | 좌표 묶기 (이 문서) |
|---|---|---|
| 이름 | `_lcGrid` · `LC_CELL` = 0.01° | `buckets` · `spots` |
| 키 | 좌표를 **잘라** 만든 셀 (`floor(lat/0.01)`) | 좌표 **그대로** (`p.lat + ',' + p.lng`) |
| 목적 | 뷰포트 질의 가속 (전수 스캔 제거) | 같은 점에 겹친 핀 합치기 |
| 수명 | 데이터당 1회 구축, 재사용 | idle 마다 뷰포트 안에서만 새로 만듦 |
| 성격 | 성능 상수 — 값을 바꿔도 결과가 안 변한다 | 동작 그 자체 — 화면에 그릴 점의 정의 |
| 위치 | :99-162 | :175-236 |

**시간 순서가 직관과 반대다.** 좌표 묶기(`fd71dd4`, 08:18)가 **먼저**고, 격자
인덱스(`f14bbf0`, 13:21)가 **나중**이다. 그래서 `fd71dd4` 시점의 `showViewportMarkers`
는 아직 `lcData.filter(...)` 로 27,374건을 전수로 훑고 있었다. 격자 이야기는
`docs/log/2026-08-26-dev-preview-lcgrid.md` §4 에 길게 있으므로 여기서는 다시 쓰지 않는다.

## 2. 데이터를 직접 셌다 — 넘겨받은 수치를 다시 잰다

`js/localcurrency-static.json` 을 node 로 전수 집계했다.

| 항목 | 값 |
|---|---:|
| 전체 건수 | 27,374 |
| 좌표 없는 건 | 0 |
| 고유 좌표 | 10,755 |
| 1건뿐인 자리 | 6,885 (64.0%) |
| 2~9건 자리 | 3,390 |
| 10~99건 자리 | 478 |
| 100건 이상 자리 | **2** |
| 한 좌표 최다 | **241건** — 경기도 화성시 동탄구 동탄대로시범길 134 |

배포 §27-H 가 든 *74.8% 중복 · 20,489건* 도 그대로 재현됐다
(2곳 이상인 자리 3,870개에 20,489건 = 전체의 74.8%). 최다 241건이 카림에비뉴라는 §27-H 의 지목도
데이터 쪽에서 뒷받침된다 — 이름에 '카림' 이 들어간 가맹점이 66건이다.

여기서 나온 가장 아픈 수는 겹침 비율이 아니라 이것이다.
**27,374 − 10,755 = 16,619건(60.7%)이 좌표만으로는 클릭할 방법이 없었다.**
한 좌표에 마커를 n개 쌓아 두면 클릭을 받는 것은 맨 위 하나뿐이기 때문이다.
(마커 히트테스트 자체는 SDK 가 이 컨테이너에서 안 떠 실측하지 못했다. 배포 §27-H
판정과 코드 경로로 논증한 것이다.)

## 3. 상한 300 을 겹친 핀이 통째로 잡아먹고 있었다

옛 코드는 `hits.length > LC_MAX_PINS(300)` 이면 **가맹점 단위**로 화면 중심에서
가까운 순으로 300개를 잘랐다. 겹친 자리는 한 자리가 상한을 수십 개씩 먹는다.

커밋 메시지의 '동탄 중심 뷰포트(±0.012°)' 를 다시 모사했다. 중심을
**(37.2003, 127.0740)** 로 잡으면 커밋의 세 수치가 **전부 동시에** 재현된다.

| | 옛 (가맹점 단위) | 새 (좌표 단위) |
|---|---:|---:|
| 후보 | 2,567건 | 2,567건 |
| 화면에 보이는 점 | **28** | **300** |
| 담기는 가맹점 | 300 | **1,823** |
| 잘려 나간 가맹점 | 2,267 | 744 |

1,823 ÷ 300 = 6.08 → 커밋 제목의 **6.1배**가 맞다. 2,567 − 300 = 2,267 도 맞다.
넘겨받은 수치가 아니라 내가 낸 수치였지만 그래도 다시 쟀다 — 격자 건에서 넘겨받은
숫자가 한 자리 틀렸던 전례가 있다(`2026-08-26-dev-preview-lcgrid.md` §8).

## 4. 고른 방법과 버린 방법

커밋 메시지에는 대안 검토가 안 적혀 있다. 되짚어 적어 둔다. 선택지는 넷이었다.

| 방법 | 판단 |
|---|---|
| **좌표 단위로 묶고 목록 카드** | **채택.** 새 의존성 0, 상한 코드는 자르는 단위만 바뀐다 |
| 스파이더파이(누르면 부채꼴로 흩기) | 버렸다. 카카오 SDK 기본 제공이 아니라 라이브러리를 얹어야 한다. 이 앱이 부르는 외부 스크립트는 카카오 SDK **한 개뿐**이다(index.html:936, `libraries=services`) |
| 좌표를 미세하게 흔들기(jitter) | 버렸다. **§27-H 가 '좌표는 맞다' 로 판정한 것을 코드가 다시 틀리게 만든다.** 길찾기가 그 좌표를 그대로 쓴다 |
| 상한 300 을 올리기 | 버렸다. 겹친 자리는 아무리 올려도 한 점으로 보인다. 화면에 보이는 점은 그대로고 마커 객체만 는다 |

핵심은 이것이다 — **상한 300 은 '그릴 수 있는 마커 수' 의 한계이지 '보여 줄 수 있는
장소 수' 의 한계가 아니었다.** 자르는 단위를 가맹점에서 좌표로 옮기니 같은 300 으로
6배가 들어왔다. 상수는 하나도 안 건드렸다.

## 5. 배지를 '2곳 이상' 인 자리에만 얹은 이유

`sp.items.length < 2` 면 배지를 안 만든다(:226).

- 고유 좌표 10,755개 중 **6,885개(64%)가 1건짜리**다. 전부 붙이면 그 자리들이 전부
  '1' 이라는 아무 정보 없는 숫자로 덮인다.
- 위 동탄 뷰포트로 세어 보면 그려진 300점 중 배지가 붙는 것은 **153점(51%)** 이다.
  나머지 147점은 깨끗하게 남는다. 다른 뷰포트는 재지 않았다.
- `99+` 로 잘리는 자리(:229)는 **데이터 전체에 2곳뿐**이다(241건·110건). 같은 뷰포트
  안에서는 최다가 71건이라 그 분기를 한 번도 안 탄다. 두 자리를 위해 넣은 안전장치다.

## 6. CustomOverlay 와 `pointer-events: none`

지역화폐 핀만 네이티브 `kakao.maps.Marker` 다 — 이유는
`docs/log/2026-08-26-dev-pin-selection-all.md` §4 에 이미 있다. 네이티브라 DOM 이
없으니 배지를 마커에 **붙일 수가 없다.** 그래서 배지는 별도 `CustomOverlay` 로
같은 좌표에 얹는다(:230-233, `yAnchor: 2.2` · `xAnchor: -0.15` — 마커 기준점이 바닥
끝이라(:357 주석) 위·오른쪽으로 밀어 놓는 값이다. 화면상의 실제 픽셀 위치는
SDK 미로드로 확인하지 못했다).

**그 순간 배지가 마커와 같은 자리를 차지한다.** 배지가 클릭을 먹으면 그 마커는
안 눌린다. 그런데 배지가 붙은 자리는 정확히 **여러 곳이 겹쳐 목록을 열어야 하는
자리**다 — 가장 눌러야 할 핀만 안 눌리는 역설이 된다. `css/20-map.css:397` 의
`pointer-events: none` 한 줄이 그걸 막는다. 주석도 그 자리에 남겨 뒀다.
(오버레이와 마커의 실제 레이어 순서는 SDK 미로드로 확인하지 못했다. 확인이 안 되는
쪽이라 더 방어적으로 껐다 — 배지는 어차피 읽는 것이지 누르는 것이 아니다.)

## 7. 목록 카드 `showLcSpotSlide` (:238-273)

마커 클릭 핸들러가 갈린다 — 1곳이면 종전 `showLcSlide`, 2곳 이상이면
`showLcSpotSlide`(:213-218). 겹치지 않은 자리의 동작은 **한 글자도 안 바뀐다.**

- 머리말은 `지역화폐 가맹점 N곳` + 주소 + *"이 건물에 있는 가맹점이에요"*.
- 목록에서 하나를 고르면 기존 상세 카드로 넘어간다. `onclick` **문자열에 객체를 못
  넣으므로** 전역 `_lcSpotBucket` 에 통째로 두고 인덱스만 넘긴다(:258·:271-273).
  전역 하나로 안전한 이유는, 인덱스를 담은 DOM(`#slide-inner`)과 그 전역이 **같은
  함수 안에서 같이 갈리기** 때문이다. 화면에 남은 인덱스는 항상 지금 전역을 가리킨다.
- 선택 링은 `bucket.items[0]` 로 건다(:242). 묶인 것들이 **같은 좌표**라 어느 것으로
  걸어도 같은 자리다.
- `_panPinAboveSlide(..., 50, 300)`(:244). 네 번째 인자는 지연이 아니라 슬라이드 카드
  높이 추정값이다(js/map.js:433-443). 개별 상세는 240, 목록 카드는 **300** 을 준다 —
  목록이 `max-height: 40vh` 라 더 길기 때문이다.
- 토스트 문구도 고쳤다(:203-204). 예전엔 상수 `LC_MAX_PINS` 를 그대로 넣어
  `300곳만 표시` 라고 했다. 마커는 정말 300개였으니 문장 자체가 거짓은 아니었는데,
  그중 겹치지 않아 닿을 수 있는 것은 28곳뿐이라 안내와 실제가 10배 어긋났다.
  이제 실제로 담긴 수(`shown`)를 말한다 — 위 뷰포트라면 *"가맹점 2,567곳 중 가까운
  1,823곳 표시"*.

## 8. 검증과 그 한계

- 커밋에 적힌 실측(Chromium 390×844): 겹침 슬라이드 3항목 렌더, 머리말
  `지역화폐 가맹점 3곳 / 동탄대로시범길 134`, 목록 클릭 → 개별 상세 전환,
  배지 배경 `rgb(22,163,74)` · 17px · `pointer-events none`, 예외 0건.
- ⚠ **지도 실동작(마커가 실제로 어디에 몇 개 놓이는지)은 검증하지 못했다.**
  카카오 SDK 가 이 컨테이너에서 안 뜬다. 커밋 메시지에도 그렇게 적어 뒀고, 묶기
  계산만 같은 알고리즘을 데이터에 돌려 확인했다.
- 되짚어 쓰면서 **자르기 단계 비용을 새로 쟀다.** 두 코드 모양을 node 로 옮겨,
  후보 2,567건을 이미 받은 상태에서 마커에 넘길 것을 고르기까지만 잰다.
  **옛 2.3ms → 새 2.9~3.1ms** (각 300회 평균, 3회 반복, 이 컨테이너 node v22).
  2,567건 정렬이 694개 묶기 + 694개 정렬로 바뀌면서 **오히려 0.6~0.8ms 늘었다.**
  이 커밋은 성능 개선이 아니다 — 화면 위 객체도 마커 300개에서 마커 300 + 배지
  오버레이 153개로 는다. 커밋 당시에는 이 비용을 재지 않았다.
- `tools/check.sh` 는 이번 되짚기에서 다시 돌리지 않았다.

## 9. 커밋 메시지가 틀린 곳 — `?v=`

메시지는 `?v= 2026082649 → 2026082650` 이라고 적었는데 **실제 diff 는 2026082651** 이다.
이유가 있다. 6분 전 배포 Claude 의 `2ded835`(사진 2차 반입)가 `js/photos.js` 만
`2026082650` 으로 올려 둔 상태였다. 번호를 한 값으로 통일하려면 50 을 넘겨야 했다.
메시지 쪽이 갱신을 놓친 것으로 보인다 — 이유는 메시지에 안 적혀 있다.
`?v=` 가 왜 되돌릴 수 없는 값이 됐는지는
`docs/log/2026-08-26-dev-cachebust-guard.md` 에 있다.

이 커밋의 `index.html` 변경 58줄은 **전부 `?v=` 숫자뿐**이고, `js/datalab.js` 변경도
`DL_VER` 한 줄뿐이다. 기능 변경은 `js/localcurrency.js` 와 `css/20-map.css` 둘뿐이다.

## 10. 곁가지 — 음식점에 같은 방식을 얹었다가 21분 만에 통째로 사라졌다

`cc9f94c`(08:50) ⑦ 항목이 `js/restaurants.js` 에 **똑같은 좌표 묶기**를 넣었다.
그 커밋의 수치도 다시 세어 확인했다 — 음식점 3,754건의 고유 좌표는 2,269개,
한 점 최대 38곳, 겹친 좌표 위에 2,047건이다(전부 일치). 소스 주석에도
*"지역화폐(js/localcurrency.js)에서 같은 문제를 겪고 좌표 단위로 바꿨다 — 여기도 같은

`.rs-count-badge` 로 색만 갈았다.

그리고 21분 뒤(08:50:23 → 09:11:46) `fcf2f62` 가 *"사용자 결정"* 으로 **지도에서
음식점 축을 통째로 걷어내면서 `js/restaurants.js` 348줄을 삭제**했다.
`showRsSpotSlide` 도 같이 사라졌다. 삭제 경위와 데이터 파일을 남긴 이유는

지금 저장소에 남은 좌표 묶기 구현은 지역화폐 쪽 하나뿐이다(grep 으로 확인.
`js/parking.js:236` 도 좌표를 키로 쓰지만 그쪽은 격자 셀 묶기라 §1 의 왼쪽 칸이다).

교훈이랄 것은 없고 사실만 적어 둔다 — **넣은 지 21분 만에 지워진 구조다.**
되살릴 일이 생기면 `git show cc9f94c:js/restaurants.js` 에 마지막 판이 통째로 있다
(그 커밋이 이 파일을 건드린 마지막 커밋이다). 남겨진 죽은 CSS `.rs-count-badge` 는 이미

## 11. 남은 것

- **머리말 주소가 빈칸으로 뜨는 자리가 있다.** 카드는 `bucket.items[0].a` 를 쓰는데
  (:246), 묶인 것 중 첫 건만 주소가 비어 있고 나머지엔 있는 자리가 **51곳**,
  전부 비어 있는 자리가 **20곳**이다(직접 셌다. 전체 3,870개 겹침 자리 중 1.8%).
  비어 있지 않은 첫 건을 고르면 51곳은 바로 메워진다.
- **목록 → 상세로 간 뒤 목록으로 돌아갈 길이 없다.** `showLcSlide` 가 `#slide-inner`
  를 통째로 갈아 끼우고 되돌리는 버튼이 없다. 다른 걸 보려면 카드를 닫고 핀을 다시
  눌러야 한다.
- 목록 카드에는 길찾기·저장 버튼이 없다. 개별 상세에만 있다.
- `spots.forEach` 를 두 번 돈다(:208 마커, :225 배지). 음식점 쪽(`cc9f94c`)에서는
  한 루프로 합쳐 놨었다. 300회짜리라 실익은 재지 않았다.
- **배지 숫자는 '지금 업종 필터가 걸린 상태에서 이 자리에 있는 곳 수'** 다. 묶기가
  필터를 거친 `hits` 위에서 일어나기 때문이다(:172-190). 건물 전체 가맹점 수가
  아니다 — 헷갈릴 여지가 있지만 카드 머리말 수와는 항상 일치하므로 그대로 뒀다.
