## 1. 🚨 가장 큰 문제 — PLACES 배열에 빈칸이 있어 앱이 반쯤 죽어 있었다

이모지를 고치러 들어갔다가 발견했습니다. **이게 이번 작업에서 가장 중요한 건입니다.**

`js/data.js:140` 이 `},,` 로 끝나 있었습니다. 쉼표가 두 번 찍혀
`PLACES` 137번 자리에 **빈칸(hole)** 이 생겼습니다.

```js
{ id:230, name:"예랑 도예원", ... desc:"화성시 예랑 도예원" },,   ← 쉼표 2개
{ id:232, name:"보물섬 모험 레져", ...
```

### 왜 아무도 몰랐나

이건 **문법 오류가 아닙니다.** `[1,,2]` 는 적법한 자바스크립트입니다.
그래서 `tools/check.sh` 의 문법 검사를 그대로 통과했고, 화면도 멀쩡해 보였습니다.

| 배열 메서드 | 빈칸을 만나면 | 결과 |
|---|---|---|
| `filter()` `forEach()` `map()` | 건너뛴다 | 목록 화면 정상 — 그래서 눈에 안 띄었다 |
| `find()` | `undefined` 로 **방문한다** | `x.id` 접근에서 TypeError |

`js/tourism.js` 의 목록 항목 클릭은 `goMapFocus(lat,lng,4,id)` 를 부르고,
그 안에서 `PLACES.find(x => x.id === placeId)` 를 돌립니다.
`find` 는 앞에서부터 훑다가 **137번 빈칸에서 그냥 죽습니다.**

즉 137번보다 **뒤에 있는 항목은 눌러도 아무 반응이 없었습니다.**

### 실측 (Chromium, 수정 전)

```
대상(index 200): 다원이음터 / id 194
  PLACES.find 로 조회   💥 Cannot read properties of undefined (reading 'id')
  빈칸 앞 항목 조회      정상 (화성호)
```

전체 251곳 중 **114곳이 클릭 불능**이었습니다. 같은 이유로
`js/home.js` 의 `renderRecentSection()` 도 최근 본 항목이 뒤쪽에 있으면 죽습니다.

### 수정 후 실측

```
빈칸 뒤 항목 조회: 성공 113 / 실패 0
문화재 항목 실제 클릭 → 예외 없음
PLACES.length  252(빈칸 포함) → 251
```

### 재발 방지 — tools/check_code.js 에 검사 D 추가

길이만 세는 검사로는 절대 못 잡습니다. 원소를 하나씩 봐야 합니다.
전역 배열을 전부 훑어 **빈칸과 null 원소**를 찾습니다.

**처음 짠 검사는 미탐이었습니다.** `Object.getOwnPropertyNames(ctx)` 로 이름을 모았는데,
`const PLACES = [...]` 는 렉시컬 바인딩이라 vm 컨텍스트의 속성이 되지 않습니다.
그래서 무관한 `var` 배열 4개만 훑고 "빈칸 0건" 이라고 답했습니다 —
버그를 일부러 다시 넣어 보고서야 알았습니다.

원문에서 선언 이름을 정규식으로 긁어 **컨텍스트 안에서 평가**하도록 고쳤습니다.
스캔 대상이 0개면 통과가 아니라 실패로 처리합니다(조용한 미탐 차단).

실패 주입 검증:

| 주입 | 결과 |
|---|---|
| 정상 | `i 전역 배열 6개 원소 291개 빈칸·null 0` |
| `},,` (빈칸) | `FAIL PLACES[137] 가 빈칸 ('예랑 도예원' 부근)` |
| `}, null,` | `FAIL PLACES[137] 가 null ('예랑 도예원' 부근)` |

## 2. 문화재 42곳이 지도에서만 보이고 목록·검색에는 없었다

배포 Claude가 넣은 `heritage` 42건이 **지도 칩으로만** 닿을 수 있었습니다.

| 경로 | 수정 전 | 수정 후 |
|---|---|---|
| 지도 칩 `data-cat="heritage"` | ✅ | ✅ |
| 추천 탭 '전체' 목록 | ❌ 통째로 빠짐 | ✅ 251건에 포함 |
| 추천 탭 서브탭 | ❌ 없음 | ✅ '문화재' 추가 (42건) |
| 홈 검색 | 나오긴 하나 회색 📌 기본값 | ✅ 보라 🏛 |
| 최근 본 목록 | ❌ 눌러도 안 쌓임 | ✅ 쌓임 |

### 원인

`js/tourism.js` `renderTourismList()` 의 '전체' 필터가 이랬습니다.

```js
const cats = ['tourist','restaurant','festival'];   // heritage 없음
```

게다가 `restaurant` 는 **PLACES 에 0건**입니다. 맛집은 `CONVENIENCE`(생활 탭) 소속이라
여기 올 일이 없습니다. 죽은 값 하나가 자리를 차지하고 정작 필요한 게 빠져 있었습니다.

```js
const cats = ['tourist','festival','heritage'];
```

### 함께 손본 것

- `renderTourismList('heritage-only')` 분기 추가
- `switchTourismSub()` 에 `heritage` 처리 — 문화재는 테마 태그(바다·자연·가족)와
  맞지 않아 테마 칩과 축제 캐러셀을 숨깁니다
- `iconClass()` 에 `heritage: 'pi-heritage'`, `iconContent()` 에 `heritage: '🏛'`
- `css/00-base.css` 에 `.pi-heritage { background:#F5F3FF }` — `data.js` 의 heritage 색과 동일
- `js/home.js` `_CAT_STYLE` 에 `heritage` 항목 추가 (없어서 회색 📌 로 떨어졌음)
- `pushRecent()` 가 문화재도 받도록 완화. PLACES 의 id 는 카테고리를 넘어 **전역 유일**이라
  (heritage ∩ tourist = 0건, heritage ∩ festival = 0건 실측) `k:'t'` 하나로 둘 다 담아도 안전합니다.
  축제는 기간이 지나면 의미가 없어 계속 제외합니다.
