## 1. 축제를 추천 탭에서 소식 탭으로 옮겼다

추천 탭 서브내비의 `data-sub="festival"` 칩을 없애고, 소식 탭(`#page-living`)
'이번 달 축제' 캐러셀 아래에 **행사 전체**(`#festival-all-section`)를 만들었다.

사용자가 두 가지 안을 줬다 — *"이번주 소식 전체보기 하면 볼수있도록"* 또는
*"이번달 축제 밑에 놓고 한 4 5개만 띄워놓고 밑에 더보기 버튼"*.
**둘을 하나로 합쳤다.** 목록은 한 벌만 두고 입구를 둘로 냈다. 따로 만들면
나중에 한쪽만 고쳐서 어긋난다.

### 이름을 '축제'가 아니라 '행사'로

데이터 50건에 콘서트·추모제·음악회가 섞여 있다. '축제 전체'는 사실과 어긋나서
같은 날 '행사 전체'로 다시 바꿨다.

### 정렬을 원본 순서로 두면 안 된다

5개만 접어 보여 주므로 맨 위 5개가 사실상 이 섹션의 전부처럼 읽힌다.
끝난 행사가 먼저 오면 쓸모가 없다. **진행 중 → 예정(가까운 순) → 날짜 미상 →
종료(최근 순)** 로 세웠다.

⚠ 상태는 `p.status` 가 아니라 `festStatus()` 로 구한다. `p.status` 는 50건이
전부 `'upcoming'` 으로 굳어 있다(§27-H 에 이미 기록된 죽은 필드).

### 칩을 지우면 같이 죽는 자리 2곳

칩만 지웠으면 조용히 고장 날 곳이 있었다. `querySelector` 로 그 칩을 찾아
누르는 코드였다.

| 위치 | 증상 | 조치 |
|------|------|------|
| 「이번 주 소식」 '전체 보기' | 없는 칩을 눌러 아무 일도 안 남 | `goFestivalAll()` |
| 햄버거 메뉴 '이번달 축제' | 같음 | '행사 전체' 로 개명 + 같은 함수 |

## 2. 「이번 주 소식」을 진짜 이번 주로

앞으로 **30일**을 담고 있어 다음 달 행사까지 올라왔다. 월요일 시작 주(월~일)로 잘랐다.

```js
var dow = (today.getDay() + 6) % 7;   /* getDay() 는 일요일이 0 */
```

이 보정을 빼먹으면 **일요일에 다음 주가 잡힌다.**

두 가지를 판단해서 넣었다.

- **근사 일정 제외.** `'2026년 8월 중'` 은 1일로 채워진 값이라 주 단위로 특정할 수
  없다. 그대로 두면 8월 1일로 계산돼 엉뚱한 주에 걸린다. 아래 '행사 전체' 에는 있다.
- **지난 요일도 이번 주면 표시**(`D+N`). '이번 주 소식'이니 월요일에 끝난 것도
  이번 주의 소식이다.

'전체 보기' 버튼은 뺐다(사용자 지시). 같은 화면 아래에 '행사 전체'가 있는데
위에서 아래로 보내는 버튼은 군더더기다.

## 3. 축제 상세·캘린더가 '온 탭'으로 돌아가지 않던 문제

사용자 지적: *"소식탭에서 축제 캘린더 보기 하면 좌측 상단에 소식이라고 안 뜨고
관광이라고 뜨네. 그리고 나갈 때도 추천으로 나가지네."*

`#view-calendar` 와 `#view-festival-detail` 은 **추천 탭 안의 뷰**다. 소식에서
열려면 `go('tourism')` 을 먼저 태워야 하고, 그 순간 헤더도 뒤로가기도 추천 것이
된다. 호출부가 6곳인데 각자 `go('tourism') + setTimeout(260)` 을 복사해 쓰고 있어
**어디서 왔는지 아무도 기억하지 않았다.**

뷰를 소식 탭으로 복제하지 않고 '온 곳'만 기억하게 했다. 복제하면 행사 상세가
두 벌이 되어 한쪽만 고치는 사고가 난다.

- `openFestView(kind, id)` — 열기 전에 `.page.active` 의 id 와 `scrollTop` 을 담는다
- `backFromCalendar()` / `backFromFestivalDetail()` — 온 탭으로 되돌리고 스크롤 복원
- 기본 문구를 `← 관광` → `← 추천` 으로 정정. 하단 내비 이름이 '추천'이고
  '관광'은 옛 이름이다(`js/datalab.js` 는 이미 '‹ 추천' 이었다)

⚠ `hideCalendar()` / `hideFestivalDetail()` 자체는 건드리지 않았다. 그 둘은
`js/calendar.js` 에서 **'캘린더를 닫고 상세를 연다'** 는 뜻으로도 쓰인다.
거기에 탭 복귀를 넣으면 상세가 열리기 전에 소식으로 튕긴다.
탭 복귀는 뒤로가기 버튼 전용 `backFrom*()` 에만 넣었다.

⚠ `resetTourismPage()` 에서 `_festViewFrom` 을 지운다. 소식에서 상세를 열어 둔 채
하단 내비로 추천을 누르면 뷰는 목록으로 돌아가는데 기억만 남아, 다음 뒤로가기가
엉뚱하게 소식으로 튄다.

## 4. `go()` 뒤 `setTimeout` — 중간 화면이 보이던 것 6곳

사용자 지적: *"소식탭에서 축제 클릭해서 상세 들어가면 왜 추천탭으로 잠깐 빠르게
넘어갔다가 들어가는거지?"*

**`go()` 는 뷰 교체와 목록 렌더까지 전부 동기로 끝낸다**(`js/nav.js`).
그러니 뒤에 `setTimeout` 을 두면 그 사이 브라우저가 '엉뚱한 화면'을 완성해서
페인트한다. 지연은 애초에 필요가 없었고, 옛 호출부가 복사해 쓰던 값이었다.

같은 패턴을 저장소 전체에서 찾아 함께 고쳤다. rAF 로 26프레임씩 샘플링한 실측:

| 경로 | 파일 | 전 | 후 |
|------|------|----|----|
| 소식 → 행사 상세 | `js/tourism.js openFestView` | 목록 번쩍 | **0프레임** |
| 홈 → 전체 순위 보기 | `js/home.js` | 목록 **6프레임** | 0 |
| 메뉴 → 캠핑장 | `js/mapnav.js menuGoTourism` | '인기' 칩 **9프레임** | 0 |
| 메뉴 → 모범음식점 | `js/mapnav.js menuGoLiving` | 목록 2번 그림 | 1번 |
| 뒤로가기 스크롤 복원 | `js/tourism.js` | 맨 위 2프레임 후 점프 | 첫 프레임부터 복원 |
| 검색 → 편의시설 | `js/home.js _srClick` | 모범음식점 300ms | 즉시 |

**남겨 둔 지연**: `goFestivalAll()` 의 280ms. 이쪽은 뷰 교체가 아니라 **스크롤**이라
페이지 전환 애니메이션(0.26s)이 끝난 뒤 움직이는 편이 자연스럽다.
'중간 상태가 보이는' 문제가 아니다. 코드에 그 이유를 적어 뒀다.

## 5. 데이터랩 뷰가 배타가 아니었다 (별건 버그)

위 검증 중에 찾았다. `showFestivalDetail()` 이 `#view-datalab` 을 안 숨기고 있었다.

**재현**: 추천 → '세대별로 많이 찾는 곳' 전체 보기 → 만세구 · 30대 → 27위
**화성뱃놀이축제** 클릭 → 데이터랩 화면이 그대로 남고 상세는 그 아래에 그려져
**눌러도 아무 일이 없는 것처럼 보인다.**

- 데이터랩 원본은 `화성뱃놀이축제`, PLACES 는 `화성 뱃놀이 축제` 다.
  배포 Claude 가 넣은 `dlGoPlace` 공백 정규화 덕에 도달 가능해졌다.
- `_dlView` 도 함께 `null` 로 내린다. display 만 내리면 `dlLoad` 의 늦은 콜백이
  `if (_dlView !== 'popular') return;` 를 통과해 숨긴 뷰를 다시 그린다.

**추천 탭의 네 뷰는 서로 배타여야 한다** —
`#view-tourism-list` · `#view-calendar` · `#view-festival-detail` · `#view-datalab`.

### 반영하지 않은 지적

검증 에이전트가 "구별 보기가 근사 분류라 경계 장소가 다른 구로 묶인다"고 했으나
**틀려서 넣지 않았다.** `js/district.js` 의 구 라벨은 카카오 `coord2RegionCode`
(공식 행정구역 코드)라 분류는 정확하다. 부정확한 것은 지도 카메라의 사각형 범위다.
없는 결함을 자백하면 있는 결함의 신뢰도까지 같이 떨어진다.

## 9. 병행 작업 충돌

이날 다른 세션의 Claude 가 같은 화면을 동시에 만졌다(`2be0b47` · `78c476d` ·
`7a561d7` 등). 이번에는 상호 보완이었지만 — '남는 네모'를 한쪽은 통계 카드로,
다른 쪽은 아이콘 줄 위 30px 패딩으로 읽어 **둘 다 실재했고 둘 다 고쳐졌다** —
방향이 갈렸다면 한쪽이 덮였다.

리베이스는 전부 `?v=` 충돌이었고, 한 번은 서브탭 칩 줄이 겹쳤다(상대는 '전체'→'인기'
개명, 나는 축제 칩 제거). **양쪽 의도를 모두 살려서** 해결했다.

⚠ `?v=` 번호 체계가 두 갈래로 갈렸다(`2026082705` vs `20260826102`).
큰 쪽을 채택하되 **한 칸 더 올려야 한다** — 상대 번호를 그대로 쓰면 내 js 변경이
캐시에 막힌다.
