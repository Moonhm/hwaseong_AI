## 0. 새 세션은 이전 세션을 기억하지 못한다 — 그래서 재구성했다

사용자가 *"어디까지 했어"* 라고 물었을 때 이 세션은 **막 시작한 상태**였다.
답할 재료가 기억에 없으므로 전부 다시 쟀다. §12 가 적어 둔 대로
**배포 컨테이너에는 `~/.claude/projects` 바인드 마운트가 없어** 세션 기록이
컨테이너와 함께 사라지기 때문이다. 이번에도 확인했다.

```
$ findmnt -no SOURCE,TARGET ~/.claude/projects
(출력 없음)                     ← 배포 컨테이너가 맞다
```

재구성에 쓴 것은 셋이다 — **git 로그** · **`docs/log/`** · **실측**. 이 셋만으로
"어디까지 했나" 가 복원됐다는 것이, 이 저장소의 기록 규칙이 실제로 값을 한다는 뜻이다.
**기억이 아니라 저장소가 인수인계를 했다.**

## 1. 재부팅은 이번이 처음이 아니고, 마지막도 아닐 것이다

§12 는 2026-08-30 하루에 세 번을 적어 두었다. 여기에 한 번을 더한다.

| 시점(KST) | 호스트명 | 비고 |
|---|---|---|
| 08-30 | `cfe9165e4b50` → `48d2bd481700` | §12 기록 |
| **09-01** | → **`addb5c12b3c5`** | **이번 건** |

재부팅 자체는 이전 세션(09-01 16:44~16:57 KST)이 이미 처리해 두었다.
서버는 그때부터 계속 살아 있다.

```
$ ps aux | grep -E 'server.py|cloudflared'
tmux new -d -s app python3 -u tools/server.py --port 8080     # 16:50 KST 부터
cloudflared tunnel --url http://localhost:8080                 # 같이 기동
```

**`work` 볼륨은 이번에도 그대로 살아남았다.** 저장소·커밋·`assets/` 전부 무사하다.
§12 의 판단("재부팅되면 날아간다가 아니라 어디에 뒀느냐가 전부") 이 또 맞았다.

(콘솔의 「수정 일시」와 일치).

## 3. 등록이 먹었는지는 대조군을 세워서 쟀다

§12 가 적어 둔 확인 명령은 배포 주소 하나만 때린다. 그런데 **`200` 하나만 보고는
"등록이 먹었다" 와 "이 엔드포인트가 원래 아무나 통과시킨다" 를 구분할 수 없다.**
그래서 **없는 도메인**을 대조군으로 같이 쟀다.

| Referer | 응답 | 판정 |
|---|---|---|
| `https://checks-sciences-palestinian-cottages.trycloudflare.com/` | **200** | 등록 먹었다 → 지도 산다 |
| `http://localhost:8080/` | 401 | 여전히 미등록 |
| `https://example.invalid/` (대조군) | 401 | **검사가 유효하다는 증거** |

대조군이 401 이므로 앞의 200 은 진짜 등록 결과다. 대조군 없이 200 만 보고 닫았다면
그건 **측정이 아니라 기대**였다. `docs/log/2026-08-31-deploy-kakao-domain.md` 건과
같은 함정을 한 겹 더 막은 것이다.

> **`http://localhost:8080` 은 이번에도 넣지 않았다.** §12 가 권고만 하고 필수로
> 잡지 않은 항목이고, 사용자 지시 범위 밖이라 손대지 않았다. 넣으면 컨테이너
> 안에서도 SDK 가 내려와 확인이 한 겹 늘어난다.

## 5. 클라이언트 시크릿 — 결론을 이 로그가 아니라 `WORKFLOW.md` 로 올린다

사용자가 붙여 준 콘솔 화면에 **클라이언트 시크릿 두 개**(카카오 로그인용·비즈니스
인증용)가 딸려 왔다. `WORKFLOW.md` 의 「⚠ 클라이언트 시크릿은 저장소·대화에 붙여
넣지 마십시오」(2026-08-31 신설) 가 **정확히 예상한 경로 그대로**다 — 화면을 통째로
복사하면 딸려 간다고 적혀 있었다.

저장소 오염은 없다. 작업트리와 **git 히스토리 전 리비전**을 훑었다.

| 값 | 저장소 | git 히스토리 |
|---|---|---|
| 클라이언트 시크릿 2개 | **0건** ✅ | **0건** ✅ |
| REST API 키 | `WORKFLOW.md` §12 · `tools/` 5개 · `docs/log/` 2개 | 있음 (기지의 건) |

**사용자 판단(2026-09-02): 조치 불필요.** — *"이거 키 전부 만료일 설정해서 괜찮아
노출돼도."* 기존 REST 키·JS 키에 적용되던 종결 근거(만료일)를 **클라이언트 시크릿까지
확장**한 것이다. 이 판단은 `WORKFLOW.md` 에 올렸다.

### 내가 그 왕복을 한 번 더 했다

`WORKFLOW.md` §0 은 이 사고를 이미 기록해 두었다 — 08-24 감사가 올리고, 08-25
사용자가 종결했는데 **결론이 로그에만 남아** 08-30 감사가 같은 건을 또 올렸다는 것.
그래서 「끝난 판단은 반드시 `WORKFLOW.md` 로」 규칙이 생겼다.

**그런데 이번에 내가 REST API 키를 「재발급 필요」로 다시 올렸다.** 규칙이 예측한
반복을 규칙이 있는 상태에서 반복한 것이다. 원인은 순서였다 — 콘솔 화면을 보자마자
경고부터 냈고, `WORKFLOW.md` 를 읽은 것은 그다음이었다.

> **교훈: 「심각」 딱지를 붙이기 전에 `WORKFLOW.md` 를 먼저 검색한다.**
> 이 저장소는 종결된 보안 판단을 그 파일에 모아 두기로 이미 정했다. 검색 한 번이
> 사용자를 세 번째로 귀찮게 하는 것을 막는다. 실제로 이 건에서 걸렸어야 할
> 검색어는 `시크릿`·`REST API` 두 개뿐이었고, 둘 다 §12 에서 바로 걸린다.

## 6. 근본 원인은 그대로다 — 임시 터널

사용자가 남긴 말이 이 건의 핵심이다.

> *"언제 또 서버가 재부팅 될지 모르겠다."*

맞다. 그리고 재부팅될 때마다 **다섯 자리를 다시 맞춰야 하고, 그중 하나(콘솔)는
Claude 가 못 한다.** `check.sh` 가 네 자리를 세어 주지만 다섯 번째는 사람 기억에
의존한다. 이번에도 그 다섯 번째만 반나절 넘게 열려 있었다.

`trycloudflare.com` 은 **매번 새 주소를 뽑는 임시 터널**이라 구조적으로 그렇다.
§12 가 이미 답을 적어 두었다 — **Named Tunnel(고정 도메인)**. 주소가 고정되면
저장소 네 곳도 콘솔 한 곳도 **다시는 안 고쳐도 된다.**

```
DS&ML센터 031-229-8897 — 주최 측 매뉴얼 9장 Named Tunnel 문의
```

**이건 Claude 가 못 하는 일이다**(외부 기관 문의). 재부팅이 반복되는 한 이 왕복은
계속 돌아온다. 해커톤 기간이 남아 있다면 문의해 두는 편이 싸다.
