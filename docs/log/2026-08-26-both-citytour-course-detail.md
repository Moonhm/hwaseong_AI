## 1. 화면을 새로 설계하지 않았다 — 축제 상세의 얼개를 그대로 폈다

`_renderDatalabView(kind)` 는 `'popular' | 'age' | 'tour' | 'report'` 넷을 문자열
하나로 갈랐다. 여기에 다섯째를 넣되 **번호가 붙는다**는 게 유일한 차이다.

```js
if (kind && kind.indexOf('course:') === 0) return _dlViewCourse(el, +kind.slice(7));
```

접두사 문자열로 간 이유는 하나다. 기존 네 뷰가 전부 같은 가드를 갖고 있다
(`js/datalab.js:517·550·591·741`). 코스만 번호가 붙어 문자열을 만들어 비교한다.

```js
if (String(_dlView) !== 'course:' + no) return;    /* js/datalab.js:451 */
```

`_dlView` 를 문자열 한 개로 유지하면 **늦게 도착한 fetch 응답을 버리는 장치가
그대로 재사용**된다. 코스 번호를 `_dlCourseNo` 같은 별도 전역에 두면 뷰 종류와
번호 두 축을 매번 함께 확인해야 하고, 그중 한 곳을 빠뜨리면 3번 코스를 누른 뒤
7번으로 옮겼을 때 3번 응답이 7번 화면을 덮는다.

### 안 간 길 — `#view-course` 를 index.html 에 새로 만들기

축제 상세(`#view-festival-detail`)처럼 전용 DOM 을 하나 더 두는 길도 있었다.
그쪽으로 가면 표시/숨김 짝을 `showDatalab` · `hideDatalab` · `switchTourismSub` ·
`js/nav.js` 재진입 복원까지 **네 곳에 더** 걸어야 한다. `#view-datalab` 안에서
`innerHTML` 을 갈아 끼우면 그 네 곳이 이미 맞춰져 있다.

## 2. ⭐ 들르는 곳을 이름이 아니라 PLACES id 로 이었다

JSON 의 `spots[]` 는 `{ "id": 24, "name": "화성 융릉과 건릉" }` 꼴이다.
왜 이름만 두지 않았나 — **이름 매칭은 한 글자만 달라도 조용히 끊긴다.**
실제로 `PHOTO_INDEX.byName` 을 두드려 봤다.

| 조회 키 | 결과 |
|---|---|
| `화성 융릉과 건릉` | **HIT · 4장** |
| `융릉과 건릉` | MISS |
| `화성융릉과건릉` | MISS |

빈 화면도 콘솔 오류도 안 난다. 그냥 사진이 없는 곳처럼 보인다. 같은 사고가 같은 날
두 번 더 났다 — `bc83f00` 09:51(`dlGoPlace` 공백 정규화) · `4bcf437` 10:23(홈
인기순위 사진). ⚠ 다만 둘 다 이 커밋(09:20) **뒤**다. 앞선 사고를 보고 피했다고는
못 쓴다 — 이름 매칭이 실제로 끊긴다는 증거로만 적는다.

### ⚠ 되짚어 보니 id 가 사진을 직접 가져오는 건 아니다

오늘 다시 세어 보고 커밋 메시지보다 정확하게 적을 것이 생겼다.
`placePhotoAll()`(js/ui.js)은 `byId[p.id]` → 없으면 `byName[p.name]` 순이다.
그런데 현재 `PHOTO_INDEX.byId` 는 **9건**뿐이고(byName 은 265건),
코스가 쓰는 **고유 id 31개 중 byId 에 걸리는 것은 0건**이다.
즉 이 화면의 사진은 전부 `byName`, 다시 말해 **JSON 에 적힌 이름 문자열**로 붙는다.

그러면 id 는 무엇을 지키나. 두 가지다.

1. **지도 링크.** `_dlSpotRow` 는 `goMapFocus(0, 0, 4, sp.id)` 로 핀을 지목한다.
2. **대조 가능성.** id 와 이름을 나란히 적어 두면 둘이 어긋난 것을 기계가 찾아낼
   수 있다. 이름만 적으면 대조할 상대가 없다. 아래 §3 이 그 결과다.

| | 이름만 적기 | id + 이름 적기 |
|---|---|---|
| 지도 | 이름→좌표를 매번 찾아야 함 | `goMapFocus(…, id)` |
| 오타 검출 | **불가** | PLACES 와 전건 대조 |
| 이름이 바뀌면 | 조용히 끊김 | 대조에서 FAIL |

## 3. ⭐ 검증 스크립트가 잡아낸 내 실수 3건

숨기지 않고 그대로 옮긴다. `7875240` 커밋 메시지 원문이다.

> 검증 스크립트가 내 실수 3건을 잡았다: id:29/31 을 봉림사↔남양향교로 뒤바꿔
> 적었고, id:26 을 화성시 역사박물관과 노작홍사용문학관 두 곳에 썼다.
> 최종 대조 결과 불일치 0건, 등재된 장소 전부 사진 보유.

사진이 뜨고 남양향교를 누르면 봉림사 핀으로 간다 — **틀린 채로 잘 도는** 결함이다.

### 그 스크립트는 남기지 않았다

## 4. PLACES 에 없는 곳은 id 없이 뒀다

입파도(코스 3)와 옥란재(코스 7) 두 곳이다. 둘 다 PLACES 에 이름으로도 없다.

```js
var go = (sp.id != null)
  ? ' onclick="hideDatalab();goMapFocus(0,0,4,' + sp.id + ')"' : '';
```

`id` 가 없으면 `onclick` 이 통째로 안 붙고, `is-link` 도 `›` 화살표도 안 붙는다.
**누를 수 없는 줄로 보이게** 만든 것이다. 썸네일 자리에는 코스 색 점(`.dl-spot-dot`)이
들어간다 — 10px 원에 좌우 여백 18px 를 줘 폭이 46px 이 되는데, 사진이 있는 줄의
`photoThumb(..., 46, ...)` 와 같은 폭이라 목록이 안 어긋난다.

**가까운 다른 곳의 id 를 붙이지 않았다.** 그러면 입파도를 눌렀을 때 입파도가 아닌
핀으로 간다 — 잘못된 목적지는 목적지 없음보다 나쁘다. **항목을 빼지도 않았다.**
실제 코스에 들어 있는 곳이므로 `sp.addr` 를 `.dl-spot-sub` 로 보여 준다.

렌더로 확인한 결과: 코스 3 은 2행 중 **1행만** 링크, 코스 7 은 3행 중 **2행**이다.

## 6. 후속 네 커밋이 왜 필요했나

### 6-1. `082877a` — 코스 전용 히어로 이미지

첫 판은 히어로를 **첫 장소의 사진**으로 썼다. 코스 5·8 은 `spots` 가 0곳이라
히어로가 색면뿐이었고, 다른 코스도 '이 코스의 얼굴'이 아니라 '첫 방문지 사진'이었다.
`assets/images/courses/<코스명>` 을 우선 쓰도록 `_dlCourseHeroSrc` 앞에 다섯 줄을 넣었다.

되짚어 보니 **코드가 커밋 메시지와 다르다.** 메시지는 "없으면 첫 장소 사진 대체"
라고 적었지만, 실제로는 `c.name` 이 있으면 무조건 전용 경로를 돌려주고 끝난다 —
아래 첫 장소 탐색 루프는 `c.name` 이 빈 코스에만 닿는다(그런 코스는 0개다).
실제 대체는 `<img onerror="this.style.display='none'">` 가 맡아, 파일이 없으면
img 만 숨고 코스 색 그라데이션 배경이 남는다. 결과적으로 화면이 깨지진 않지만
**주석이 코드보다 관대하게 적혀 있다.**

부수 효과로 코스 5·8 도 히어로를 갖게 됐다(렌더 실측 `<img>` 1개).

이미지 자체는 이 저장소에 없다 — `.gitignore` 에 `assets/` 가 통째로 들어 있어
`git ls-files assets/images/courses/` 가 0건이고 폴더도 없다. 경로만 코드가 만든다.
파일명이 NFD 라 11장이 전부 404 났던 사고와 `.png` → `.jpg` 전처리(15.5MB → 1.1MB)는
`docs/log/2026-08-26-deploy-cinema-merge.md` §8② 와 §9 에 있다.

### 6-2. `441ba24` — '투어' 서브탭 분리

사용자 지시: *"추천탭 서브 카테고리 인기에 있는 화성시티투어는 새로운 서브
카테고리 투어를 따로 만들어서 넣어줘."*

칩을 '인기' **바로 뒤**에 뒀다. 뒤따르는 관광지·문화재·숙박·캠핑·템플스테이는
'장소 종류' 필터인데 인기·투어는 큐레이션이라 성격이 같은 둘을 앞에 모았다(칩 7개).

빠뜨리기 쉬운 자리는 `switchTourismSub` 의 `sections` 배열이었다. 이 배열이
서브탭을 옮길 때 전부 `display:none` 으로 내리는 목록이라, `'tourism-tour'` 를
안 넣으면 투어를 켠 뒤 다른 탭으로 가도 시티투어가 **남는다**.

`renderDatalabSections()` 에서는 반대로 `renderDlCityTour()` 호출을 **뺐다** — 남겨
두면 '인기'를 열 때마다 숨어 있는 `#dl-tour-body` 를 헛되이 다시 그린다.
`js/nav.js` 는 손대지 않았다. 재진입 복원이 '칩이 있으면 무조건
`switchTourismSub`' 이라 새 칩이 자동으로 걸린다.

### 6-3. `436ed70` — 코스 10개 전부 + 전체 보기에도 사진

사용자 지적 2건이다.

① *"왜 6개만떠?"* — `renderDlCityTour` 가 `cs.slice(0, 6)` 이었다. '인기'
큐레이션 안의 **가로 미리보기 캐러셀**이던 시절의 제한인데, 6-2 에서 전용 서브탭이
된 뒤에도 그대로였다. 그 탭의 본문이 6개만 보이고 나머지 4개는 '전체 보기'를 한 번
더 눌러야 나왔다. 제한을 뺐다.

② *"전체보기하면 또 사진이 안뜨네?"* — **경로 문제가 아니었다.**
`_dlViewTour` 는 처음부터 이미지를 그리지 않았다. 28px 번호 배지(`.dl-course-no`)뿐이라
같은 코스가 화면마다 다르게 보였다. 68px 썸네일(`.dl-course-thumb`)을 넣고 번호는
사진 위 배지로 올렸다. 배경이 코스 색이라 404 여도 색 사각형 + 배지가 남는다.

### 6-4. `16f7c68` — 사실은 첫 후속이었다

`7875240` 은 `DL_VER` 을 `2026082672` 로 올리고 `css/50-datalab.css?v=` 도 올렸는데
`js/datalab.js?v=` 만 `2026082671` 로 남았다. 671 을 캐시한 브라우저는 옛 `DL_VER`
을 계속 써서 새 JSON 을 안 받는다 — **데이터를 바꿔 놓고 화면만 그대로인**,
눈에 안 보이는 실패다. 1분 뒤 한 줄로 맞췄다.

## 7. 검증

카카오 지도 SDK 는 이 컨테이너에서 뜨지 않는다. 그래서 **'들르는 곳'을 눌러 지도
핀까지 가는 동작은 코드 경로로만 논증**했다 — `_dlSpotRow` 는 좌표를 0 으로 넘기는데
(`goMapFocus(0,0,4,id)`), `js/mapnav.js` 가 `(!lat || !lng) && placeId != null` 이면
PLACES 에서 좌표를 채운다. 이 폴백은 이 호출부 때문에 나중에 들어갔고 경위는
`docs/log/2026-08-26-dev-audit-a11y-optimization.md` §2 표에 있다.

나머지는 node vm 에 DOM 셰임을 만들어 10개 코스를 실제로 렌더해 셌다.

| 화면 | 실측 |
|---|---|
| 코스 상세 10개 | 전부 렌더 · `<img>` 합계 **62** (히어로 10 + 장소 썸네일 52) |
| 코스별 `<img>` | 1:8 · 2:9 · 3:2 · 4:6 · 5:1 · 6:4 · 7:3 · 8:1 · 9:5 · 10:23 |

## 8. 남은 것

- **`.dl-course-no` 가 고아다.** `css/50-datalab.css:168-172` 의 28px 배지 규칙인데,
  `436ed70` 이 `.dl-course-thumb` + `.dl-course-no-badge` 로 갈아치운 뒤
  `js/` · `index.html` 에서 `dl-course-no` 를 찾으면 `datalab.js:617` 의
  `dl-course-no-badge` 만 걸린다 — 이 클래스를 만드는 곳은 없다.
- **코스 색이 두 벌이다.** 상세는 JSON 의 `c.color` 를 쓰고, 목록과 미리보기는
  `DL_TOUR_COLORS[i % 6]` 를 쓴다. 코스 2 는 상세에서 `#B45309`, 목록에서 `#F97316`
  으로 다른 색이 된다.
- **코스 10 의 '들르는 곳 3곳' 이 실제와 다르다.** `_dlViewTour` 의 건수 라벨이
  `c.spots.length` 인데 코스 10 은 `regions` 에 22곳이 들어 있다. 목록은 3곳,
  상세는 22행이다.
- **코스 JSON 을 검사하는 도구가 없다.** §3 의 대조 스크립트는 저장소에 없고
  `tools/check_data.py` 도 이 파일을 보지 않는다. id↔이름 대조를 `check_data.py`
  에 넣으면 같은 실수를 다음에도 잡는다.
- 코스 5·8 은 `spots` 가 0곳이다. 채우려면 데이터가 먼저 필요하다.
- 렌더 시간·전송량은 **측정하지 않았다.** JSON 이 2.6KB → 12.4KB 로 늘었지만
  `_dlCache` 가 한 번만 받는다는 것만 확인했고 체감 영향은 재지 않았다.
