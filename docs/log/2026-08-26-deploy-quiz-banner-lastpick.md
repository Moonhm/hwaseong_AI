## 1. 퀴즈는 결과를 저장하지 않는다 — 태그만 저장한다

가장 먼저 확인한 것이다. `js/quiz.js` 는 이렇게 저장한다:

```js
localStorage.setItem('hwaseong_rec', JSON.stringify({ tags: _quizTags }))
```

**1위 관광지가 아니라 사용자가 고른 태그만 들어 있다.** 그래서 배너에 띄우려면
`_computeRec(tags)[0]` 으로 매번 다시 계산해야 한다.

새 저장 로직을 만들지 않고 재계산을 택했다. 그 편이 오히려 정확하다 —
`js/data.js` 에 관광지가 추가·수정되면 저장된 1위는 낡은 값이지만 재계산은 늘
지금 데이터 기준의 1위를 낸다.

## 2. 상자는 하나로 유지한다

사용자 원문의 "**이 네모 칸**"은 단수다. 카드를 하나 더 붙이는 게 아니라 지금
있는 그 상자를 늘리라는 말로 읽었다. 그래서 `.menu-rec-banner` 를 그대로 두고
배경을 2겹으로 만들었다.

```
background:
  linear-gradient(180deg, 흰 베일 …) center bottom / 100% 80px no-repeat,   ← 위 겹
  linear-gradient(135deg, #F97316, #EA580C);                                ← 원본 그대로
```

아래 겹은 기존 배너 배경을 글자 그대로 옮긴 것이라 **윗부분 색은 전혀 안 변한다.**

### 80px 은 임의의 수가 아니다

```
padding-bottom 14  +  행 높이 44  +  행 위 여백 22  =  80
```

- 베일이 0 인 지점(0%)  = '시작하기 →' 의 밑변
- 베일이 0.88 인 지점(28%) = 새 행의 윗변

즉 **페이드 램프 22px 전체가 두 텍스트 사이 빈 공간 안에서만 일어난다.**
셋 중 하나를 고치면 `background` 의 80px 도 같이 고쳐야 한다. CSS 에 경고를 달았다.

**%가 아니라 px 인 이유**: 배너 높이가 확장 유무로 달라져 %를 쓰면 페이드
시작점이 떠돌아 흰 글씨 '시작하기 →' 를 덮는다.

## 3. 3개 안을 만들어 판정단 3인이 비교했다

| 안 | 방식 | 평균 |
|---|---|---:|
| **1. 한 덩어리** | 배너 자체를 늘리고 배경 그라데이션을 아래로 옅게 | **83** |
| 2. 레이어드 | 배너 뒤에서 빠져나온 별도 카드 | 66 |
| 3. 재사용 | 기존 `.recent-card` 계열 최대 활용 | 61 |

심사 렌즈는 의도 충실도 / 견고성 / 코드·디자인 품질 셋이다.
1안이 "네모 칸을 연장"이라는 원문에 가장 문자 그대로 맞았다.

### 판정단이 1위 안에서 잡아낸 결함 4건 — 전부 반영했다

**① 손상된 localStorage 가 탭 전환을 통째로 죽인다 (치명)**

원안의 가드는 `if (!tags || !tags.length)` 였다. 문자열 `"바다"` 는 `length` 가 2라
**이 가드를 통과하고**, 그다음 `_computeRec` 안의 `userTags.reduce` 가 던진다.
직접 재현해 확인했다:

```
_computeRec("바다") → TypeError: userTags.reduce is not a function
```

이 함수는 `closeQuiz()` 안에서 불리고 `closeQuiz()` 는 `go()` 의 첫 줄이다.
**예외 하나가 `go()` 를 중단시켜 하단 내비 네 탭이 전부 먹통이 된다.**
`Array.isArray` 로 바꾸고 `_computeRec` 호출도 try/catch 로 감쌌다. 재검증했다:

```
tags="바다" / 42 / {} / null / [] / '["바다"]'  → 가드 전부 차단
정상 tags → 1위: 제부도 (score 3)
```

**② 썸네일이 두 갈래로 서로 다르게 나온다**

`photoThumb()` 이 만드는 `.ph-thumb` 는 `border-radius:10px` 에 배경이
`var(--bg)`(차가운 회색)이고 `.ph-thumb-fb` 는 `font-size:60%`(상속 기준 약 9px)다.
사진이 404 로 숨는 순간 **살구색 위에 회색 사각형과 좁쌀만 한 이모지**가 남는다.
사진이 아예 없을 때 쓰는 `.menu-rec-top-fb`(radius 11px, 따뜻한 흰색, 21px)와
어긋난다. `photoThumb(p, 44, fb, 'menu-rec-top-ph')` 로 클래스를 넘겨 덮었다.

**③ 이름 칸이 8자밖에 안 된다**

360px 화면에서 실제 이름 칸을 계산하면:
```
360 - 40(--px) - 32(배너 margin) - 40(배너 padding) + 16(음수 margin) = 264
264 - 16(padding) - 44(썸네일) - 11(gap) - 55('지도 ›' 알약) - 11(gap) ≈ 127px
```
14px/800 한글로 약 8자다. '서해랑 제부도해상케이블카'(13자)가 잘린다.
알약을 셰브론 SVG(16px)로 줄여 약 45px 을 회수했다. 앱의 다른 목록
(`.place-item`)도 오른쪽 끝이 셰브론이라 모양도 그쪽에 맞는다.

**④ `#rec-banner-top:empty` 규칙이 아무 일도 안 한다**

원안은 `:empty { display:none }` 과 "이 div 안에 공백을 넣지 말 것" 경고를 달았다.
그런데 `_off()` 가 `innerHTML=''` 을 하면 자식이 사라져 **높이가 자연히 0** 이고
`--top` 클래스도 함께 떼어져 padding·베일까지 사라진다. 규칙도 경고도 지웠다 —
없는 지뢰를 미래의 편집자에게 심는 셈이었다.

## 4. 클릭은 퀴즈가 아니라 지도로 보낸다

배너 전체에 `onclick="openQuiz()"` 가 걸려 있어 `event.stopPropagation()` 이 필수다.
지도로 보낸 근거 셋:

1. 바로 위 '시작하기 →' 가 이미 퀴즈 진입이다. 같은 상자에서 두 번 보낼 이유가 없다.
2. 이 앱에서 `[사진+이름+주소]` 한 줄은 어디서나 '누르면 지도'다(`.recent-card` 등).
3. 사용자가 원한 건 1등으로 나왔던 그곳으로 가는 지름길이다.

## 5. 퀴즈를 안 해 본 사람에게는 예전 배너 그대로

`_off()` 가 확장 구간을 비우고 `--top` 클래스를 뗀다. "아직 결과가 없어요" 같은
빈 상자를 두지 않았다 — 바로 위 두 줄이 이미 "5가지 질문이면…" + "시작하기 →"
라는 안내라, 같은 말을 두 번 하면서 배너만 80px 길어진다.

## 6. 하지 않은 것

- **실기기 확인을 못 했다.** 색 대비는 계산으로만 검증했다
  (`#7C2D12`/`#FBE1D3` = 7.5:1, `#9A3412`/`#FBE1D3` = 5.85:1 — 둘 다 AA 통과).
- `.menu-rec-banner:has(.menu-rec-top:active)` 로 확장 구간을 누를 때 배너 전체가
  줄어들지 않게 했는데, `:has()` 미지원 브라우저에서는 예전처럼 줄어든다.
  동작에는 영향이 없어 폴백을 따로 두지 않았다.
- 후속 커밋 `93a45e3` 에서 사용자 지시로 라벨 앞 🥇 를 뺐고, 배너 래퍼의 아래
  패딩을 0 → 16px 로 키워 서브탭 칩과 띄웠다.
