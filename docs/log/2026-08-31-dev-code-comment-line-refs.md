## 0. 미뤄 뒀던 이유와, 그게 틀렸던 점

08-30 에 문서와 `tools/` 를 정리하면서 코드 주석 74건은 이렇게 미뤘다.

> **72건은 주석에 앵커가 없어 기계가 판정을 못 한다.** 사람이 한 건씩 읽어서
> '원래 뭘 가리키려 했나' 를 복원해야 한다.

**절반만 맞았다.** 기계 판정이 안 되는 건 사실이지만, **앵커가 없다는 건 틀렸다.**
막상 74건을 한 줄씩 읽어 보니 **대부분은 주석 문장 자체가 이름을 이미 말하고 있었다.**

```
✗  setFilter 는 토글이라 켜져 있는 칩을 다시 누르면 해제된다(js/map.js:938-950).
                                                            ↑ 이름이 왼쪽에 이미 있다
✓  setFilter 는 토글이라 켜져 있는 칩을 다시 누르면 해제된다(js/map.js 의 setFilter).
```

기계가 못 한 것은 **판정**이지 **복원**이 아니었다. 사람이 읽으면 거의 다 자명했다.
「기계가 못 하니 사람이 오래 걸린다」로 넘긴 것이 과대평가였다.

## 1. 얼마나 틀려 있었나

74건 중 **맞는 것은 1건**이었다 (`css/40-quiz.css` 가 가리킨 `css/20-map.css` 의
`.place-slide`). 나머지는 전부 밀려 있었다. 대표적인 것들:

| 주석이 가리킨 곳 | 그 자리에 실제로 있던 것 | 원래 뜻 |
|---|---|---|
| `js/map.js:949` (setFilter) | `function activateParking()` | `setFilter` |
| `js/home.js:222` (검색 디바운스) | 다른 코드 | `_srTimer` (실제 422줄) |
| `js/home.js:316` (`_srResults`) | 다른 코드 | `doHomeSearch` (실제 910줄) |
| `index.html:58` (관광 탭 active) | 다른 마크업 | `.ttab[data-tab="tourism"]` (실제 123줄) |
| `js/home.js:588-591` ('living' 분기) | 검색 필터 코드 | `switchHomeTab()` (실제 1417줄) |
| `css/00-base.css:294` (.tourism-more-btn) | 다른 규칙 | `.tourism-more-btn` (실제 321줄) |
| `js/nav.js:24` (renderLivingPage) | 다른 코드 | go() 안 living 분기 (실제 136줄) |
| `css/20-map.css:274` (.place-item) | 다른 규칙 | `.place-item` (실제 359줄) |

**500줄 이상 밀린 것도 여럿 있다.** `js/home.js:222` 는 실제 422줄이고,
`js/home.js:588-591` 은 1417줄이다. 두 배 넘게 벌어졌다.

원인은 뻔하다 — 08-25 의 JS 분리(§20) 와 그 뒤 기능 추가가 파일을 계속 키웠다.
**주석은 코드와 같은 파일에 있는데도 같이 안 움직였다.**

## 2. 파일명 없는 맨 콜론이 더 나빴다

`(:114)` · `(:309)` · `:117` · `(:1026)` 처럼 **같은 파일 안을 가리키는 것**들이 있었다.

```
✗  toggleJebuList(:114)가 false 로 뒤집고 :117 이 이미 숨겨진 것을 또 숨겨
✓  toggleJebuList() 가 false 로 뒤집고, 이미 숨겨진 것을 또 숨겨
```

이쪽이 더 조용히 밀린다. **파일명이 없으니 「어느 파일인지」조차 검색이 안 되고**,
같은 파일이라 편집할 때마다 밀리는데 아무도 안 본다.
`(:1026)` 은 `levelToSlider = 15 - level` 을 가리킨다고 적혀 있었는데
그 자리엔 `setLcVisible(false)` 가 있었다.

## 3. 고친 방법 — 이름을 만들어 내지 않았다

원칙 하나만 지켰다. **주석이 이미 말하고 있는 이름을 쓴다.** 없으면 코드에서 찾아
쓰되, 없는 이름은 절대 지어내지 않는다.

| 가리키는 것 | 쓴 표기 |
|---|---|
| 함수 | `js/map.js 의 setFilter` |
| 전역 변수 | `js/parking.js 머리의 전역 선언` |
| CSS 규칙 | `css/20-map.css 의 .place-item` |
| DOM | `index.html 의 #map-chips` |
| 같은 파일 안 | `setupZoomSlider 의 levelToSlider()` (파일명 생략) |

### 그런데 여기서 내가 또 틀렸다

`js/map.js` 의 줌 슬라이더 주석을 **`initZoomSlider 의 zoom_changed 리스너`** 로
고쳤다. **그런 함수는 없다. `setupZoomSlider` 다.**

바꾼 식별자 전부를 `grep` 으로 실존 확인하는 단계에서 잡혔다.

```
!! 없음  initZoomSlider
```

**줄번호를 없는 식별자로 바꾸면 하나도 나아지지 않는다.** 오히려 나쁘다 —
줄번호는 밀렸어도 '어딘가는' 가리키지만, 없는 이름은 grep 이 0건을 낸다.
그래서 이 검증 단계가 작업의 일부다. 함수 32개 + CSS 셀렉터 10개를 전수 확인했다.

## 4. 검사를 코드까지 넓혔다

74건을 다 고쳐도 **내일 다시 들어올 수 있다.** 08-30 에 배운 것이 정확히 그거였다
(§27-H 가 규칙만 적어 두고 검사가 없어서 반나절 만에 5건 밀렸다).

`tools/check.sh` 의 `line_ref_guard()` 를 확대했다.

| | 전 | 후 |
|---|---|---|
| 대상 | `WORKFLOW.md` `README.md` `check.sh` | **+ `js/*.js` `css/*.css` `index.html`** |
| 매칭 | 백틱으로 감싼 `파일:줄` | 코드는 **주석 줄**에서 맨몸 `파일:줄` |
| 맨 콜론 | 안 봄 | **`(:114)` 류도 잡는다** |

코드에는 백틱 관습이 없으니 **주석 줄로 범위를 좁혀** 잡는다. 문자열·URL 오탐을
피하려고 주석 밖은 보지 않는다.

회귀 테스트 두 건으로 확인했다 — 주석에 `js/nav.js:999` 를 넣으니 FAIL 을 냈고,
`(:777)` 도 잡았다. 둘 다 되돌렸다.

**작업 중에 이 검사가 내가 놓친 1건(`(:1026)`)을 잡았다.** 74건을 손으로 세고
눈으로 훑었는데도 하나가 남아 있었다. 검사를 먼저 넓혔으면 더 빨랐을 것이다.
