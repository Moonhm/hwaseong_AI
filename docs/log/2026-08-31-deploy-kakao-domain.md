# 지도가 죽었다 — 터널 주소를 바꿀 때 고칠 곳은 셋이 아니라 넷이었다

- 날짜: 2026-08-31
- 담당: 배포 Claude
- 커밋: `4e3b18d`
- 발단: 사용자 지시 — *"야 카카오맵 api연결 다시 해봐."*

---

## 1. 재봤다 — 도메인 미등록이다

카카오 JS 앱 키는 **도메인 제한**이 걸려 있다(§12 표에 원래 적혀 있던 사실이다).
SDK 요청에 `Referer` 를 바꿔 가며 던져 봤다.

```
$ curl -s -H "Referer: <주소>/" \
    "https://dapi.kakao.com/v2/maps/sdk.js?appkey=<JS앱키>&libraries=services&autoload=false"
```

| Referer | 결과 |
|---|---|
| `news-appliances-tap-cab…` (**현재 주소**) | **401** `domain mismatched! caller=… check out registered web domains.` |
| `culture-reed-dee-rug…` (08-30 에 죽은 옛 주소) | **200** — 등록돼 있다 |
| `endless-cocktail-…` (08-31 오전 폐기) | 401 |
| `http://localhost:8080` | **401** |
| (Referer 없음) | 200 |

**등록된 것은 이미 사라진 옛 주소뿐이다.** 지금 서비스 중인 주소는 거부된다.

## 2. 화면에서는 이렇게 보인다 — 그리고 안내가 틀렸다

SDK 가 401 이면 스크립트가 안 실행되고 `kakao` 가 정의되지 않는다.
`js/map.js` `initMap()` 의 첫 가드가 걸린다.

```js
if (typeof kakao === 'undefined' || !kakao.maps) {
  showMapError('카카오맵을 불러오지 못했어요.<br>페이지를 새로고침 해주세요.');
```

**「새로고침 해주세요」는 이 경우에 절대 안 듣는다.** 도메인이 등록될 때까지
몇 번을 새로고침해도 같다. 사용자는 네트워크 탓이라 생각하고 계속 누른다.

> 이 문구를 고치는 것이 맞지만 `js/map.js` 는 §17 상 **개발 Claude 파일**이라
> 손대지 않았다. 제안만 남긴다 — `401` 을 구분해 *"이 주소가 카카오에 등록되지
> 않았습니다"* 로 갈라 주면 다음 사람이 8초를 헤매지 않는다.

## 3. 진짜 문제 — 네 번째 자리가 git 밖에 있었다

§12·§13 이 지금까지 **"터널을 다시 띄우면 세 곳을 갱신하라"** 고만 적어 두었다.

| # | 자리 | git |
|---|---|---|
| 1 | `README.md` 배지·본문 | ✅ |
| 2 | `WORKFLOW.md` §1 | ✅ |
| 3 | `tools/check.sh` `LIVE_URL` | ✅ |
| **4** | **Kakao Developers → 플랫폼 → Web → 사이트 도메인** | ❌ |

세 곳은 `grep` 으로 찾아지고 `check.sh --live` 가 지켜 준다. **네 번째는 저장소
바깥이라 어떤 검사도 못 본다.** 그래서 08-31 에 세 곳을 정확히 고치고도 지도만
조용히 죽었고, `check.sh --live` 는 **exit 0** 이었다 — 그 검사는 `index.html`
바이트만 대조하지 지도가 뜨는지는 안 본다.

**「검사가 통과했다」와 「기능이 산다」가 또 갈렸다.** 이 저장소가 여러 번 겪은 그 패턴이다
(`2026-08-26-deploy-full-audit.md` §5).

## 4. 고친 것 — 문서에 박았다

- **§12 「Kakao API」에 절을 신설**했다. 401 실측, 화면 증상, 등록 경로,
  **「고칠 곳은 셋이 아니라 넷」** 표.
- §12 재기동 절차의 "세 곳" 세 군데를 **카카오 콘솔을 포함하도록** 고쳤다.
- **§13 에 미해결 항목으로 올렸다** — Claude 가 못 고치는 건이라 사용자 조치가
  필요하다는 것을 명시했다.

## 5. 내가 못 하는 것 — 사용자 조치

**콘솔 로그인이 필요해 Claude 가 대신할 수 없다.**

```
Kakao Developers → 내 애플리케이션 → (해당 앱) → 앱 설정 → 플랫폼 → Web
  사이트 도메인에 추가:
    https://news-appliances-tap-cab.trycloudflare.com
    http://localhost:8080          ← 함께 넣어 두면 개발 중 확인도 된다
저장 → 브라우저에서 강력 새로고침
```

**우회로를 만들지 않았다.** 서버가 `Referer` 를 등록된 도메인으로 바꿔 SDK 를
프록시하면 화면상 지도는 뜬다. 그러나 그것은 **키 주인이 걸어 둔 접근 제한을
우회하는 것**이라 하지 않는다. 올바른 해결은 등록이고 1분이면 끝난다.

## 6. 곁가지 — 「SDK 가 이 컨테이너에서 안 뜬다」의 절반은 이것이었다

`docs/log/` 여러 건이 *"카카오 SDK 는 이 컨테이너에서 로드되지 않아 지도 동작은
코드 경로로만 논증했다"* 고 적어 왔다(`pin-selection-all` · `lc-marker-cluster` ·
`map-scope-and-photo-wiring` 등). 원인은 **브라우저가 안 뜨는 것**(`libnspr4.so`
없음)으로 이해돼 왔다.

이번 실측에서 **`http://localhost:8080` 도 401** 이라는 것이 나왔다. 즉 브라우저가
멀쩡히 떴어도 **SDK 요청 자체가 거부되고 있었다.** 두 원인이 겹쳐 있었고, 그중
하나는 **등록 한 번으로 사라진다.**

> ⚠ 다만 브라우저가 안 뜨는 문제는 그대로다. 등록해도 이 컨테이너에서 지도를
> 눈으로 보려면 chromium 이 먼저 떠야 한다. **둘 중 하나만 고쳐진다** —
> 과장하지 않으려고 적어 둔다. 어디서 쟀는지도 함께 적는다: **배포 컨테이너**
> (`48d2bd481700`)에서 `curl` 로 쟀다(§0 · §12).

## 7. 남은 것

  `--live` 축이 맞다. 지시받지 않아 만들지 않았다.
