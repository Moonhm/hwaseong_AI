## 3. 온도 막대를 하루가 아니라 주 전체로 정규화했다

`js/weather.js:96-100` — `lo = min(daily.temperature_2m_min[0..6])`,
`hi = max(daily.temperature_2m_max[0..6])`, `span = Math.max(1, hi - lo)`.

버린 방법은 **날마다 그날의 최저~최고로 100% 를 잡는 것**이다. 그러면 일교차 3도인 날과
15도인 날이 같은 길이로 그려져 막대가 정보를 못 준다. 주 전체를 자로 쓰면 막대의
**왼쪽 끝 위치**가 그날이 추운 날인지, **길이**가 일교차가 큰 날인지를 동시에 말한다.

`span` 은 `Math.max(1, …)` 로 0 나눗셈을 막고, 폭은 `Math.max(6, wide)` 로 최소 6% 를
준다 — 일교차가 없는 날에도 막대가 안 사라진다. 이 6 에는 주석이 없다.

## 4. 현재 시각 칸을 '지금' 으로 덮지 않았다

`js/weather.js:152-157`.

```js
var past = (i === 0 && hr + 3 <= nowH);
var cur  = (i === 0 && !past && hr <= nowH && nowH < hr + 3);
```

3시간 칸은 **다 지나야** `is-past` 다(`hr+3 <= nowH`). '지금' 이 걸린 칸은 `is-now` 지만
라벨은 `15시` 그대로 둔다. 이유는 커밋 메시지에 있다 — *"이 화면을 여는 목적 자체가
'몇 시에 몇 도' 를 보는 것"* 이라, 그 칸을 '지금' 으로 덮으면 **정작 필요한 정보 한 칸이
지워진다.** 강조는 `border` 대신 `box-shadow: inset 0 0 0 1px rgba(37,99,235,.25)`,
지난 칸은 `opacity: .38` — 커밋 메시지가 말한 `.38` 과 CSS 값이 일치한다.

**한계 하나는 코드에서 읽힌다.** `nowH` 는 `new Date().getHours()`, 즉 **기기 로컬 시각**인데
데이터는 `timezone=Asia%2FSeoul` 로 받는다. 기기가 KST 가 아니면 `is-now`/`is-past` 가
어긋난다. 화성시 앱이라 두었다.

## 5. 하루를 펼치면 3시간 간격 — 인덱스는 `i*24 + hr`

Open-Meteo 는 `daily` 7칸과 `hourly` 168칸을 **각각 한 배열로** 준다. 그래서 i번째 날의
hr시는 `hourly[i*24 + hr]` 이다(`js/weather.js:142,147`). 홈 바와 같은 엔드포인트지만
질의가 다르다 — 홈 바는 `forecast_days=2` 에 `current` 를 받고, 여기는 7일치를 `current`
없이 받으며 `precipitation_probability(_max)` 를 더 붙인다.

의존은 `_WMO`(`js/home.js:194`)와 `_hwLat`/`_hwLon`(`js/home.js:192`) 둘이다. 로드 순서상
`js/home.js`(`index.html:929`)가 `js/weather.js`(949)보다 앞이라 성립한다. 없을 때의 처리는
둘이 다르다 — `_hwLat` 이 없으면 컨테이너를 비우고 끝나고(`:66`), `_WMO` 가 없으면
`'🌡️,—'` 로 대신해 그대로 그린다(`:37,41`). 패널의 다른 칸을 같이 죽이지는 않는다.

되짚어 쓰는 오늘(2026-08-27) 같은 좌표로 실제 응답을 받아 **56칸(7일 × 8시각)을 전수
대조**했다. `daily.time` 7칸(08-27~09-02) · `hourly.time` 168칸 · **불일치 0** ·
`i=2,hr=15 → 2026-08-29T15:00 · 27°C`. `timezone=Asia/Seoul` 은 DST 가 없어 하루가 항상
24칸이라 이 산술이 성립한다 — 서머타임이 있는 지역이면 23·25칸짜리 날에 깨진다.

### ⚠ 그 김에 찾은 버그 — 정규화 기준과 표시값의 반올림이 어긋난다

같은 실응답으로 막대 좌표까지 계산해 봤다. 이번 주 `lo=21.1`, `hi=29.9`, `span=8.8`.

| i | 날짜 | 표시 | `left` | `width` |
|---:|---|---|---:|---:|
| 0 | 08-27 | 22° ~ 29° | 10.2% | 79.5% |
| **6** | **09-02** | **21° ~ 30°** | **-1.1%** | **102.3%** |

`lo`/`hi` 는 **반올림 전** 값(21.1, 29.9)인데 `tmin`/`tmax` 는 `Math.round` 를 거친 값
(21, 30)이다. 그래서 반올림이 `lo` 아래나 `hi` 위로 넘어가는 날은 `left` 가 음수, `width` 가
100% 초과가 된다 — 이번 주는 `i=6` 이 그랬다(21.1→21, 29.5→30).
**`.wk-bar` 의 `overflow: hidden` 이 잘라 주므로 화면은 안 깨진다** — 그래서 아무도
못 봤다. 어긋남 상한은 반올림 폭 0.5도, 이번 주 기준 약 5.7%p 다.
`lo`/`hi` 를 `Math.round` 한 뒤 `span` 을 잡으면 된다. **고치지 않았다** — 인계한다.

## 7. 내가 고친 것 — 화살표 제거 (`9cb0045`)

사용자 지시: *"날씨에서 주간예보 이거 안맞아 옆에 화살표가 안맞아. 그냥 이거 빼.
이거 없어도 클릭하면 나오는거니까."*

`.wk-caret`(`▾`/`▴`)은 줄 오른쪽 끝에서 온도 숫자와 세로 정렬이 어긋나 보였다. 줄 전체가
`<button class="wk-head">` 라 화살표가 없어도 눌린다 — 조작 수단이 아니라 장식이었다.
JS 한 줄과 CSS 한 규칙을 지우고 지운 자리에 이유를 주석으로 남겼다.

그때 "펼침 상태는 `aria-expanded` 와 `.is-open` 이 계속 알린다" 고 적었는데,
`css/` 전체를 grep 해 보니 **`.wk-day.is-open` 에 대응하는 CSS 규칙은 없다**
(`.is-open` 이 붙은 규칙은 `.tide-now`·`.td-tide` 둘뿐 — `css/50-datalab.css:259,263,393,396`).
`.is-open` 은 화면 단서가 아니라 DOM 상태 표시이자 테스트 훅이다. 화살표를 뺀 뒤
**눈에 보이는 펼침 단서는 펼쳐진 시간 격자뿐**이고, 접힌 줄만 보고 "이게 눌리는 줄" 임을
알 방법은 남지 않았다. 사용자 지시대로 뒀지만, 잃은 것이 없다고 쓰면 거짓이다.
