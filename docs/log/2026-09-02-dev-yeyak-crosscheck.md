## 0. 사용자 감이 또 맞았다 — 다만 원인은 예약시스템이 아니었다

전날 공식 축제표(`festival5.jsp`) 10건을 맞췄는데도 사용자가 여전히 "안 맞는 것 같다" 고 했다.
확인해 보니 **남은 어긋남이 실제로 있었고, 그건 예약시스템과 무관한 앱 내부 문제**였다.

## 1. 준 주소는 목록이 AJAX 로 채워지는 껍데기였다

`cultureAllList.do` 는 문화/체험 **전체** 탭이고, 축제·행사는 `/1071/3010/festivalList.do` 다.
그냥 받으면 `li` 344개가 전부 메뉴다. `fnSearch()` 가 `searchYn=Y` 를 붙여 GET 으로 다시
제출하는 구조라 그 파라미터를 줘야 목록이 나온다. 페이지당 10건 × 6쪽 = **51건**.

```
https://yeyak.hscity.go.kr/1071/3010/festivalList.do?searchYn=Y&currentPageNo=1..6
→ 「총 항목 수 : 51건」
```

## 2. CATALOG #31 도 틀렸다 — #28 에 이어 두 번째

> | 31 | 화성시 시티투어 예약현황 (yeyak.jsp) | … | **2026년 우리동네 축제·행사 51건.
> 기존 festival 항목과 전부 중복, 신규 없음. 별도 저장 불필요** |

세 조각으로 갈라 각각 판정했다.

| 주장 | 판정 |
|---|---|
| 출처 = 「시티투어 예약현황」 | ❌ 시티투어(#27)와 무관. 통합예약시스템 축제/행사 탭이다 |
| 「2026년」 51건 | ❌ 상세 `이용기간` 실측 — **2023년 21 · 2024년 8~10 · 2025년 14~16 · 2026년 3~4** |
| 「기존 festival 과 **전부 중복**」 | ❌ **정반대. 겹치는 것이 0건**이다 |
| 결론 「별도 저장 불필요」 | ✅ 맞다 — 다만 **이유가 정반대로 적혀 있었다** |

중복 판정은 서로 다른 **세 가지 방법**으로 확인했다 — 2-gram Jaccard(최고 0.29) ·
최장공통부분문자열(최댓값 5자인데 전부 「화성특례시」 접두어) · 특징어 32종 grep(전무).
가장 위험한 쌍(yeyak 「펫힐링 산책」@여울공원 ↔ 앱 id:127 「반려동물 행복나눔 축제」)도
직접 봤는데 2024년 동탄6동 주민자치 프로그램 대 2026-11-07 시 단위 축제로 다른 건이다.

**올바른 보류 사유는 「중복이라서」가 아니라 「51건 전부가 이미 지난 행사라서」다.**
가장 늦은 것이 `id:317` 「2026 병점 로컬 마켓」 `2026-08-10 ~ 08-31` 로 이틀 전 종료다.
게다가 20건은 2023년 여울애축제 체험부스를 20~40분 단위로 쪼갠 **예약 슬롯**이다.

원인도 찾았다 — `7e7e705` 가 원근거 txt 에 담긴 **1페이지 10건만 보고 51건 전체를 단정**했다.

> **#28 과 #31 이 연달아 틀렸고 원인이 같다(표본을 전수로 착각).** 같은 커밋이 넣은
> 다른 「거의 일치」·「충분하다」류 단정도 검증받지 않았을 가능성이 높다.

## 3. 진짜 어긋남은 앱 안에 있었다 — 「미확정」이 D-day 로 찍히고 있었다

공식 표가 「8. 22.(토)**(미확정)**」이라 적은 것을 `date:"2026-08-22"` 로 넣어 두었다.
`_parseFestDateMeta` 는 **문자열만** 보므로 ISO 면 무조건 `approx:false` 를 낸다.
그래서 출처가 "미정" 이라 한 일정에 앱이 **확정 배지와 D-day 를 붙이고 달력에 점을 찍었다.**

```
id 95   2026-09-19  desc "9. 19.(토)(미확정)"   → D-17  ← 살아 있는 결함
id 113  2026-10-25  desc "10. 25.(일) 미정"     → D-53  ← 살아 있는 결함
id 126  2026-11-07  desc "11. 7.(토) (미확정)"  → D-66  ← 살아 있는 결함
id 86   2026-08-22  desc "8. 22.(토)(미확정)"   → 이미 지나 무해
```

**사용자가 느낀 「약간 안 맞는다」의 실체가 이 셋이다.** 상세 화면에만 "(미확정)" 글자가
남아 있어 같은 화면 안에서 서로 다른 말을 하고 있었다.

### 고친 방법

`_parseFestDateMeta(str, approxHint)` 로 두 번째 인자를 받게 하고, 데이터에 `dateApprox:true`
를 두었다. 호출부 7곳이 전부 place 를 갖고 있어 그대로 넘긴다.

`date` 문자열에 `?` 를 붙이는 방법도 검토했다가 **버렸다** — `p.date` 를 직접 파싱하는 곳이
여럿이라 그쪽이 조용히 깨진다.

효과는 실제 코드를 vm 에 올려 확인했다.

| id | 고친 뒤 |
|---|---|
| 95 · 113 · 126 | `approx=true` → **D-day 사라짐 · 달력 점 제외**. 목록에는 '예정'으로 그대로 보인다 |
| 86 | `approx=true` 지만 8월이 지나 `ended` — **화면 출력은 변화 없음** |
| 84(확정 8/29) · 102(확정 범위) | `approx=false` 유지 — **회귀 없음** |

> ⚠ 처음에는 「id:86 이 제일 나쁘다, 고치면 살아난다」고 판단했다가 **반증 단계에서 뒤집혔다.**
> 두 가지 고침안을 실제 `festStatus` 에 넣어 돌려 보니 8월 자체가 지나서 어느 쪽이든
> `ended` 였다. 실행해 보지 않고 결과를 예언한 것이 오류였다.

## 4. 곁들여 — id:105 는 두 달 뒤 조용히 사라질 예정이었다

`date:"2026년 10월 중"` 인데 `desc` 는 `"10~ 11월 중"` 이다. `festStatus` 의 approx 분기가
**그 달 말일**을 기준으로 삼으므로 **2026-11-01 에 자동으로 `ended`** 가 되어 둘러보는 목록
세 곳에서 사라진다. 국가 소상공인의 날은 11월 5일이다. `"2026년 11월 중"` 으로 옮겼다.

## 6. 남은 것

- **지오코딩 가능 3건** — `id:103`(에코센터) · `106`(화성시민대학) · `107`(안석낚시터).
  장소명이 확실한데 폴백 좌표라 「지도에서 보기」가 화성시청으로 보낸다. §17 상 배포 Claude 몫.
  `id:128` 은 실제로 화성시청이라 폴백이 정답이고, `id:90` 은 「(예정)」이라 보류.
- **날짜 근거가 아예 없는 9건** — `85·89·90·105·107·108·109·110·133`. `desc` 에 요일조차 없다.
  1차 출처(`total.hscity.go.kr`)는 **404** 이고 `festival1~4.jsp` 는 본문이 비어 있어
  외부 재검증 경로가 없다. **추측으로 손대면 지금 깨끗한 데이터를 망친다 — 그대로 둔다.**
- **동·면 단위 마을축제**가 시 관광과 표에는 없다는 단서를 얻었다(동탄6동 「여울애축제」,
  팔탄면 「팔탄신명축제」). 다만 **2026년 개최 근거가 이 51건에는 없다.** 추적하려면
  `festivalList` 가 아니라 `cultureAllList`·`visitList` 쪽을 봐야 한다.
