## 1. 왜 하필 지금 검토했나

이날 하루에 UI·데이터 변경을 20건 넘게 했다. 사용자 지시가 빠르게 이어졌고
그때마다 커밋했다. **각각은 검사를 통과했지만 서로 맞물렸을 때를 아무도 안 봤다.**

실제로 그 틈에서 가장 심각한 결함이 나왔다(아래 §3-①). 단일 변경만 보는 검사로는
절대 못 잡는 종류였다.

## 2. 방법 — 6축으로 나눠 보고, 나온 지적을 다시 공격했다

한 명이 전부 보면 한 관점에 갇힌다. 축을 나눠 병렬로 보게 했다.

| 축 | 무엇을 보는가 |
|---|---|
| 회귀 | 오늘 변경이 기존 기능을 깨뜨렸나 |
| 영화관 데이터 | 이관의 무결성, 공식 CSV 전건 대조 |
| 사진 파이프라인 | 빌더·슬라이드·최적화 도구 |
| 퀴즈 배너 | 새로 넣은 기능의 예외 경로 |
| UI 일관성 | 사용자가 지시한 것이 그대로 됐나 |
| 문서·프로세스 | 로그 규칙 준수, 수치 정합, assets 커밋 여부 |

**핵심은 두 번째 단계다.** 감사가 낸 지적을 그대로 믿지 않고, 지적마다 별도
검증자를 붙여 **반증을 시도**하게 했다. "확신이 없으면 real=false" 를 기본값으로 뒀다.

결과: **41건 지적 → 26건 확정 / 15건 기각**. 기각률 37%다. 그대로 다 고쳤다면
멀쩡한 코드를 열다섯 군데 건드릴 뻔했다. 감사보다 반증에 더 높은 사고 예산을 준 것이
옳았다.

## 4. 도구가 데이터를 지울 뻔했다

`tools/optimize_images.py` — 어제 내가 만든 전처리 도구다. 셋 다 되돌릴 수 없는 사고다.

1. **같은 stem 의 `.png` 와 `.jpg` 가 한 폴더에 있으면**, `.png` 를 JPEG 로 저장하며
   기존 `.jpg` 를 덮어쓰고 원본 `.png` 는 `unlink` 한다. 서로 다른 사진 한 장이
   **영구 소실**된다. `--check` 도 알려주지 않았다. → 대상이 있으면 건너뛰고 알린다.
2. **EXIF 미보존** — Orientation 이 사라져 스마트폰 세로 사진이 눕는다. → `exif` 전달.
3. **`KEEP_PNG` 가 영문 토큰만 검사** — `assets/images/` 의 PNG 4장이 전부 한글 이름
   투명 로고였다. JPEG 로 바꾸면 배경이 검게 칠해진다. → 실제 투명도(RGBA/LA/투명
   팔레트)로도 판정.

`assets/` 는 이 서버에만 있는 유일본이다. 도구를 만들 때 **되돌릴 수 없는 작업이라는
전제**를 충분히 깔지 않았다.

## 5. 검사가 보는 것과 화면이 보는 것이 달랐다

이번 검토를 관통한 주제다. 같은 증상이 세 곳에서 나왔다.

| 곳 | 검사는 통과했는데 화면은 |
|---|---|
| 편의정보 사진 33장 | `check_data.py` 고아 판정은 `convenience.js` 를 보는데 `build_photo_index.py` 는 안 봐서, 인덱스에 없어 화면에 안 떴다 |
| `cinemas` FLOOR | FLOOR 에 있지만 실측을 안 채워 늘 통과 |
| 빌더 `covered` | `None` 이 섞여 편의정보 293곳이 '전부 커버됨' 으로 판정돼 **공백 263건이 리포트에서 통째로 사라졌다** |

**검사 통과 = 정상이 아니다.** 검사가 그 경로를 보고 있는지를 따로 확인해야 한다.
`check.sh` 스스로도 마지막 줄에 이렇게 적어 두었다 —
*"통과. (건너뛴 검사가 있으면 위를 읽어라 — 통과가 아니라 안 본 것이다)"*

## 6. 안 고친 것과 그 이유

### 되돌리면 안 되는 지적 하나 — 감사가 맥락을 몰랐다

`css/10-content.css` `.recent-name` 의 `word-break: break-all` 을 `keep-all` 로
되돌리라는 지적이 나왔다. 근거는 "코드베이스 30여 곳이 전부 `keep-all` 이고 그중
둘은 '한국어에 필수' 라는 주석까지 있다" 였다. 코드만 보면 맞는 말이다.

**그런데 원래 `keep-all` 이었고, 그것 때문에 "율암온천숯가마테마파크" 가 잘려서
사용자가 직접 고쳐 달라고 한 것이다.** 되돌리면 그 요구가 깨진다.

감사는 코드베이스 일관성만 보고 그 변경이 왜 생겼는지를 모른다. **자동 감사의 지적을
그대로 적용하면 사용자 요구를 코드 관례로 덮어쓰게 된다.** 이번 검토에서 가장
중요한 판단이었다.

### 사용자에게 넘긴 3건 — 전부 구조·설계 결정이다

| 건 | 왜 내가 정하지 않았나 |
|---|---|
| 영화관 핀 좌표 이원화 (`conv_map.js`) | 핀은 주소 지오코딩, 카메라는 `convenience.js` 좌표를 쓴다. 고치려면 `CONV_CAT_CFG` 전체에 영향 |
| `.menu-rec-banner` 이중 들여쓰기 (`90-misc.css`) | 사이드 드로어 시절 `margin:16px` 이 남아 좌우 36px. 사이드 메뉴 쪽 영향 확인 필요 |
| '관광지' 탭 테마칩 범위 (`tourism.js`) | 칩이 문화재·축제까지 낸다. 오늘 '인기'에서 칩을 걷어내며 드러났다. UX 판단 |

사용자가 개발 Claude에게 전달하겠다고 해서 정리해 넘겼다.
