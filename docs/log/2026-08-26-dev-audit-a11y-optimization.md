## 3. 접근성 — 여섯 건이 같은 뿌리였다

전부 **"마우스 쓰는 정상 시력 사용자만 쓸 수 있다"** 로 모인다.

### 확대를 앱 전체에서 막고 있었다

viewport 에 `maximum-scale=1.0, user-scalable=no`. 저시력 사용자가 글자를 키울
방법이 없다(WCAG 1.4.4).

⚠ 여기서 **회귀를 넣을 뻔했다.** 처음에 "iOS 자동 확대는 입력 글꼴 16px 로 막으면
되고, 우리는 이미 16px 이라 필요 없다" 고 주석까지 썼는데 **실제는 14px(지도 13.5px)**
이었다. 그대로 올렸으면 iOS 에서 검색창을 누를 때마다 화면이 확대됐을 것이다.
확인 후 입력 글꼴을 16px 로 올려 **둘을 맞바꿨다** — 자동 확대는 그대로 막고
사용자 확대만 되살렸다.

### `--text-muted` 가 흰 배경에서 2.54:1

AA 기준은 4.5:1 이다. 이 토큰 하나에 하단 내비 라벨·모든 부제·목록 메타가
묶여 있어서 앱의 '작고 흐린 글자' **전부**가 기준 미달이었다.
`#9CA3AF` → `#6B7280` (흰 배경 4.83:1 · 회배경 4.47:1).

### `onclick` 을 단 `<div>` 가 키보드로 닿지 않았다

정적 마크업만 48곳인데 `tabindex` 는 2개. 칩·메뉴 항목·카테고리 아이콘·목록 행이
전부 키보드 밖이었다.

**마크업 48곳을 고치지 않았다.** JS 가 `innerHTML` 로 그리는 항목이 더 많아서
정적 마크업만 고치면 절반이 남고, 새 목록을 만들 때마다 잊으면 그 자리만 조용히
닿지 않게 된다. `js/boot.js` 에 위임 한 벌을 뒀다 —
`_kbEnhance()` 가 `[onclick]:not([tabindex])` 에 `tabindex`·`role` 을 붙이고,
`document` keydown 하나가 Enter·Space 를 click 으로 넘긴다.

⚠ 처음엔 `.dim` 배경 오버레이까지 포커스 대상이 됐다. 그건 '바깥을 눌러 닫는'
자리라 버튼이 아니고 탭 순서에 빈 정거장만 만든다. 제외했다.

⚠ `<button>`·`<a>`·`<input>` 은 건드리지 않는다. 이미 포커스 대상이고
`role="button"` 을 덧씌우면 스크린리더가 링크를 버튼으로 잘못 읽는다.

### 주차 핀 글자가 배경에 묻혔다

핀 배경은 `hsl(0~118, 72%, 42%)` 빨강→초록 그라데이션인데 글자는 흰색 고정이라
노랑~연두에서 **2.1:1**. 명도를 30% 까지 낮춰 계산해도 노랑은 3.99:1 이라 못 넘고,
색으로 상태를 알리는 게 이 핀의 존재 이유라 그라데이션을 포기할 수도 없다.

→ **배경을 어둡게 하는 대신 글자를 뒤집었다.** 배경 상대휘도를 구해 흰 글씨가
4.5:1 을 못 넘으면 `#111827` 로 바꾼다. 전 구간 4.64~8.27:1 로 통과.

## 4. 최적화 — 25건 발굴, 2건만 살아남았다

5축(재렌더·리스너·DOM·CSS·초기화)으로 후보를 뽑고 **"실제로 할 가치가 있나"** 를
적대적으로 물었다. 23건이 기각됐다 — 측정 과장, 체감 불가, 금기 저촉,
위험이 이득보다 큼.

기각이 압도적인 게 정상이다. 이 저장소는 이미 뷰포트 컬링·좌표 버킷팅·지연 로드·
지오코딩 캐시가 들어가 있어서, 남은 것은 대부분 '이론상 빠른' 것들이었다.

### 채택 ① 관광 목록이 전량을 그렸다

`collapsible = theme === 'all' && ...` 이라 `*-only` 경로에는 더보기가 아예 안 붙었다.
게다가 `theme === 'all'` 은 지금 UI 에서 도달하지 않는다('인기' 서브탭은 목록 자체를
숨긴다) — **미리보기 기구 전체가 죽은 코드였다.**

실측 390×844: 관광지 151건 = DOM **2,523노드** · `<img loading=lazy>` 118개.
화면에 동시에 보이는 건 8개다. 서브탭·테마칩을 누를 때마다 전량 재생성됐다.

→ 2,523 → **328노드 (-87%)**.

`PREVIEW` 를 소식·생활과 같은 5 로 두지 않고 20 으로 잡았다.
저 목록들은 '확인' 용이고 이건 '둘러보기' 용이다. 5 면 첫 화면(8개 노출)에서
바로 잘려 탐색이 끊기고, 더보기를 누르면 어차피 2,523노드로 돌아가 순손해다.

### 채택 ② 죽어 있던 transition

`css/90-misc.css` 가 마지막에 로드되는데
`.lc-fchip, .chip-arrow, .lc-arr, .fsc-arr, … { transition: transform 0.12s }`
한 규칙이 같은 명시도로 앞 파일들을 통째로 덮고 있었다.

실측: `.chip-arrow`·`.fsc-arr` 의 computed transition 이 `transform 0.12s` 뿐 —
원래 있던 `opacity 0.18s` 가 사라져, `.visible` 토글로 나타나고 사라지는 화살표가
페이드 없이 깜빡였다. **성능이 아니라 동작이 죽은 건**이라 채택했다.

⚠ `.lc-fchip` 은 병합 목록에서 뺐다. `css/20-map.css` 의 `all 0.15s` 가 transform 까지
이미 덮으므로, 여기 넣으면 그 `all` 이 죽어 `.active` 색 전환이 사라진다.
⚠ `css/90-misc.css` 한 파일만 고쳤다. 앞 파일을 되돌리면 파일 소유권 규약
(두 Claude 가 다른 파일을 만진다)이 깨진다.

## 8. 이 세션에서 두 번 반복된 실수

**"고쳤다" 고 말하기 전에 그 주장을 검증했는가.**

- `check.sh` 를 grep 으로만 봐서 실패를 며칠 놓쳤다.
- viewport 를 고치면서 "입력이 이미 16px" 이라고 **확인 없이 주석에 썼다.**
  실제는 14px 이었고, 그대로 갔으면 iOS 회귀였다.
- `LC_ICON_HTML` 을 `js/ui.js` 에 뒀다가 `js/home.js` 가 통째로 죽었다.
  `<script>` 순서가 home(4번째) → ui(8번째) 라 로드 시점 평가에서 ReferenceError.
  **브라우저를 안 열었으면 못 찾았다.**

셋 다 코드를 고친 직후 브라우저·종료코드로 확인해서 잡았다.
정적으로 읽는 것만으로는 셋 다 놓쳤을 것이다.
