### 지켜야 할 규칙 3가지

1. **`<link>` 나열 순서를 바꾸지 마십시오.** 번호순 = 캐스케이드 순서입니다. 순서가 어긋나면 스타일이 조용히 뒤집힙니다.
2. **새 규칙은 「가장 가까운 번호대 파일」에 넣습니다.** 그래야 개발 Claude가 30번대를, 배포 Claude가 20번대를 만져도 git 충돌이 구조적으로 안 납니다.
3. **`90-misc` 앞의 50~80 은 비워 뒀습니다.** 새 화면이 생기면 그 사이에 넣으십시오. 기존 파일을 쪼개지 마십시오.

`:root` 변수는 `00-base.css` 에 있고 나머지 5개가 전부 그것을 전제로 합니다. **`00-base.css` 만은 반드시 첫 번째여야 합니다.**

### 왜 CSS 분리가 JS 분리보다 안전한가

CSS 는 스코프·호이스팅 같은 의미론이 없고 **캐스케이드가 순수하게 텍스트 순서**입니다. 따라서 「이어붙인 결과가 원본과 바이트 단위로 같고 `<link>` 순서가 같다」면 렌더링이 동일함이 **증명**됩니다. JS 는 실행 순서·전역 스코프 때문에 그만큼 단정할 수 없었습니다.

### 또 검사 도구 결함이 드러났다 — 이번엔 더 위험한 종류

`tools/check_markup.py` 의 `<style>` 중괄호 검사가 **`<style>` 블록만 보고 있었습니다.** CSS 를 밖으로 빼자 그 `for` 문이 한 번도 안 돌고 **아무 말 없이 통과**했습니다.

이건 오탐(false positive)이 아니라 **미탐(false negative)** 이라 훨씬 위험합니다. 오탐은 시끄러워서 눈에 띄지만, 미탐은 **검사가 죽은 줄도 모르고 초록불이 뜹니다.** §19 에 적어 둔 설계 원칙 「건너뛸 때는 반드시 SKIP 을 찍는다」를 검사기 스스로 어긴 셈입니다.

고친 내용:
- `index.html` 의 `<style>`(남아 있다면)과 `css/*.css` 를 **함께** 본다
- **볼 대상이 하나도 없으면 그 자체를 실패**로 만든다 — 다음에 스타일 위치가 또 바뀌면 조용히 통과하지 않고 소리를 낸다
- `<link>` 가 부르는 css 가 실제로 있는지, 디스크의 css 를 index.html 이 부르는지 양방향 대조를 추가

세 경우(중괄호 파손 / 고아 파일 / 없는 파일 참조)를 주입해 전부 잡히는 것을 확인했습니다.

> **교훈** — 구조를 바꾸면 검사 도구가 옛 구조를 가정하고 있는지 반드시 확인해야 합니다. §20 에서 2건, §21 에서 1건이 나왔습니다. **검사가 통과했다는 것과 검사가 일을 했다는 것은 다릅니다.**
