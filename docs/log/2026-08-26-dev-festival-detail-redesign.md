## 2. 비어 보인 것은 디자인이 아니라 데이터였다

먼저 축제 50건을 전수로 세어 봤다.

| 항목 | 실측 |
|---|---|
| 축제 건수 | 50 |
| 설명문(`desc`) | `2026년 8월 \| 8. 29.(토)` 꼴. **33건은 `date` 를 그대로 되풀이할 뿐**이다 |
| 나머지 `desc` 17건 | 끝 날짜 `~` 12 · `(미확정)` 꼬리표 4 · 한 줄 소개 1(id 276). id 277 은 둘 다 |
| 태그 | 50건 중 **49건**이 `["축제","행사"]` 로 동일 |
| 날짜 확정(`YYYY-MM-DD`) | 39 |
| 날짜 근사(`2026년 10월 중` 등) | 10 |
| 날짜 `미정` | 1 |
| `date` 필드의 기간(`~` 범위) | **0** — 기간은 `desc` 문자열에만 있다 |

⚠ 커밋 `3e8f429` 메시지에는 "설명문이 없고 기간도 없다" 고 적었는데 정확하지 않다.
`desc` 가 `date` 보다 더 말하는 것이 17건 있다. 다만 그 17건은 이미 화면에 나온다 —
히어로가 `descParts[1]`(`|` 뒤 전체)을 그대로 찍기 때문이다. 그래서 이 개편의 전제
자체는 바뀌지 않는다. 새로 채울 재료가 없다는 것은 나머지 33건에서 맞다.

없는 정보를 지어내지 않기로 하고 세 갈래로 갔다 —
(1) 중복을 걷어내고 (2) 가진 날짜에서 계산할 수 있는 것을 꺼내고
(3) 그 달의 다른 행사로 아래를 채운다.

걷어낸 중복은 둘이다. 히어로가 `📅 8. 29.(토)` 를, 정보 카드가 `일정: 2026-08-29` 를
따로 말했다 — 카드 쪽을 없앴다. 카드의 '화성시 문화생활 예약 →' 와 하단 '🎪 예약하기' 가
같은 URL 이었다 — CTA 하나로 모았다.

**버린 방법 둘.** 여백·글자를 키워 눌러 채우는 것은 안 했다. 얇은 내용에 큰 여백을 주면
더 비어 보인다. `desc` 를 그럴듯하게 지어 넣는 것도 안 했다 — 이 데이터는 화성시 공식
예약 시스템(`yeyak.hscity.go.kr`, README 출처표 기준)과 공식 축제 일정 페이지
(`festival5.jsp`, data/CATALOG.md 28번 행)에서 온 것이라 지어낸 문장이 공식 정보처럼
읽힌다.

## 3. 빈 띠의 범인은 `position: sticky` 였다

`.fd-cta` 가 `position:sticky; bottom:0` 이었다. 본문이 짧을 때 sticky 는 버튼을
화면 아래에 붙여 두고 그 위를 통째로 빈 띠로 남긴다. 래퍼를 걷어내고 버튼을
`.fd-body` 흐름 안으로 넣었다(`.fd-cta-btn { width:100% }`).
커밋에 기록된 실측은 '약 150px' 이고, 개편 뒤 페이지 스크롤 높이 804 = 상세 높이 804 다.
이번 정리에서 다시 재지는 않았다.

## 4. D-day — 근사 일정에는 붙이지 않는다

js/tourism.js:437-447 이다.

| `place.date` | D-day |
|---|---|
| `2026-08-29` (확정) | `D-3` · `오늘` · `내일` · `어제` · `4일 지남` |
| `2026년 10월 중` (근사) | **안 붙인다** |
| `미정` | **안 붙인다** |

근사 일정은 `_parseFestDateMeta` 가 그 달 1일로 채우고 `approx:true` 를 같이 준다.
그 값에 D-day 를 찍으면 **없는 확정 일정이 화면에 생긴다** — 실제로 'D-36' 이 찍힌 적이
있다(2026-08-26 감사). `if (_dm && !_dm.approx)` 로 막았다.

7일 안이면 `.soon` 을 붙여 강조한다. 끝난 행사는 'D+4' 가 아니라 '4일 지남' 으로
방향을 뒤집어 말한다. 같은 이유로 `_ended` 일 때 CTA 문구를 '🎪 예약 · 상세 정보' 에서
'🗓️ 다른 행사 보기' 로 바꾼다 — 끝난 행사에 '예약하기' 는 말이 안 된다.

날짜가 `미정` 인 1건은 `_dm` 이 null 이라 D-day 도 'N월의 다른 행사' 블록도 안 붙는다.
의도한 결과다 — 달을 모르는데 '그 달의 다른 행사' 를 고를 수 없다.

## 5. 히어로 사진 — 자르지도, 가리지도 않는다

원인 셋이 전부 사용자 말 그대로였다. `.fd-hero` 가 `height:210px` 고정,
`object-fit:cover` 로 비율이 다른 사진이 통째로 잘림, 그 위에 제목·날짜를 얹고
검은 그라데이션(0.08→0.60)까지 덮음.

### 5-1. 종횡비를 0.8~1.78 로 가둔다

`_fdFitHero()`(js/tourism.js:383-389)가 `onload` 에서 원본 비율을 읽어 상자에 넣는다.

```js
r = Math.max(0.8, Math.min(1.78, r));   /* 4:5 ~ 16:9 */
box.style.aspectRatio = r.toFixed(3);
```

| 안 | 왜 버렸나 |
|---|---|
| 고정 16:9 + cover | 축제 사진은 대부분 세로 포스터다. 잘리면 포스터 글씨가 날아간다 |
| 원본 비율 그대로 | 긴 세로 포스터가 화면을 통째로 먹는다 |
| **원본 비율을 읽되 4:5~16:9 로 클램프** | 채택 |

데이터에 가로·세로가 없어 CSS 만으로는 비율을 알 수 없다. 그래서 `aspect-ratio: 3/2` 를
기본값으로 두고 사진이 로드된 뒤 JS 가 덮어쓴다.

### 5-2. ⚠ `aspect-ratio` + `max-height` 는 높이가 아니라 **폭**을 줄인다

이번 작업에서 제일 크게 밟은 것이다. `.fd-hero--photo` 에 `max-height: 52vh` 를 걸었더니
세로 포스터에서 상자가 **390px → 351px** 로 좁아지고 오른쪽에 **39px** 흰 틈이 생겼다.

인라인 크기가 auto 인 상자는 `max-height` 가 비율을 타고 `max-width` 로 옮겨 간다.
390×844 기준으로 산술이 그대로 맞는다.

```
52vh = 438.88px        높이 상한
438.88 × 0.8 = 351.1   비율 하한 0.8 을 타고 넘어온 폭 상한
390 − 351   = 39       오른쪽 흰 틈
```

`.fd-hero--photo` 에 `width: 100%` 를 명시해 인라인 크기를 확정값으로 만들면 이 전이가
일어나지 않는다. 높이만 잘리고 폭은 그대로다. 지금 CSS 에 그대로 살아 있다
(css/10-content.css:560-572 — `width:100%` · `height:auto` · `aspect-ratio:3/2` · `max-height:52vh`).

> **다음 사람에게** — `width:100%` 가 군더더기로 보여도 지우지 마라.
> 지우는 순간 세로 포스터가 다시 오른쪽으로 39px 비뚤어진다.
> 같은 경고를 CSS 주석에도 남겨 뒀다.

### 5-3. 남는 여백은 검은 띠가 아니라 사진 자신이 받는다

`object-fit: contain` 은 레터박스를 반드시 만든다. 비율을 클램프해도 원본이 클램프 밖이면
여백이 남는다. 그 자리를 같은 사진의 흐린 판(`.fd-hero-blur`, css/10-content.css:580-585)이
받는다. 빈 검정 띠를 안 남기려는 것이다.

```css
.fd-hero-blur { position:absolute; inset:-30px;
  background-size:cover; background-position:center;
  filter: blur(24px) saturate(1.25) brightness(0.62); transform: scale(1.08); }
```

`inset` 이 음수 30px 인 이유는 blur 가 가장자리에서 바깥 픽셀을 못 읽어 테두리가
옅어지기 때문이다. 상자보다 크게 깔고 넘치는 부분을 잘라낸다. `<img>` 와 같은 URL 이라
이미지를 두 번 받지 않는다.

제목·날짜·배지는 사진 위에서 아래 흰 바탕(`.fd-titlebar`)으로 내렸다. 글씨가 사진 위에
없으니 검은 그라데이션을 씌울 이유도 사라져 `.fd-hero--photo::after { display:none }` 으로
껐다. 흰 바탕에서는 히어로용 D-day 색(반투명 흰색)이 안 보이므로 `.fd-titlebar` 안에서만
`#FFEDD5/#C2410C` 로 바꿨다 — 다시 계산해 4.52:1 이다. `.soon` 은 반전해 `#C2410C/#fff`,
5.18:1.

사진이 없는 경로는 예전 그대로 둔다(그라데이션 + 글씨 얹기). 축제 50건은 **전부** 사진이
있어(PHOTO_INDEX 로 확인, 50/50) 실제로는 안 타지만 다른 분류가 이 화면을 쓰면 필요하다.
사진이 404 면 `onerror` 가 `no-img` 를 붙여 상자를 접는다 — 안 접으면 흐린 배경만 남아
뿌연 판이 그냥 서 있게 된다.

## 6. 주소 복사 — "없앴다" 가 아니라 "여긴 원래 없었다"

사용자가 "왜 없앴냐" 고 물었으므로 먼저 사실부터 확인했다. `git log -S"fd-info-val"` 로
이 줄을 건드린 커밋을 전부 열었다 — `6590e46`(초기), `6a75c71`(인라인 JS 분리),
`1ffdf15`(CSS 분리), `3e8f429`(이번 개편). **`copyAddress` 와 묶인 적이 한 번도 없다.**
내가 개편하면서 뺀 것이 아니다.

기존 복사는 지도 슬라이드 카드 네 곳에 있고 지금도 정상이다 — js/map.js:582 ·
js/parking.js:433 · js/localcurrency.js:381 · js/conv_map.js:515.
즉 '지도에서는 되는데 축제 상세에서는 안 되는' 상태였고, 그래서 없어진 것처럼 보였다.
요청대로 여기에도 붙였다.

- 새 함수를 만들지 않고 `copyAddress`(js/ui.js:147)를 그대로 쓴다.
- **인라인 `onclick` 에 주소 문자열을 직접 박지 않는다.** 슬라이드 카드 네 곳이 이미 쓰는
  방식대로 `data-addr` 에 담고 `copyAddress(this.dataset.addr)` 로 꺼낸다.
  `onclick="copyAddress('...')"` 로 박으면 주소 안의 작은따옴표가 JS 문자열을,
  큰따옴표가 HTML 속성을 끊는다. 지금 PLACES 주소 243건 중 따옴표가 든 것은 0건이라
  실제로 터진 적은 없다 — 방어다.
- 화면에는 '경기도 화성시' 를 뗀 짧은 주소를 보여 주지만 **복사되는 값은 전체 주소**다.
  붙여넣어 검색할 때 시 이름이 없으면 안 걸린다.
- `복사` 라벨을 붙였다. `.sl-addr` 은 핀 아이콘으로 '누르는 곳' 임을 알렸는데 여기는 정보
  카드 안이라 그냥 텍스트로 읽힌다 — 누를 수 있다고 말해 줘야 한다.
- `role="button" tabindex="0"` 을 마크업에 직접 달았다. js/boot.js 의 `_kbEnhance` 가
  `[onclick]` 에 자동으로 달아 주지만 MutationObserver 디바운스를 거친다.
  상세는 열자마자 키보드로 닿아야 한다.

⚠ 한계: 축제 50건 중 **16건은 주소가 `경기도 화성시 미정`** 이다. 화면에도 '미정' 이 뜨고
복사도 '경기도 화성시 미정' 이 된다. 데이터 쪽 문제라 화면에서 손대지 않았다.

## 7. 되짚은 것 — 내가 넣은 '지도에서 위치 보기' 가 무동작이었다

`3e8f429` 에서 새로 넣은 버튼인데 눌러도 탭이 `page-map` 이 아니라 `page-tourism` 그대로
였다. 다음 실측에서 잡았다(`139ba82`).

원인은 `goMapFocus(place.lat, place.lng, 4, place.id)` 의 **네 번째 인자**다.
js/mapnav.js:114 의 `goMapFocus` 는 `placeId` 가 축제면 '지도에 핀이 없다' 며
`openFestView('detail', placeId)` 로 되돌린다. **축제 상세 안에서 부르면 자기 자신을 다시
그리는 것**이라 화면이 안 바뀐다.

그 가드 자체는 옳다. 즐겨찾기·홈·데이터랩·퀴즈·관광 목록에서 축제를 누르면 상세로 가야
한다(그 호출부 11곳은 손대지 않았다). 문제는 '이미 상세인 곳' 에서 부른 내 호출이었다.

수정은 `placeId` 를 넘기지 않는 것이다. `goMapFocus(lat, lng, 4)` 는 가드를 건너뛰고
카메라만 옮긴다. **왜 인자를 뺐는지 주석으로 남겼다** — 없으면 다음 사람이 '빠뜨린 인자' 로
보고 다시 넣는다.

⚠ 남은 한계: 축제 50건 중 **21건이 `(37.199, 126.831)` 한 점에 몰려 있다.** 그 좌표는
js/map.js:22 의 `HWASEONG`, 즉 지도 초기 중심값(폴백)이다. 이 21건에서 '지도에서 위치
보기' 를 누르면 화성시 한복판으로 갈 뿐 그 행사 자리가 아니다. 좌표가 채워지기 전에는
화면 쪽에서 고칠 수 없다.
