## 2. 죽은 조건을 찾았다 — `세계문화유산`

`js/tourism.js` 의 `THEME_TAGS.history` 는 `['역사','세계문화유산']` 을 찾는데
**그 태그를 가진 항목이 데이터에 0건이었다.** 조건이 아무것도 안 거른다.

`세계문화유산` 문자열이 프로젝트에 나오는 곳은 그 한 줄뿐이었다 —
누군가 붙일 생각으로 조건만 넣고 데이터에 반영하지 않은 것으로 보인다.

화성시의 유네스코 세계문화유산은 **융릉·건릉 한 곳뿐**이다. 2009년 등재된
조선왕릉 40기에 포함된다(융릉=사도세자, 건릉=정조). `id:24` 에만 붙이고
그 사실을 데이터 주석으로 남겼다 — 다른 곳에 붙이면 안 된다.

결과: history 테마 매칭 20 → **21건**.

### 상세 강조 — '약간' 을 지켰다

사용자가 "약간 강조" 라고 했으므로 크기·모양은 그대로 두고 색과 굵기만 올렸다.
배지처럼 키우면 태그 줄의 리듬이 깨지고 그 아래 액션 버튼과 시각적으로 경쟁한다.
대비 `#92400E / #FEF3C7` = 7.6:1 (WCAG AA 통과).

**⚠ 이 태그에는 `tagStyle` 인라인을 붙이지 않는다.** 붙이면 뒤에 오는 인라인
`style` 이 클래스 규칙을 이겨 강조가 통째로 사라진다. 검증에서 누출 없음을 확인했다.

## 3. 죽은 링크 — 마크업이 아니라 주소가 문제였다

사용자 지적: 투어 탭의 `🚌 화성시 공식 시티투어 예약·안내` 버튼은 잘 열리는데
코스 상세 안의 `예약·문의는 …에서 확인하세요` 는 안 된다.

**양쪽 다 `<a href target="_blank" rel="noopener">` 로 똑같이 생겼다.**
가리키는 주소가 달랐다.

```
index.html:380   https://tour.hscity.go.kr/citytour/index.jsp   → 200
JSON 의 source   https://www.hscitytour.com                     → 연결 실패(000)
```

후자는 죽은 도메인이다. `js/datalab.js` 의 코스 상세(:497)와 코스 전체 보기(:630)가
둘 다 `d.source` 를 쓰므로 **두 곳이 함께 먹통**이었다 — 사용자는 상세만 언급했지만
전체 보기도 같은 상태였다.

고친 곳은 코드가 아니라 데이터다. **두 벌을 함께 고쳤다** —
`js/citytour_courses_hwaseong.json`(앱이 읽는 사본)과
`data/processed/citytour_courses_hwaseong.json`(원본).
원본을 안 고치면 다음 갱신 때 죽은 URL 이 되살아난다.

> 교훈: '링크가 안 된다' 는 신고를 받으면 마크업보다 **주소를 먼저 찍어 본다.**
> 같은 화면 안에 잘 되는 링크가 있다면 그 둘의 URL 을 대조하는 것이 가장 빠르다.

## 4. ⚠ 같은 사고를 두 번 냈다 — `?v=` 누락

이 날의 가장 부끄러운 기록이다.

`c05d6e9` 가 `js/map.js`·`css/20-map.css` 를 고치고도 `index.html` 을 안 고친 채
나갔다. 서버에 immutable 캐시가 켜져 있으므로(`02aebda`) 같은 `?v=` 에 다른 내용이
나가면 그 URL 을 이미 받은 브라우저는 **1년간 새 파일을 못 본다.**
Firefox·Safari 는 강제 새로고침으로도 `immutable` 을 무시하지 못한다.

**오늘 아침 `f7d7e84` 에서 똑같은 사고를 내고 개발 Claude 가 잡아 준 바로 그
유형이다.** 그때 원인은 존재하지 않는 값으로 `sed` 를 돌린 것이었고,
그래서 `tools/bump_version.py` 를 만들어 근본 원인을 없앴다고 적었다.

그런데 이번에는 **다른 경로로 같은 결과**가 났다.

```
리베이스 중 index.html 이 ?v= 숫자만으로 충돌
  → git checkout --ours index.html 로 리모트 것을 통째로 채택
  → 그때 내가 bump_version.py 로 올려 둔 ?v= 갱신도 함께 되돌아갔다
```

리모트 값(135)은 개발 Claude 의 앞선 커밋이 올린 것이라 **내 js/css 변경분은
반영돼 있지 않다.** 도구를 만들어 놓고도 그 뒤에 도구의 결과를 지워 버린 셈이다.

개발 Claude 가 만든 `version-guard`(커밋 이력을 보는 검사)가 즉시 잡았다 —
`check.sh` 종료 코드 1. `a6c277e` 로 복구했다.

### 새로 지킬 것 둘

1. **`?v=` 충돌을 `--ours`/`--theirs` 로 넘기지 않는다.** 어느 쪽을 고르든
   '내 변경이 반영된 버전' 이 아니다. 충돌을 해결한 뒤 반드시 `bump_version.py` 를
   다시 돌려 새 값으로 올린다.
2. **`push` 를 `check.sh` 와 같은 명령줄에 붙이지 않는다.** 이번엔 `&&` 로 묶어
   놓아 실패를 눈으로 보고도 이미 나간 뒤였다. 종료 코드를 확인하고 나서 민다.

## 5. 내 검사기가 틀렸던 일

태그를 검증하면서 정규식으로 `js/data.js` 를 파싱했는데 **"태그 0건"** 이라는
거짓 결과가 나왔다. 데이터가 아니라 검사기가 틀린 것이었다.

```python
r'\{\s*id:(\d+),\s*name:"…"(.*?)\}(?=,?\s*(?:\{|\]))'
```

내가 방금 `id:24` **앞에 넣은 주석** 때문에 앞 항목(`id:23`)의 lookahead 가
실패하고, `.*?` 가 주석을 건너뛰어 `id:24` 까지 통째로 삼켰다. 그래서 `id:24` 가
독립 항목으로 잡히지 않았다.

실제 JS 파서(`node` + `vm`)로 다시 재서 바로잡았다 — 1건, 오적용 0건.

> **`js/data.js` 를 정규식으로 파싱할 때는 항목 사이 주석을 반드시 고려할 것.**
> 더 나은 방법은 `vm` 으로 실제 로드해서 `PLACES` 를 읽는 것이다.
> 그게 '앱이 보는 것' 과 같다.
