# 행정구역(4개 구)별 지도 보기 · 검색

- 날짜: 2026-08-26
- 담당: 개발 Claude (hm8824@naver.com)
- 발단: 사용자 요청 — "동네별로 그니까 행정동으로 나눠서 지도를 보게 하는 기능도
  만들수있어? 검색 할때도 사용하고말이야"

---

## 1. '행정동' 이 아니라 '구' 로 간 이유 — 데이터가 없다

읍면동으로 나누려면 데이터에 읍면동이 있어야 한다. 전수로 세어 봤다.

| | 읍면동 인식 | 구 인식 |
|---|---:|---:|
| 주차장 131 | **3건 (2%)** | 73% |
| 음식점 3,754 | 1,439 (38%) | **100%** |
| 지역화폐 27,374 | 39% | **98%** |
| PLACES 251 | 141 (56%) | 67% |

주차장 주소는 대부분 도로명이라 읍면동이 **131건 중 3건**밖에 안 나온다.
읍면동으로 나누면 절반 이상이 '미분류'로 빠진다.

화성시가 2026년 4개 구(동탄·병점·만세·효행)로 개편돼 새 주소에는 구가 들어 있다.
그래서 구 단위는 데이터가 받쳐 준다.

## 2. 지도는 '분류' 가 아니라 '화면' 으로 거른다 (사용자 제안)

처음엔 항목마다 구를 붙여 필터링하려 했다. 사용자가 더 나은 방법을 제안했다 —
*"지도에서 행정동만을 띄우게 하고 전체 데이터를 띄운 다음에 거기서 지도 밖에 있는 건
안 띄우는 식, 이렇게 하면 핀은 그대로 살리고 보이고 싶은 것만 보이고"*

**이게 더 낫고, 실은 앱이 이미 그렇게 돌고 있다.** 지역화폐 27,374건과 음식점
3,754건이 이미 뷰포트 컬링(`showViewportMarkers` / `showRsViewportMarkers`)으로
화면 밖을 안 그린다. 구 칩은 **카메라만 옮기면** 된다.

| | 속성으로 거르기 | 화면으로 거르기 |
|---|---|---|
| 경계 근처 애매한 곳 | 좌표 분류 정확도 84% 가 한계 | 화면에 있으면 보임 — **정확도 개념이 없다** |
| 새 코드 | 분류 + 필터 로직 | `setBounds` 한 줄 |
| 이미 있음 | ❌ | ✅ |

### 폴리곤(경계선)은 그리지 않는다

`data/` 의 '공간정보' CSV 10개를 전부 열어 확인했다. **경계 좌표를 담은 파일이
하나도 없다** — `BML_ADMB` 는 이름과 달리 29행짜리 코드표다(`화성시 = EAO014`).
구하려면 국가공간정보포털에서 SHP/GeoJSON 을 따로 받아야 하고 보통 수 MB다.
경계선은 보기 좋은 것이지 기능이 아니다 — 구를 고르면 그 화면이 되므로
사용자는 이미 '이 동네를 보고 있다'는 걸 안다.

## 3. 검색은 라벨이 필요하다 — 방법이 데이터마다 갈린다

bbox 로만 거르면 **22% 가 두 구에 동시에 걸린다**(만세구가 효행구를 감싸는 모양).
그래서 검색용으로는 항목마다 구 라벨을 붙인다.

| 데이터 | 방법 | 비용 |
|---|---|---|
| 음식점 3,754 · 지역화폐 27,374 | 주소 파싱 (100% / 98%) | **0** |
| PLACES(축제 제외) · 주차장 = 382건 | `coord2RegionCode` | 약 8초 1회, 캐시 |

사용자가 지오코딩을 제안했고(*"행정동은 카카오맵 지오코딩으로 알 수 있을 것 같은데"*)
맞는 말이었다. 다만 **큰 데이터에는 쓸 수 없다** — 기존 편의시설 지오코딩과 같은
속도(10건/200ms)로 계산하면 음식점 3,754건은 75초, 지역화폐 27,374건은 9분이다.

**그런데 큰 데이터는 주소가 깨끗해 지오코딩이 필요 없고, 지오코딩이 필요한 쪽은
건수가 적어 비용이 싸다.** 정확히 갈린다.

### 읍면동 → 구 매핑을 데이터에서 뽑았다

음식점 중 구와 읍면동이 **함께** 있는 1,439건에서 매핑 17종을 추출했다.
두 구에 걸치는 모호한 동은 **0종**이었다.

```
동탄구  경기동 · 동탄치동
병점구  병점동
효행구  기안동 매송면 봉담읍 비봉면 정남면
만세구  남양읍 마도면 서신면 송산면 양감면 우정읍 장안면 팔탄면 향남읍
```

## 4. ⚠ 축제는 통째로 제외했다

사용자 지시(*"축제는 일단 빼버려 아예 그냥"*). 근거가 있다 —
**장소 미정 축제 21건이 `(37.199, 126.831)` 한 점에 몰려 있다.**
그 좌표는 `js/map.js` 의 지도 초기 중심값, 즉 폴백이다.
어느 구로 넣어도 거짓이 되므로 지역 라벨·지역 검색에서 전부 뺐다.

## 5. 구현에서 걸린 것

### setFilter 가 지역 칩까지 껐다

```js
document.querySelectorAll('#map-chips .chip:not([data-cat="parking"])')
```

지역 칩은 `data-cat` 이 없으므로 `:not([data-cat="parking"])` 에 **걸린다**.
카테고리를 바꿀 때마다 보고 있던 동네가 풀렸다.
`:not([data-gu])` 를 더해 두 축을 갈랐다. 회귀 테스트로 확인했다.

### 검색 배지가 주소와 겹쳤다

`동탄구 · 동탄구 청계동` — 주소에 이미 구가 들어 있는데 배지를 또 붙였다.
`addr.indexOf(_g) < 0` 일 때만 붙이도록 고쳤다.

### 지오코딩 호출 시점

`coord2RegionCode` 는 SDK 가 뜬 뒤에만 쓸 수 있다. `autoload=false` 를 넣은 뒤라
더 그렇다. 지도 초기화 직후 1.2초 뒤로 걸었다 — 가장 이른 안전 지점이다.
실패해도 검색은 주소·bbox 폴백으로 그대로 동작한다.

## 7. 남은 것

- 지오코딩이 `region_3depth_name`(행정동)까지 캐시한다. `dongOf()` 로 꺼낼 수 있지만
  아직 화면에 쓰는 곳이 없다 — 나중에 읍면동 단위로 좁힐 때 쓸 자리다.
- 지역화폐·음식점은 주소 파싱으로 구를 알지만 검색 결과 배지에는 아직 안 붙였다.
