## PLACES 좌표 일괄 재지오코딩 프로토콜 (Session 3 후반)

### 문제 발견

지도 탭에서 관광지·축제 핀이 실제 위치와 다른 곳에 찍히는 문제 다수 발견.  
원인: `data.js`에 수동 입력된 lat/lng가 주소와 불일치하거나, gen_data.py의 VENUE_COORDS 딕셔너리가 부정확했음.

### 방법 — tools/regeocode.py

새 스크립트 `tools/regeocode.py`를 작성해 Kakao 로컬 REST API로 주소를 재지오코딩 후 `js/data.js`를 직접 교체.

**작동 방식:**

1. **파싱**: 정규식(`_PLACE_RE`)으로 data.js에서 `tourist` + `festival` 항목 블록 위치(start/end) 추출
2. **지오코딩**: 항목별 `address` 필드 → Kakao REST API (`/v2/local/search/address.json`) 호출
   - 실패 시 "경기도 화성시 " 접두어 추가 후 1회 재시도
   - API rate limit 방지: 호출 사이 0.11초 대기
3. **차이 판단**: 기존 lat/lng와 새 좌표의 합산 차이가 0.0001° 초과인 경우만 패치 대상으로 분류
4. **안전 교체**: 패치를 **뒤에서부터** 적용해 앞쪽 문자열 오프셋 밀림 방지
5. **옵션**: `--dry-run`(파일 수정 없이 출력만), `--category`(카테고리 선택), `--key`(REST API 키 직접 지정)

```
python tools/regeocode.py --key 1bd845da5756d1c78955463b800731ef
```

### 핵심 기술 사항

| 항목 | 내용 |
|------|------|
| API | Kakao REST API `/v2/local/search/address.json` |
| 인증 | REST API 키 (JS 앱 키와 별도 발급 필요) |
| 파싱 방식 | 정규식 직접 파싱 (JSON.parse 불가 — JS 문법) |
| 좌표 정밀도 | `round(..., 7)` — 소수점 7자리 (약 1.1cm 정밀도) |
| 실패 처리 | 원본 좌표 유지 (덮어쓰지 않음) |
