# 제부도 바닷길 — 자정 넘김 오판과 구간별 통행 표시

- 날짜: 2026-08-29
- 담당: 개발 Claude (hm8824@naver.com)
- 커밋: `c1ec97a`
- 발단: 사용자 지적 — *"제부도 바닷길 시간표에서 못 건널 때는 '지금 건널 수
  있어요'[라고 뜬다]"*, 이어서 *"여기부분 빨간색으로 표시하고 못건난다고해"*

---

## 0. 먼저 — 이건 사람이 갇힐 수 있는 종류의 오류다

제부도 바닷길은 하루 두 번 물에 잠긴다. 모르고 들어가면 못 나온다.
**틀리는 방향이 "못 건너는데 건널 수 있다고 말하는" 쪽**이었다.
이 앱의 오류 중 실제 위험으로 이어지는 몇 안 되는 자리다.

## 1. 데이터 한 줄이 이틀에 걸쳐 있다

```json
"2026-08-29": {
  "cross1": { "open": "07:04", "close": "16:09" },
  "cross2": { "open": "18:58", "close": "04:07" }
}
```

`cross2` 의 `04:07` 은 **8월 30일** 04:07 이다. 하루치 레코드 한 줄이
자정을 넘어 다음 날까지 이어진다.

## 2. 두 번의 수정, 두 번 다 반쪽이었다

### 1차 (2026-08-26 감사) — 자정 넘김을 아예 안 봤다

원래는 이랬다.

```js
return nowMin >= o && nowMin <= c;
```

`o=18:58(1138) > c=04:07(247)` 이면 이 식은 **영원히 거짓**이다.
통행 가능한 시간이 통째로 '잠김' 으로 뒤집혔다 — 365일 중 131일.

### 2차 (그 감사의 수정) — 오늘 새벽을 오늘 것으로 계산했다

```js
if (c < o) return nowMin >= o || nowMin <= c;
```

`|| nowMin <= c` 를 붙여 자정 넘김을 살렸다. 그런데 이 식은
**오늘 새벽도 오늘 구간의 꼬리로** 계산한다. 실제 그 시간의 주인은
'어제' 구간이고, **어제의 close 는 오늘과 다르다.**

| | 어제(08-29) cross2 | 오늘(08-30) cross2 | 08-30 04:20 |
|---|---|---|---|
| 실제 | 18:58 ~ **04:07** | 19:39 ~ 04:39 | 04:07 에 닫혔다 → **잠김** |
| 2차 수정 코드 | — | 오늘 close 04:39 로 판정 | **"건널 수 있어요"** |

32분 동안 거짓으로 통행 가능이라고 말했다.

### 전수 실측 (2026년 364일 × 1,440분)

| | 값 |
|---|---:|
| 어긋나는 날 | **133일** |
| 거짓 '건널 수 있어요' | **6,394분** (약 106시간) |
| 거짓 '잠김' | 5,324분 |

## 3. 고친 방식 — 하루를 두 조각으로 나눈다

한 함수가 '자정 넘김' 을 통째로 다루려니 오늘 몫과 어제 몫이 섞였다.
그래서 나눴다.

```js
_tideOpenNow(seg, m)   // 오늘 시작하는 부분만.  c < o 면  m >= o
_tideTailNow(seg, m)   // 어제 시작해 오늘 새벽까지 이어진 꼬리.  c < o 면  m <= c
```

지금 상태는 **오늘 두 구간 + 어제 두 구간의 꼬리**를 합쳐 본다.

```js
_tideStatusNow(sch, now, nowMin)
  → { open, todayHit: 'cross1'|'cross2'|null, tail: {k,s}|null }
```

`tail` 을 함께 돌려주는 이유는 화면 때문이다 — 새벽에 열려 있을 때
그게 **어느 창 덕인지** 보여 줘야 한다(§4).

### 수정 후 전수 재검

독립 진리표(각 구간을 절대 분 축에 펼쳐 겹침을 보는 방식)와 대조했다.

```
어긋나는 날      : 0 / 364일
거짓 '건널수있음' : 0분
거짓 '잠김'      : 0분
```

2026-08-29 하루 전이:

```
00:00 통행 가능   ← 어제(08-28) cross2 꼬리, 03:38 까지
03:39 잠김        ← 예전 코드는 04:08 이었다 (29분 거짓)
07:04 통행 가능
16:10 잠김
18:58 통행 가능
```

## 4. 화면 — 구간마다 지금 되는지 적는다 (사용자 지시)

예전에는 해당 구간에 **테두리만** 둘렀다. 위 배지가 '건널 수 있어요' 면
두 줄 다 건널 수 있는 것처럼 보였다 — 사용자가 지적한 그림이 이것이다.

이제 줄마다 색과 글자로 가른다.

| | 배경 | 글자 |
|---|---|---|
| 지금 해당 (`.hit`) | `#D1FAE5` 초록 | **지금 통행** |
| 아닌 구간 (`.miss`) | `#FEE2E2` 빨강 | **못 건넘** |

새벽에 어제 창이 이어지는 중이면 **`어제 2차` 줄을 맨 위에** 세운다.
그게 없으면 배지는 '건널 수 있어요' 인데 아래 두 줄이 모두 '못 건넘' 이라
무엇 덕에 열려 있는지 알 수 없다.

## 5. 실측 (390×844, `page.clock` 으로 시각 고정)

| 시각 | 배지 | 줄 |
|---|---|---|
| 08-29 12:00 | 건널 수 있어요 | 1차 **지금 통행** / 2차 못 건넘 |
| 08-29 17:00 | 물에 잠겨 있어요 | 1차 못 건넘 / 2차 못 건넘 |
| 08-29 21:14 | 건널 수 있어요 | 1차 못 건넘 / 2차 **지금 통행** |
| 08-30 02:00 | 건널 수 있어요 | **어제 2차 지금 통행** / 1차·2차 못 건넘 |
| 08-30 04:20 | **물에 잠겨 있어요** | 1차·2차 못 건넘 |

마지막 줄이 이 작업의 핵심이다 — 고치기 전에는 여기서
"지금 건널 수 있어요" 가 떴다.

## 6. 곁가지 — 시각을 잘못 읽고 헛다리를 짚었다

조사 도중 컨테이너 `date` 가 `12:12` 를 보여 줘서 그 시각 기준으로
"`hit` 가 1차가 아니라 2차에 붙었다, 뒤집혔다" 고 판단했다. **틀렸다.**
브라우저에 물어보니 `21:14` 였고, 21:14 면 2차가 맞다.

> **시각은 코드가 실제로 보는 곳에 물어야 한다.** 셸의 `date` 가 아니라
> 브라우저의 `new Date()` 다. 이 컨테이너는 둘이 9시간 어긋나 있었다.

진짜 원인은 그 뒤 하루 전체를 훑다가 나왔다.

## 7. 하지 말 것

- **`_tideOpenNow` 에 `|| nowMin <= c` 를 다시 붙이지 마라.** 자정 넘김이
  안 되는 것처럼 보여서 붙이고 싶어지는데, 그게 §2 의 2차 수정이고
  6,394분짜리 오류다. 새벽 몫은 `_tideTailNow` 가 맡는다.
- **`_tideStatusNow` 를 건너뛰고 `_tideOpenNow` 두 개만 부르지 마라.**
  어제 꼬리가 빠져 새벽이 통째로 '잠김' 이 된다.
- **구간 줄에서 `.miss` 를 빼지 마라.** 색이 없으면 사용자가 처음 지적한
  그 화면으로 돌아간다.
