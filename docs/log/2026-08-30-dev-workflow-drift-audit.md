## 2. 문제는 `WORKFLOW.md` 쪽이었다 — 구조적으로 그럴 수밖에 없다

`docs/log/` 는 **새 파일만 추가**하니 낡을 수가 없다. 반면 `WORKFLOW.md` 는
**제자리 수정**이라 고치는 사람이 없으면 그냥 틀린 채로 남는다.

가장 뚜렷한 증거는 **같은 문서 안의 모순**이었다.

```
§20  "인라인 JS 분리 → js/ 10개"      (2026-08-25)
§21  "CSS 분리 → css/ 6개"            (2026-08-25)
§17  "index.html — CSS·JS 전부 인라인, 별도 css/ 디렉토리 없음"   ← 그대로 남아 있었다
```

§17 은 **담당 파일표**다. 새 세션이 "내가 뭘 건드리는가" 를 여기서 읽는다.
그게 5일째 틀려 있었다.

## 5. 같은 왕복을 두 번 하게 만든 것 — 새 규칙으로 막았다

감사 결과를 보고할 때 **API 키 평문 노출을 '심각' 1순위로 올렸다. 그건 틀린 보고였다.**

```
08-24  감사가 "폐기·재발급 권고" 를 로그에 적었다
08-25  사용자가 "만료일 걸어 뒀다. 조치 불필요" 로 종결 — 그 결론도 로그에만 적혔다
08-30  내가 08-24 로그를 먼저 찾아 같은 건을 다시 올렸다 → 사용자가 두 번 답했다
```

원인은 내 검색이 부실했던 것이 절반, **구조가 절반**이다. `docs/log/` 는 시간순이고
읽는 사람은 검색에 걸린 것을 먼저 읽지 날짜순으로 읽지 않는다. **나중 결론이 앞 기록을
덮어 주지 않는다.**

그래서 §0 에 두 가지를 넣었다.

1. **끝난 판단(종결·기각·보류)은 `WORKFLOW.md` 로 올린다.** 로그는 "그때 무슨 일이
   있었나", `WORKFLOW.md` 는 "지금 무엇이 참인가" 다.
2. **이 파일은 아무도 안 고치면 조용히 썩는다.** 구조를 바꾸는 작업을 했으면
   그 커밋에서 해당 줄까지 고친다.

그리고 §12 Kakao API 절에 **결론 자체를 박아 뒀다** — 어디에 노출돼 있고, 판정이
무엇이고, 근거가 무엇이고, 뒤집을 조건이 무엇인지. 다음 감사는 로그를 뒤지기 전에
이걸 먼저 본다.

## 6. 안 한 것

- **로그 68개의 옛 줄번호 참조 8건을 안 고쳤다.** §0 이 로그를 역사 기록으로 정했고,
  당시엔 맞았던 값이다. 고치면 "그때 무엇을 봤는가" 가 사라진다.
- **절 번호를 다시 매기지 않았다.** 코드 10곳이 `WORKFLOW.md §3`·`§17`·`§18`·`§19-3`
  식으로 번호를 가리킨다(실제로 세어 확인했다). 순서만 바로잡았다 — `27-I → §28 → 27-H`
  로 뒤엉켜 있던 것을 `27-G → 27-H → 27-I → §28` 로.
- **`js/restaurants.js` 를 구현하지 않았다.** §13-R 의 사양은 살아 있고 데이터
  3,754건도 준비돼 있다. 문서상 유일하게 남은 개발 과제인데, 이번 작업은 감사라
  범위 밖이다. 지시가 오면 그때 한다.
- **배포 URL 을 못 고쳤다.** `culture-reed-dee-rug.trycloudflare.com` 이 응답
  없음(`000`)이라 `check.sh --live` 가 안 돈다. Quick Tunnel 은 재시작마다 호스트명이
  바뀌므로 **배포 Claude 만 새 주소를 안다.** §13 에 인계 항목으로 적었다 —
  README 배지·§1·`check.sh` `LIVE_URL` 세 곳을 함께 갱신해야 한다.
