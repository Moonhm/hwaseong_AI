## 1. 가장 위험했던 것 — §17 인계 표가 틀린 값에 「우선」 딱지를 달고 있었다

§17 「배포 Claude 인계 대기」 표의 머리글은 이렇게 되어 있었다.

> **§13 의 해당 항목보다 이 표가 우선합니다.**

그런데 그 표의 `id:102` 화성송산포도축제 행이 **나중에 오기로 밝혀진 값**이었다.

| 출처 | 주행사장 | 좌표 |
|---|---|---|
| §17 표 (2026-08-24 조사) | 화성에코팜테마파크 | `37.1201662 / 126.6935902` |
| `2026-08-26-deploy-master-data-summary.md:103` | **궁평항** (공식 페이지 재확인) | `37.1154134 / 126.6807231` |
| 현재 `js/data.js` | 궁평항 | `37.1154134 / 126.6807231` ← **맞는 값** |

`master-data-summary` 는 이렇게 적어 뒀다 —
*"이전 세션에서 '화성에코팜테마파크'로 **잘못 기입** → 공식 페이지 확인 → 궁평항으로 재수정"*.

**표는 고쳐지지 않았고 「우선」 딱지만 남았다.** 다음 세션이 §17 규칙을 곧이곧대로
지키면 맞는 좌표를 틀린 좌표로 되돌린다. 문서가 자기 규칙으로 사고를 유도하는 상태였다.

### 왜 이런 게 생기나

§17 표는 **한 시점의 조사 결과**인데 「우선」이라는 **영속적인 규칙**이 붙어 있었다.
조사는 뒤집힐 수 있지만 규칙은 안 뒤집힌다. 그래서 조사가 뒤집힌 뒤에도 규칙만 남았다.

머리글에 경고를 넣고, **값을 반영하기 전에 `js/data.js` 현재 값과 먼저 비교하라**는
절차를 못박았다. 표를 그대로 밀어 넣지 말라는 뜻이다.

### 같은 종류가 §13 에도 있었다

§13 은 「작은섬1·2 / 양지팬션·리조텔」을 **"데이터 보정 필요"** 로 적어 뒀는데,
§17 의 교차검증 결론은 정반대인 **"정상 — 수정 금지"** 였다. 좌표뿐 아니라 주소도
같은 부지가 맞고, 제부도 숙박 65건 전부가 도로명주소 중심점을 쓰는 일관된 규약이라
오프셋을 주면 근거 없는 좌표를 만드는 셈이다. §13 에서 미해결 목록 밖으로 빼고
**고치지 말라**고 명시했다.

## 2. `js/weather.js` — 인계받은 적 없는 인계건이 있었다

`2026-08-26-both-weekly-forecast-weather-js.md` 가 이렇게 넘겼다.

> :128 — *"`lo`/`hi` 를 `Math.round` 한 뒤 `span` 을 잡으면 된다. **고치지 않았다 — 인계한다.**"*
> :220 — *"`js/weather.js` 는 **배포 Claude 파일**이다. §17 대로 고치지 말고 넘긴다"*

**그런데 `WORKFLOW.md` 어디에도 이 건이 없었다.** §0 이 "로그는 새 파일만 추가하고
기존 파일은 고치지 않는다"고 정해 둔 이상, **로그에만 적힌 인계는 아무도 다시 읽지 않는다.**
넘긴 쪽은 넘겼다고 생각했고 받는 쪽은 받은 적이 없다. 8/26 이후 `js/weather.js` 커밋 0건.

### 버그

```js
var lo = Math.min(...);            // 반올림 전  21.1
var span = Math.max(1, hi - lo);
var tmin = Math.round(...);        // 반올림 후  21
var left = ((tmin - lo) / span) * 100;   // 21 - 21.1 → 음수
```

정규화 기준(`lo`/`hi`)은 원본 소수인데 표시값(`tmin`/`tmax`)은 `Math.round` 를 거친다.
반올림이 `lo` 아래나 `hi` 위로 넘어가는 날은 `left` 가 음수, `width` 가 100% 초과가 된다.

로그에 적힌 실응답으로 재현했다.

| | `lo` | `hi` | `span` | 범위 이탈 |
|---|---:|---:|---:|---:|
| 수정 전 | 21.1 | 29.9 | 8.8 | **2건** (`i=2` 끝 101.1% · `i=6` left −1.1% / width 102.3%) |
| 수정 후 | 21 | 30 | 9.0 | **0건** |

`lo`/`hi` 도 `Math.round` 를 거치게 했다. `Math.round` 는 단조라
`tmin >= lo` · `tmax <= hi` 가 보장되고, 따라서 `left >= 0` 이며 `left + width <= 100` 이다.

### 왜 아무도 못 봤나

`.wk-bar` 의 `overflow: hidden` 이 넘친 부분을 잘라 준다. **화면은 멀쩡해 보였다.**
막대 길이가 최대 5.7%p 어긋나 있었을 뿐이라 눈으로는 구분이 안 된다.

### 고치지 않은 것

`Math.max(6, wide)` 의 최소 너비 6% 는 그대로 뒀다. 그날의 최저기온이 주 전체 최고와
같은 극단적인 경우 `left + 6% > 100%` 가 될 수 있으나, 실제로 그런 주는 최저=최고인
날이 있어야 하고 `overflow: hidden` 이 처리한다. **인계받은 범위 밖이라 손대지 않았다.**
