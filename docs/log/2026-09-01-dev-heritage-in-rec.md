# 「사진 93장이 안 보인다」는 낡은 서술이었다 — 진짜 빠진 건 문화재 42건의 추천 후보 자격

## 1. 착수하자마자 전제가 무너졌다

`docs/PHOTO_NEEDS.md` 가 이렇게 적고 있었다.

> **축제·행사 50장** — `p.category === 'tourist'` 조건 탓에 목록에서 이모지로만 뜬다.
> 상세 화면도 CSS 그라데이션 배너다. **지도 슬라이드 카드에서만 보인다**
> **지정문화재 43장** — 위와 같은 조건에 걸린다
> 축제·문화재 93장은 **사진을 다 받아 놨는데 정상 동선에서 한 장도 안 보인다.**

**세 문장이 다 낡았다.** 고치려고 코드를 열었더니 이미 고쳐져 있었다.

| 화면 | 실제 |
|---|---|
| 추천 탭 목록 | `photoThumb(p, 56, …)` — **카테고리를 안 본다.** 2026-08-26 에 고쳐졌고 그때 남긴 주석까지 있다 |
| 축제 상세 | `hasPhoto(place)` 로 사진 히어로를 쓴다. 사진 비율에 맞춰 `contain` + 흐린 배경까지 붙어 있다 |
| 지도 슬라이드 | `placePhotoHtml` 의 비-tourist 분기도 `src` 를 쓴다 |

실측으로 확인했다 — `PHOTO_INDEX` 를 파싱해 `PLACES` 전건과 대조하고, `photoThumb()` 을
세 카테고리에 실제로 실행했다.

```
tourist  151 / 사진 151 / photoThumb → <img> ✅
festival  50 / 사진  50 / photoThumb → <img> ✅
heritage  42 / 사진  42 / photoThumb → <img> ✅
```

**하마터면 이미 끝난 일을 다시 할 뻔했다.** §0 이 경고하는 실패의 다른 얼굴이다 —
그쪽은 '끝난 판단이 로그에만 있어 다시 올라오는 것' 이고, 이쪽은 **'끝난 작업인데 그것을
적어 둔 문서를 아무도 안 고쳐서 다시 올라오는 것'** 이다. 문서를 고쳐 뒀다.

## 2. 그래서 진짜 빠진 것을 찾았다

「문화재를 노출한다」로 남아 있던 것은 사진이 아니라 **추천 후보 자격**이었다.

```
js/quiz.js   _computeRec()          PLACES.filter(p => p.category === 'tourist')
js/home.js   가장 가까운 관광지        PLACES.filter(p => p.category === 'tourist')
```

문화재 42건이 두 화면의 후보에서 **통째로 빠져 있었다.** '역사·문화 탐방' 을 고른
사용자에게 문화재가 한 건도 안 나오는 상태였다.

### 넣어도 되는지부터 쟀다

| | 값 | 판단 |
|---|---|---|
| 문화재 태그 보유 | **42/42** | `_getSpotTags` 가 `역사`·`문화`·`전통` 을 그대로 뽑는다 — 점수 계산에 바로 참여한다 |
| 문화재 좌표 | **폴백 0 · 중복 0** | 셋 중 가장 깨끗하다. 「길찾기」 버튼을 붙여도 안전하다 |
| 홈 「가장 가까운」 | 격자 1,300지점 중 **24.8%** 에서 문화재가 더 가까웠다 | 넷 중 하나꼴로 「가장 가까운」이 거짓이었다 |

### 축제는 뺐다

같은 논리로 축제도 넣을 뻔했는데 좌표를 재고 그만뒀다.

```
festival 50건 중  시청 폴백 좌표 21건 · 서로 겹치는 좌표 37건
```

두 화면 다 **「길찾기」 버튼이 붙어 있다.** 넣으면 시청으로 안내한다. 게다가 축제는 기간이
있어 끝난 것을 추천하면 안 된다. 축제는 소식 탭·캘린더·추천 목록·상세에서 이미 사진과
함께 잘 나오므로 노출이 부족하지도 않다.

## 3. 순위를 문화재 쪽으로 밀지는 않았다

후보에만 넣고 **점수 규칙은 그대로 뒀다.** 전체 응답 조합을 전수로 돌려 결과를 확인했다.

```
1,024가지 조합 중 문화재가 TOP3 에 드는 것 — 37가지 (3.6%)
나머지는 관광지가 태그를 한 개 더 맞혀 이긴다 (문화재 최고 11점 vs 12점)
```

**이 3.6% 가 정직한 값이다.** 억지로 올리는 안을 둘 시험했다가 **둘 다 버렸다.**

| 시험한 안 | 결과 |
|---|---|
| 동점 시 **평점**으로 가르기 | 문화재 평점 상한이 4.3, 관광지는 4.9 라 구조적으로 밀린다. 0/24 로 변화 없음 |
| 동점 시 **매칭 비율**(맞은 태그 / 전체 태그) | **추천 품질이 나빠졌다** — 태그가 적은 무명 장소(치동천체육공원·개나리공원)가 제부도·융릉과 건릉을 밀어냈다 |

지금 '역사 덕후' 응답에 나오는 답은 **융릉과 건릉·용주사·남양성모성지**다. 융릉과 건릉은
세계유산이고 용주사는 대찰이다. **좋은 추천을 억지로 밀어내면서까지 문화재를 올릴 이유가 없다.**
빠져 있던 것은 '자격' 이었지 '가산점' 이 아니었다.

## 4. 라벨

홈 카드가 `'🎡 가장 가까운 관광지'` 를 하드코딩하고 있었다. 문화재가 뽑혔을 때
**'관광지' 라고 부르면 거짓말**이라, 뽑힌 분류에 따라 갈리게 했다.

```
tourist  → 🎡 가장 가까운 관광지
heritage → 🏛️ 가장 가까운 문화재
```
