## 1. ① 여러 날 축제가 마지막 날 '종료'로 뒤집혔다 — 진행

`date` 에 시작일 하나만 있어 둘째 날부터 `festStatus` 가 `ended` 를 냈다.
**축제가 열리고 있는 당일에** '종료' 배지가 붙고 목록 맨 아래로 밀리며
달력에서도 그날이 빈 칸이었다.

`js/calendar.js` 는 `'A ~ B'` 범위를 이미 처리할 줄 안다. 그런데 축제 50건 중
`~` 가 든 것이 **0건**이라 그 분기가 통째로 죽어 있었다. 코드가 아니라 데이터 문제다.

### 근거는 같은 항목의 desc 안에 있었다

예: id102 `date:"2026-09-05"` 인데 `desc` 에 `"9. 5.(토) ~ 9. 6.(일)"`.

**요일까지 교차 검증했다 — 20/20 전부 일치**(시작·종료 각 10건).
시작일이 기존 `date` 와 어긋나는 것도 0건이었다. 외부 조회 없이 저장소 안에서
끝났다.

```
id98·99  09-12 → 09-12 ~ 09-13     id115  10-17 → 10-17 ~ 10-18
id100    09-11 → 09-11 ~ 09-13     id116  10-16 → 10-16 ~ 10-18
id102    09-05 → 09-05 ~ 09-06     id118  10-03 → 10-03 ~ 10-04
id114    10-24 → 10-24 ~ 10-25     id128  11-02 → 11-02 ~ 11-05
                                    id277  05-22 → 05-22 ~ 05-25
```

개발 Claude 조건 두 가지를 지켰다 — **10건만**(나머지 40건은 근거가 없다),
형식은 `"2026-09-05 ~ 2026-09-06"`(ASCII 물결, 양쪽 다 완전한 날짜.
끝값을 줄여 쓰면 오류 없이 하루짜리로 되돌아간다).

`sed` 일괄 치환을 쓰지 않았다. id 로 항목을 특정해 그 안의 `date` 하나만 바꾸고,
**치환 건수가 정확히 1이 아니면 중단**하도록 했다.

### 곧바로 회귀를 만들었다

날짜를 범위로 바꾸자 표시 코드 두 곳이 `"09.05 ~ 2026.09.06"` 을 만들었다.
문자열 통째로 `replace(/^\d{4}-/)` 를 걸어 **앞 연도만** 지워지고 뒤는 남는다.

개발 Claude 가 미리 지목했고 실제로 재현됐다. `'~'` 로 나눠 **조각마다** 연도를
떼도록 고쳤다(`js/calendar.js:179` · `js/home.js:692`).

`calendar.js` 끝에 있던 `.replace(' ~ ',' ~ ')` 도 지웠다 — 자기 자신으로
치환하는 코드라 아무것도 막지 못했고, 그래서 이 버그가 그대로 통과했다.

> 데이터 커밋과 코드 커밋을 분리했다(개발 Claude 조건).

## 2. ② 좌표 2건 — 보류였다가 진행으로 바뀌었다

처음에 개발 Claude 는 *"기준 좌표를 안 밝혔으니 하지 마세요"* 라고 했다.
**그 지적이 맞았다.** 나는 "15.2km 차이" 라고만 쓰고 무엇과 비교한 15.2km 인지
밝히지 않았다. 검증도 재현도 안 되는 보고였다.

그 뒤 검증자가 저장소 안에서 기준을 찾아내 진행으로 바뀌었다.

```
id118 정조효문화제   37.2285,126.8266 → 37.2062275,126.9965079  (id139 정조효공원)
id115 유소년 승마대회 37.183,126.882   → 37.1113606,126.8661029  (id213 발리오스 승마클럽)
```

둘 다 주소에 장소가 명시돼 있는데(id115 는 번지까지) 15.25km · 8.09km 떨어진
곳을 가리켰다. 정정값이 같은 파일 안에 있어 외부 조회가 필요 없었다.

### 내 성격 규정이 틀렸다

나는 `37.2285,126.8266` 을 '플레이스홀더' 라고 불렀다. **4건짜리였다.**

진짜 플레이스홀더는 `37.199,126.831` 이고 지도 중심 상수(`HWASEONG`)와
소수점까지 같으며 **21건이 공유**한다. 그중 **16건은 주소가 '미정'** 이다.
주소가 미정인데 좌표를 박으면 없는 사실을 만드는 것이므로 **손대면 안 된다.**

검증에서 그 21건이 그대로인지 확인했다(21건 유지, `37.2285` 쪽은 id118 만 빠져 3건).

## 3. ③ 주소 읍·면 표기 — 내 숫자가 재현되지 않았다

내 보고는 **"26곳 불일치, 12곳은 구까지 뒤바뀜"** 이었다.
개발 Claude 가 *"어떤 방법으로도 재현되지 않는다. bbox 로 셌다면 9할이
아티팩트"* 라고 했고, 다시 세어 보니 맞았다.

```
구 표기 불일치 40건
  ├ bbox 중첩 구간(아티팩트 의심)  25건
  └ 중첩 아님(실제 의심)          15건
bbox 가 2개 이상 구에 걸림: 57건 (23%)
```

`js/district.js:25` 에 이미 이렇게 적혀 있었다 —
*"bbox 로만 거르면 22% 가 두 구에 동시에 걸린다(만세구가 효행구를 감싸는 모양)."*
**경고가 코드에 적혀 있는데 그대로 밟았다.**

'실제 의심 15건' 도 9건이 봉담읍·비봉면·매송면이라 만세구/효행구 중첩 구간이다.
주소에 구 이름이 **명시된** 것만 추리면 4건(id38·220·241·245)이고,
개발 Claude 가 말한 "실제 3곳" 과 자릿수가 맞는다.

**여기서 멈췄다.** bbox 로는 판별이 안 되고, 어느 쪽이 맞는지 정하려면
외부 출처(행정구역 경계 또는 Kakao 지오코딩)가 필요하다.
②에서 "근거 없이 손대지 말라" 던 기준을 여기에도 적용하는 것이 맞다.

## 5. 오늘 두 번, 종료 코드를 보고도 푸시했다

`4a1ba00` 커밋에서 `check.sh` 가 **종료 코드 1** 을 냈는데 그대로 밀었다.
명령을 `&&` 로 묶어 놓아 결과가 눈앞에 찍혔는데도 이미 나간 뒤였다.
(확인해 보니 스테이징 타이밍 문제라 지금은 0 이다. 결과가 무해했을 뿐
절차는 틀렸다.)

같은 날 `?v=` 사고에서 얻은 교훈 — *"push 를 check.sh 와 같은 명령줄에 붙이지
않는다"* — 를 적어 놓고 지키지 않았다.

그 뒤 커밋부터는 이렇게 분리했다.

```
bash tools/check.sh >/dev/null 2>&1; RC=$?
test $RC -eq 0 && echo "커밋 진행" || echo "중단"
```
