## 4. 하단 내비 위 그늘

### 4-1. 원인 — bottom:0 + translate(…,100%) 은 그림자를 안 밀어낸다

그늘을 만든 패널 3개는 전부 같은 날 내가 넣은 것이다.

| 패널 | 들어온 커밋 |
|---|---|
| `#tide-panel` | `b248d63` 08-26 06:07 |
| `#today-panel` · `#settings-panel` | `b5f2fbe` 08-26 06:30 |

지적이 `e0ad1b0`(07:23)로 이어졌으니 버그는 한 시간 남짓 살아 있었다.
셋 다 `position:fixed; bottom:0; transform:translate(-50%,100%);
box-shadow:0 -6px 28px rgba(0,0,0,.18)` 였다.

`bottom:0` 인 상자를 자기 높이의 100% 만큼 내리면 **패널 윗변이 뷰포트 맨 아래에
정확히 걸친다.** 그런데 그림자는 offset 이 `-6px` 라 **위로** 뻗으므로 화면 안에 남는다.
그 자리에 하단 내비가 있다 — `css/00-base.css:107` 의 `.bottom-nav` 는
`bottom:0; z-index:300` 이고 높이는 `--nav-h: 52px` 다. 패널 `z-index` 는 그때 `310` 이라
**그림자가 내비 위에 칠해졌다.** 사용자가 본 어두운 띠가 이것이다.

⚠ 커밋 메시지는 번짐을 '위로 34px(6+28)' 이라고 적었는데 **그 값은 상한이다.**
blur 반경 28 을 전부 바깥으로 친 값인데, CSS 명세는 blur 를 경계에 걸쳐 절반씩
나눈다 — 바깥으로 나가는 것은 14px 이고 총 `6+14 ≈ 20px` 쪽이 맞다.
**렌더링으로 재지 못했으므로 단정하지는 않는다.** 이 컨테이너의
`chrome-headless-shell` 이 `libnspr4.so` 를 못 찾아 뜨지 않아 다시 잴 수가 없었다
(커밋 시점에는 떴다 — 그때는 캡처로 확인했다). 20 이든 34 든 52px 내비 안에 들어오므로
원인 판정은 바뀌지 않는다.

### 4-2. `.place-slide` 방식을 버린 이유

같은 문제를 이미 푼 코드가 있었다. `.place-slide` 는
`translateY(calc(100% + 200px))`(`css/20-map.css:271`) 로 **그림자까지 화면 밖으로
밀어낸다.** 그 손을 그대로 쓸 수 있었는데 안 썼다.

| | 여백을 더 밀기 (`+200px`) | `visibility` 로 끄기 (채택) |
|---|---|---|
| 그림자 크기를 바꾸면 | 200px 이 다시 모자랄 수 있다 — 두 값이 **조용히 묶인다** | 무관 |
| 닫힌 패널의 접근성 트리 | 남는다 (스크린리더·탭 이동에 잡힌다) | 빠진다 |
| 이동 거리 | 늘어나 같은 0.26s 라도 체감 속도가 달라진다 | `100%` 그대로 |
| 새 값 | 매직넘버 1개 추가 | 없음 |

그리고 **이 저장소는 이미 `visibility` 방식을 쓰고 있었다.** `#menu-drawer` 가
`visibility:hidden` + `transition: … , visibility 0s 0.35s`
(`css/30-panel.css:28~36`) 다. 같은 종류의 그림자 누출을 예전에 그렇게 풀었고
docs/log/2026-08-19-both-bug-history.md 의 '사이드 메뉴 shadow 노출' 줄에 남아 있다.
**새 패널 3개가 그 선례를 안 따른 것이 사고의 근본 원인이다** — 새로 발명한 게 아니라
있던 것을 못 찾아 쓴 것이다.

### 4-3. transition 두 줄이 짝이다

```
        transition: transform .26s cubic-bezier(...), visibility 0s linear 0.26s;
.open   transition: transform .26s cubic-bezier(...), visibility 0s;
```

닫힘 쪽 `0.26s` 지연은 **애니메이션이 끝난 뒤에 숨기라**는 뜻이다. 이게 없으면
내려가는 모습 없이 즉시 사라진다. 열림 쪽은 지연 0 이어야 올라오는 모습이 보인다.
한쪽만 두면 반쪽만 동작하므로 둘을 같이 봐야 한다.

  깔리던 문제).
