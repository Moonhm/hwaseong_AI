## 1. 무엇이 빠져 있었나

검색은 홈·지도 두 창이 `doHomeSearch(q, where)` 한 벌을 나눠 쓴다(`where` 는
어느 DOM 에 그릴지만 고른다). 그 한 벌이 **7종만** 훑고 있었다.

| | 그때 | 지금 |
|---|---|---|
| 관광·문화재·행사 | 243 | 243 |
| 공영주차장 | 131 | 131 |
| 지역화폐 가맹점 | 27,374 (이름·업종만) | 27,374 (**주소 포함**) |
| 편의정보 | 모범음식점 94 · 관광식당 35 · 영화관 13 = **142** | **295** (전 8종) |
| 시티투어 코스 | — | **10** |
| **앱 기능·화면** | — | **최대 31** |

빠져 있던 것: 관광호텔 10 · 캠핑장 17 · 템플스테이 1 · 관광편의시설 10 ·
제부도 숙박 115 · 시티투어 코스 10, 그리고 **기능 전부**.

사용자가 콕 집은 '제부도 물길'과 '오늘의 화성 날씨'는 **데이터가 아니라 화면**이다.
`jebu_tide_2026.json` 은 값이 전부 `"HH:MM"`/`"계속통행"` 이라 검색어로 칠 문자열이
없다. 그래서 데이터가 아니라 `openTide()` 라는 **행 하나**로 넣었다.

## 2. 세 가지 설계를 견주고 하나를 골랐다

조사 3갈래(데이터 / 기능·화면 / 성능) 뒤에 서로 다른 관점의 설계안 3개를 받아
심사했다. 심사 기준은 순서대로 — 사용자 요청 충족 → 27,374건이 다른 종류를
삼키지 않음 → 390px 에서 쓸 만함 → 220ms 디바운스 → 구현이 작음.

| 안 | 뼈대 | 판정 |
|---|---|---|
| 구역형 | 종류별 섹션 + 상한 | 예산·sticky·0건 폴백 설계가 가장 정교 → **가져옴** |
| 점수형 | 한 목록 + 점수 랭킹 | 27,374건을 막으려 **방지책을 다섯 겹** 쌓아야 했다. 섹션 하나로 대체된다 |
| 단계형 | 가벼운 것 먼저 | 지뢰(아래 §3)를 셋 중 유일하게 맞게 짚음 → **뼈대로 채택** |

**설계 단계에서 세 안이 서로 어긋난 곳은 저장소에서 직접 판정했다.** 그 과정에서
셋 다 틀린 것도 하나 나왔다 — `touristFacilities` 10건을 두고 셋 모두
"칩이 없어 목적지가 죽었다"고 했는데, `setFilter` 가 `if (chip)` 로 칩 부재를
넘어가고 `CONV_CATS`·`CONV_CAT_CFG` 에 이름이 살아 있어 **칩 없이도 동작한다.**
셋의 제안대로 칩을 되살렸다면 2026-08-26 사용자 지시를 되돌릴 뻔했다.

## 3. 밟았을 지뢰 셋

**`dlShowCourse(no)` 를 검색에서 부르면 안 된다.** 그 함수는 `showDatalab` 만
부르고 `go('tourism')` 이 없다. 홈에서 누르면 **보이지 않는 추천 탭에 코스 화면만
그려지고 화면은 그대로**다. `goDatalab('course:'+no)` 를 써야 한다.

**`switchTourismSub(null, tab)` 은 TypeError 로 죽는다** — 첫 인자 null 가드가
없다. 칩을 못 찾으면 그 행을 아예 안 만든다.

**테마 칩에는 `data-*` 가 없다.** `onclick` 에 값이 들어 있으므로
`.chip[onclick*="'sea'"]` 로 잡는다. 인덱스로 잡으면 칩 순서가 바뀌는 날
조용히 엉뚱한 테마로 간다.

## 4. 구조 — 섹션 7개, 예산 12행

```
① 바로가기(3)  ② 지역(2)  ③ 관광·문화재·행사(4)  ④ 공영주차장(3)
⑤ 먹고 자고 놀기(3)  ⑥ 시티투어 코스(2)  ⑦ 지역화폐 가맹점(3)
```

섹션 상한 합은 20 이고, **12행을 넘으면 ⑦→① 순으로 한 행씩 깎는다.**
비어 있지 않은 섹션은 최소 1행을 보장한다. 빈 섹션은 머리글째 안 그린다 —
`날씨` 는 머리글 1 + 행 1 로 끝난다(실측 186px).

**⑦ 가맹점은 항상 맨 끝**이다. 이유는 두 가지다. 27,374건이 구조적으로 다른
종류를 밀어낼 수 없고, 817KB 가 늦게 도착해 ⑦이 나중에 채워져도 **위쪽 행이
1px 도 안 밀린다** — 누르려던 항목이 손가락 밑에서 움직이면 안 된다.

머리글은 sticky 이고, 깎여 남은 것이 있으면 오른쪽에 `N건 모두 보기 ›` 가 붙는다.
그 목적지는 **전부 이미 있는 화면**이다. 새 화면은 하나도 만들지 않았다.

## 5. 검색 방식 — AND 토큰 + 점수

**모든 토큰이 맞아야 통과(AND).** 현행이 통짜 `includes` 라
`제부도 주차장`·`오늘 날씨`·`융건릉 주차` 가 **전부 0건**이던 원인이 이것이다.

| 등급 | 점수 |
|---|---:|
| 이름 완전일치 | 100 |
| 이름 앞일치 | 60 |
| 별칭·동의어 완전일치 | 55 |
| 이름 부분일치 | 40 |
| 공백 제거 부분일치 | 30 |
| 별칭·동의어 부분일치 | 25 |
| 보조필드(주소·태그·업종) | 15 |

이름이 한글·숫자로 시작하지 않으면 −5(`#헤어` 가 `미용실진` 을 앞서지 않게).

**별칭표** — 사람들이 부르는 이름과 데이터 이름이 다른 것만 넣었다.
`융건릉`→`화성 융릉과 건릉`, `공룡알`→`화성 고정리 공룡알 화석산지`,
`케이블카`→`서해랑 제부도해상케이블카` 등 5건.

**종류 동의어**는 검색에만 쓰고 화면에는 안 보인다(`주차`→주차장,
`맛집`→모범음식점 등). ⚠ **지역화폐에는 심지 않았다** — `가맹점` 을 심으면
27,374건이 전부 걸린다. 그 요구는 ①의 '지역화폐 가맹점 전체' 한 행이 맡는다.

## 6. 27,374건과 817KB

### 스캔 — 문자열을 이어 붙이지 않는다

처음엔 행마다 `n + ' ' + c + ' ' + a` 로 합쳐 `indexOf` 했다. **실측 `cgv` 36.2ms** —
설계가 예상한 6~8ms 의 5배였다. 원인은 27,374번의 문자열 할당이다.
필드를 따로따로 `indexOf` 하고 하나만 맞으면 통과시키도록 바꿨다.

| 질의 | 고치기 전 | 고친 뒤 |
|---|---:|---:|
| cgv | 36.2 ms | **11.9 ms** |
| 쿼티쿼티 | 26.5 ms | 10.7 ms |
| 스타벅스 | 20.2 ms | 12.7 ms |
| 동탄 | 3.3 ms | 1.6 ms |

**한글 질의에는 `toLowerCase()` 를 아예 안 돌린다.** 라틴 문자가 든 질의에만
소문자 사본을 1회 만들어 캐시한다(`_lcLowerIndex`).

### 로드 — 세 단계

1. **미로드** — ⑦ 섹션에 안내행 하나. `가맹점 27,374곳에서 '치킨' 찾기 · 눌러서
   불러오기 · 약 0.8MB`. 조용히 0건이 되는 것이 지금 가장 큰 거짓말이다.
2. **첫 검색 뒤** `requestIdleCallback` 으로 배경 프리페치 1회.
   ⚠ `focus` 에 걸지 않는다 — `날씨` 한 단어 치러 온 사람에게 817KB 를 물릴 수 없다.
   ⚠ `_loadLcData(cb, true)` 로 **silent** 호출. 안 그러면 타이핑 도중에
   '불러오는 중이에요' 토스트가 뜬다(`js/ui.js` 에 `silent` 인자를 새로 뒀다).
   ⚠ `navigator.connection.saveData` 면 하지 않는다.
3. **도착하면** ⑦만 채워진다.

> 사용자에게 "약 4MB" 라고 쓰지 않는다. 원본은 4,365,304 B 지만 실제 전송량은
> gzip **836,395 B = 817KB** 다.

## 9. 하지 말 것

- **`dlShowCourse(no)` 를 검색 결과에서 부르지 마라** (§3). `goDatalab('course:'+no)`.
- **`switchTourismSub(null, tab)` 을 부르지 마라.** 칩을 못 찾으면 행을 안 그린다.
- **테마 칩을 인덱스로 잡지 마라.** `onclick` 속성으로 잡는다.
- **`index.html` 의 `touristfacility` 칩을 되살리지 마라.** 2026-08-26 사용자
  지시로 뺀 것이고, `goMapConv('touristfacility', ...)` 는 칩 없이도 동작한다.
- **`window._srResults` 를 섹션별 중첩 배열로 바꾸지 마라.** `_srClick(idx)` 인라인
  onclick, 0건 시 `null` 대입, `resetHomePage` 의 GC 방지가 전부 평면 배열을 전제한다.
- **27,374건에 문자열 이어 붙이기·`toLowerCase`·`replace` 를 돌리지 마라** (§6).
- **`_loadLcData` 를 `silent` 없이 배경에서 부르지 마라.** 토스트가 뜬다.

- **`_UNI_ACTIONS`·별칭표를 `ui.js`·`boot.js` 로 빼지 마라.** `home.js` 는 로드
